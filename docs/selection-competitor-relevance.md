# 竞品类型与用途分类

用户要求每个主品比较 5–10 个相关竞品。真实 Amazon 搜索实测混入其他用途商品，原 ASIN 去重后取前十条不能证明相关性。本项接入新采集任务，保留全部原始事实，不修改跨机会归属或历史数据。

## 当前实现

- ProviderSourceExecutor 完成原始证据持久化后，仅对 amazon_product 且 projection_type=opportunity_competitors 的子任务执行分类。其他情报、详情、找货及手动采集目的不受影响。
- 同组织、工作区、任务和子查询读取实际规范化记录；从既有 SQL 解析当前主品，按采集时间取较新主品证据。主品 ASIN 必须与目标一致；独立候选去重、排除主品，分类最多二十个，最终投影最多十个。
- 模型只返回 source_ref、relation、rationale。关系为 substitute、different_use、accessory、uncertain；每个实际引用恰好一次，不接受新增引用、字段、价格或指标。主品/候选完整原始标题由代码绑定，模型不能生成或拼接“原文证据”。分类用于商品类型与用途判断，不是购买决策或事实生成。
- 模型调用在事务外。调用前后续租并检查取消；写审计前核对实际 running 状态、同租户、当前 lease token 和未过期租约，再读取当前证据并比较确定性指纹。证据变化、租约失效或审计失败回滚。
- 内部事件 opportunity.competitors_classified 保存原始输入、关系、任务/子查询、证据指纹及模型指纹。模型地址、名称和凭证不写事件、不下发浏览器。新事件合同同步到 OpenAPI 自定义 worker 事件区，无新增 HTTP 字段。
- 模型/分类审计失败按现有 validation_failed 进入采集任务最多四次尝试，原始证据保留；不累加 Amazon 来源故障或触发来源熔断。分类为空仍是实际空结果，不补商品凑数。
- 竞品投影仅接受同机会、任务和子查询的当前指纹分类，且关系为 substitute。缺失/失效分类不回退为前十条，数量不足仍明确 insufficient。原身份、5–10 数量、详情采集、评分和质量门继续保留。

## 配置和发布

复用 AI_BASE_URL、AI_MODEL、AI_API_KEY、AI_TIMEOUT_MS 和 COLLECTION_TASK_LEASE_SECONDS。分类超时为 AI 超时、采集租约一半及 60 秒三者的最小值，默认 30 秒；需调整时使用已有受限配置，租约不能小于实际请求耗时。没有新增环境键、依赖、数据库表或迁移，无需修改环境示例。

仅 Qwen3.5-* / Qwen/Qwen3.5-* 的本分类请求沿用已核实的官方非思考参数；其他模型不增加该扩展。情报关联、主品选择和既有货源分类合同不变。当前来源/任务/租约是原生产者，审计和竞品投影为本项消费者；API、前端、Python 和插件没有请求/字段变化，不增加 UI 流程。

本地构建、提交后由固定宝塔脚本发布；需重启唯一 Node 项目 ai选品，API/Worker 同包：`/www/server/panel/pyenv/bin/python /www/server/panel/script/restart_project.py nodejs ai选品`。无需 Python 重启。当前未部署、未启用生产来源。

## 验证与实际模型

初次真实模型请求返回 HTTP 200、8351ms，但拼接了不连续的“原文”并误将不同安装用途候选归类；严格校验拦截，未写数据库。由此改为三字段输出、代码绑定完整原始标题，并明确用途/安装场景差异。

最终使用上轮真实 Amazon 标题、现有受限模型服务和当前代码生成的请求，HTTP 200、6626ms，九个独立候选中选出五个同类手持风扇，排除台式风扇、塔扇、吹尘器和婴儿车风扇；输出通过引用和合同校验。仅为该组真实标题的模型诊断，没有使用生产任务或写入数据库，不能保证所有类别的分类质量或证明每天百品。

相关回归覆盖原始标题、未知引用、重复/遗漏、额外价格、事务外调用、running 租约、证据变化、回滚、指纹稳定、采集失败不触发来源熔断、缺失分类禁止回退，以及在二十候选中筛选后再限制十个。实际结果与构建记录见 selection-release-verification.md。
