# M01-02 MFA 与企业身份适配层 Runbook

## 配置与发布

在宝塔受限环境保留至少 32 字符的 `CREDENTIALS_MASTER_KEY`，并按 `config/env.example` 配置 `MFA_ISSUER`、时间步、位数、时钟窗口、挑战 TTL、尝试次数和恢复码数量。默认 30 秒/6 位/窗口 1 由 RFC 6238 兼容性确定；生产更改必须由安全负责人批准。所有配置在 API 启动时读取，修改后必须在宝塔重启 Node API；Worker/Crawler 不参与 M01-02，无需重启。

按 `0009a`、`0009b`、`0009c` 顺序执行 up 迁移。发布后运行 `npm run build`、三个 `tests/m01-02` 测试、`node scripts/verify-mfa-live.mjs`、M01-02 Playwright 和 `npm run verify:module -- M01-02`。真实 MySQL 探针要求 5.7、product_scout 业务账号与 utf8mb4，脚本只创建唯一测试账号并清理关联因子、挑战、恢复码、会话和审计。

## 观测与故障恢复

日志只记录事件类型、结果、request_id/trace_id 和剩余尝试，不记录邮箱、密码、TOTP、恢复码、种子、Cookie 或主密钥。关注：`mfa.challenge.failed/blocked` 激增、因子解密失败、时间漂移导致验证码连续失败、挑战锁定和主密钥缺失。服务器时间必须由宝塔可见的基础设施时间同步维护；不得通过扩大窗口掩盖漂移。

用户丢失认证器时使用尚未消费的恢复码；恢复码也丢失时，当前模块不提供弱化的自助绕过，必须等待后续安全管理员身份核验流程。挑战过期或锁定后重新输入邮箱与密码。因子密文无法解密时隔离记录，携带 trace_id 处理，禁止明文修改种子。OIDC/SAML/SCIM 在 Provider/租户映射获批前保持显式不可用。

## 回滚

先关闭 MFA 新绑定入口并在宝塔回退 Web/API 构建。已启用 MFA 的账号不能直接回退到忽略第二因子的旧登录逻辑；必须先由安全负责人完成受控迁移或停用，并保留审计。确认允许删除 MFA 数据后，按 `0009c`、`0009b`、`0009a` 逆序执行 down；这会删除挑战、恢复码与因子，属于破坏性操作，执行前必须导出加密备份和审计证据。若需要保留数据，只回退应用且不执行 down。最后只通过宝塔重启上一版 API，验证 health live/ready 和本地登录，不使用面板外服务顶替。
