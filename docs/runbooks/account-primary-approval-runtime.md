# 账号迁移：费用审批与原签署

账号模式下，`/cost-rules/{costRuleId}/actions` 只允许已验证且拥有该规则的主账号使用 `primary_account` 审批位。选品经理仍须拥有该规则的有效授权，不能由主账号的所有权代替；同一账号不能签两个位置。已签的原人员、决定、理由和回执保留。未部署前，不把此模式视作线上已生效。

普通 `/tasks/approvals` 工作流仍按原模板、目标和当前指定审批人运行，不把普通待审批节点批量转给主账号。读、写和幂等重放均重新检查封存归属；历史记录和原链接不合并。费用规则页面按实际返回的所有权与审批资格展示操作。

普通审批超时仍转给该节点原指定的升级审批人。后台同时核对待处理租约、请求、模板版本、节点定义和原任务或选品决定的归属；原生模板缺少归属封存时拒绝用旧坐标继续。升级动作、审计和通知投递在同一事务内写入，任何一步失败均不改变指定人或保留半条回执；任务仅保存可公开的故障码。此流程不改变 SLA，也不授予主账号普通审批权限。

本地构建授权、API 和前端，通过费用规则、利润查询、审批列表／详情／模板／决定及启动门禁测试。启动切换仍须通过正式协调发布，未修改正式库或重启服务，无新增设置。
