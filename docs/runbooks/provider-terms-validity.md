# 来源条款有效期

2026-10-15 所有者批准新增显式永久有效方式。

- `0074_provider_terms_permanent.up.sql` 兼容 MySQL 5.7，新增 `terms_permanent TINYINT(1) NOT NULL DEFAULT 0`；不改既有记录的批准状态或有效期，不自动批准任何来源。
- API `terms_permanent` 为布尔值，旧客户端省略时按 false。永久有效为 true 时 `terms_expires_at` 必须为 null；拒绝字符串、数字或双重有效期。非永久仍必须填写未来到期时间。
- 来源定义编辑页勾选“永久有效”会清空并禁用日期。保存、列表和重新打开均读取真实字段；取消永久后重新填写日期。平台 `provider:configure`、同源、幂等、版本锁、审计不变。
- 所有公开入口仍要求批准与非空版本，robots、限流、登录、五项质量门不变。内部批准并非第三方许可证明，不能绕过网站限制。
- 选择任务、来源回放/启停/配置回滚、竞品/供应搜索、自动调度、Worker 执行一致使用“永久或未来有效期”；缺失/无效日期不当成永久。
- 部署器在启动新代码前用业务账号执行迁移，并通过宝塔重启统一 Node 后端（API/Worker）；前端重新构建上传。Python 输入不增加字段，由 Node 在执行前执行门禁，Python 服务合同不变。
- 回滚应用不删除字段，旧代码会对没有日期的永久来源失败关闭；需要删除字段时先停止新代码，并将永久来源停用/重新审核，不能伪造远期时间。
- 本次没有新增环境变量、凭证或依赖，不需要改 `.env`。
