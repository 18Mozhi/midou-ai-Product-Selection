# M06-02 宝塔运维与回滚

1. 在宝塔备份数据库。固定目录部署脚本会在切换代码前校验并幂等执行 `0040_platform_messages.up.sql`；已执行环境只校验迁移文件校验值。迁移兼容 MySQL 5.7 与 utf8mb4，不创建常驻服务。
2. 在 Node API 受限环境设置 `PLATFORM_DASHBOARD_DEFAULT_WINDOW=24h`、`PLATFORM_DASHBOARD_QUEUE_WARNING=1000`、`PLATFORM_DASHBOARD_ERROR_LIMIT=20`，并令 `SCOUTOPS_ACCEPTANCE_API_REPORT_FILE=/www/wwwroot/ai选品/runtime/verification/production-api-coverage.json`。调整后必须由宝塔重启 Node API；不需要重启 Worker/Crawler。
3. 分别以平台超级管理员和平台运营管理员访问 `/platform-admin`，确认“平台事实”来自当前 MySQL：两者都能看到活动组织/用户聚合、启用来源、任务成功率和窗内文件增长；只有超级管理员能看到组织、用户明细入口和顶部“新建组织”。切换 15 分钟、24 小时、7 天和 30 天后，URL 必须写入对应 `window`，刷新后保持；快速双击刷新只能产生一次仪表盘请求和一次关联审计。停止测试数据库时，已有快照必须继续显示并提示刷新失败；恢复数据库并重新刷新后提示消失。超过 12 秒的请求必须进入有恢复动作的超时状态。确认折线图同时展示成功/失败总数和趋势；再检查内容、通知、系统状态、账号与组织、人员与权限等导航。系统状态页应按访问入口、共享依赖、异步执行展示六类既有运行观测；制造一个测试环境的 warning 或 stale 观测后，“当前需核查的传播范围”必须只列异常节点，保留对应专属运维入口，并以“如异常持续”表达待核查范围，不能把关联服务直接判为已故障。邮件 Provider 为 `pending_provider_selection` 时不得出现“邮箱管理”菜单，直接访问 `/platform-admin/email` 应显示页面不存在，通知偏好和平台通知草稿的邮件选项应禁用；直接 API 提交 `email_enabled=true` 或邮件草稿必须返回 `mail_provider_pending`。历史邮件事实仍保留，不执行删除。所有允许的修改必须填写原因，并用关联编号在 `platform_audit_events` 定位记录。
   在系统状态页已有成功快照后再次点击刷新，六类拓扑必须继续显示，刷新按钮变为“刷新中…”并禁用。将测试 MySQL 停止后，GET 应返回 503，但页面必须保留上一份快照并显示恢复提示；恢复 MySQL 并刷新后提示消失。用测试网络延迟令读取超过 15 秒时，请求必须被中止并提示已保留成功数据。实际删除隔离库中的全部测试任务和来源时，页面应分别显示“当前没有采集任务状态记录”和“当前没有来源配置记录”，且下钻入口继续可用。以上故障注入只允许在本地或测试环境执行。
   进入通知中心后模拟一次 EventSource 断开并恢复，再进入系统状态页；“实时连接退化”应在当前浏览器标签页会话中显示非零重连率与一次降级轮询。刷新新标签页时从零开始；该值不得当作全站指标，也不应出现在平台管理 API 或数据库中。
4. 告警异常时先进入 `/platform-admin/logs`，使用 request_id、trace_id、任务 ID、事件名或错误码跨 API、Worker、爬虫检索归一化链路；确认同一 trace_id 的事件按时间正序收在一个调用链分组中。异常 Worker 任务应能进入对应采集任务；异常 Crawler 运行在存在持久化关联时应同时进入任务和过滤后的来源页，没有精确关联时不得显示伪造入口。需留存当前筛选时点击“导出当前筛选”，填写原因；CSV 与页面使用相同查询、运行面和 200 条上限，平台审计应出现 `platform.logs.export` 及真实记录数。需要进程原始日志时再到宝塔核对 Node API、Worker/Crawler 日志及既有采集控制台。链路日志页和驾驶舱都不会重放任务或修改队列。
5. 进入 `/platform-admin/api-coverage`，未运行生产验收时应显示“当前目录待验收”、222 个路径、255 个操作和 0% 实时覆盖率。由宝塔手工运行 `product-scout-production-acceptance` 后刷新；只有报告指纹匹配时才显示“当前目录已验收”，并按六角色、成功/空结果/受阻/越权、数据来源、UI 消费方和爬虫副作用展示统计。OpenAPI 或元数据更新后无需重启即可读取部署包新文件，但部署新后端包本身仍需按固定流程由宝塔重启 Node 项目 `ai选品`；不得手工复制旧报告覆盖新目录。

390px 验证时，来源健康、全量数据、规则治理、热点内容、通知投递、历史邮件记录和每条调用链事件应显示摘要卡片且没有横向宽表；点“查看详情”后可查看完整事实并执行原有审核、投递处置或异常任务/来源下钻动作。移动筛选应从抽屉打开，关闭后重开仍保留已选条件，状态选项显示中文。来源 UUID 和代码、业务记录 ID、版本代码、原始投递状态与错误码只在“技术详情”出现；告警主列表不应直接暴露组织/工作区 UUID，请求标识也只在页尾“技术详情”中展示。

通知运营验收时准备超过 100 条本地通知与平台消息，核对摘要必须使用完整筛选结果，投递列表每页 20 条、草稿与发布记录每页 10 条；两个页码、查询和通知类型刷新后保持，越界页码由 API 收束到末页。桌面和 390px 都只应出现一个“发布通知”入口，长正文不得撑宽或形成无限长单卡。快速双击刷新只产生一个逻辑读取；已有结果遇到数据库 503 或 15 秒超时时继续显示并提供重试。创建并发布全体用户站内通知后，核对接收人数、`notifications`、`notification_deliveries`、`realtime_events`、`platform_management_operations` 与 `platform_audit_events`；邮件开关和邮件草稿 API仍必须失败关闭。手工发布不经 Worker/Crawler，不得据此伪造异步任务证据。

数据中心验收时分别切换热点、机会、竞品和供应商，核对状态选项必须对应真实状态：热点含展示中/无关/已过期/已归档，机会含待决策/已采纳/观察中/已拒绝，竞品含监控中/已暂停，供应商含信息不完整/可评估/已隔离。每页 20 条，最多覆盖当前筛选最近 100 条；筛选后翻到第 2 页再刷新，URL 和结果范围必须保持。输入但未提交的筛选草稿不得改变受控导出范围。验证 `?evidence_id=<uuid>` 和 `?issue_id=<uuid>` 时应直接进入证据与质量视图并定位详情或问题。已有结果刷新失败或超过 15 秒时必须保留旧事实。CSV 仍需同源、2–300 字原因、UTF-8 BOM、公式注入保护和 `platform.data.export` 审计；不要把同步最近 100 条导出描述为全历史异步导出。

治理中心验收时分别切换评分规则、费用与风险、审批工作流、自动化规则、灰度与回滚，核对摘要必须是五张业务表及来源版本表的真实全量计数，列表每页 20 条。各分类状态必须使用真实集合，跨分类状态组合应返回 `platform_governance_status_invalid`；缺少分类或无效页码应返回对应 400。筛选后翻页、刷新和浏览器返回时，`section`、`q`、`status`、`page` 与实际列表一致。停止测试 MySQL 后刷新，已加载事实必须保留并显示 503 恢复提示；恢复数据库再刷新应消除提示。页面不直接执行治理写操作，所有工作台链接仍进入评分、费用、组织审批、自动化或发布控制原模块。

本次依赖拓扑及状态刷新控制只改变 Web 对既有状态响应的展示和读取生命周期，不新增路由、字段、配置、迁移或运行进程；单独发布该页面只需替换 Web 静态文件，不需要重启 Node API、Worker 或 Crawler。若与本模块后端路由改动一起发布，仍须通过宝塔重启 Node API。

回滚：先由宝塔回退网站与后端到上一提交。仅在确认不再需要通知/邮件草稿及发布记录后，才人工执行 `0040_platform_messages.down.sql`；该操作会删除平台消息记录，必须先备份。历史投递与审计事实不随表回滚删除。
