# M06-03 宝塔运维与回滚

1. 备份后执行 `0021_collection_console_m06_03.up.sql`，由宝塔发布并重启 Node API；Web 同步发布。
2. 设置 `COLLECTION_CONSOLE_RECENT_LIMIT=50`（10–200），该值是“最近尝试”和“死信”各自的服务端分页大小；调整后只需重启宝塔 Node API，不需要重启 Worker/Crawler。
3. 访问 `/platform-admin/collection/overview`，用来源、组织、工作区和最近 24 小时/7 天/30 天/全部时间验证范围；从中文用途链接进入来源配置、健康、任务、浏览器运行和数据质量页面。
4. 在“错误根因”核对各根因数量等于当前范围内 `collection_dead_letters` 的失败任务数；选择真实错误码，确认最近尝试与死信同步下钻。再次点击或使用“清除根因筛选”恢复全部错误。仍在重试但未进入死信的尝试不得计入根因总数；根因名称来自固定中文显示，原始码只在技术详情中展示。
   - 切到“全部时间”，分别翻阅最近尝试与死信分页，核对页面显示的总数与同一筛选 SQL 的 `COUNT(*)` 一致；刷新页面后筛选、根因和两个页码应从 URL 恢复。切换范围或根因后两组页码必须回到第一页。
   - 连续点击“应用范围”只能产生一个读取请求。让接口超过 15 秒或返回失败时，页面必须保留上一份已验证数据、显示重试提示并继续展示旧观测时间，不能清空控制台。
   - “告警类别”必须明确区分网络、登录、验证码和解析；类别只用于阅读。点击根因后仍应以技术详情中的单个真实错误码下钻，不得按类别合并重放或改变重试规则。
   - 在 390px 视口确认来源与最近尝试显示为摘要卡片而非窄列表格；点“查看详情”后才能看到来源代码、任务 UUID、trace_id 和组织/工作区 UUID，关闭、遮罩和 Esc 均能退出抽屉并返回原触发卡片。
   - 准备超过 8 个来源并让末尾来源进入受阻或连续失败；桌面和 390px 默认都应将异常来源排进前 8 个，只渲染 8 条来源记录并显示完整来源总数。点击“查看全部”后所有来源可见，再收起恢复 8 条；来源筛选选项仍保持完整。
   - 分别检查0、1、8、9个来源：只有0个时显示“当前范围没有来源健康记录”；1–8个时不能同时显示空提示；9个时显示8项、可展开全部并收起。来源健康是平台来源当前元数据，仅来源ID影响来源列表，不应解释成组织/工作区/时间窗口内的健康统计。UI2-CL52以隔离响应覆盖桌面/移动边界，不证明真实采集健康。
5. 使用 request_id/trace_id 关联 `collection_console_views`、`platform_audit_events`、任务尝试和宝塔日志。控制台不创建第二套重放接口，批量入口只组合 M03-05 单任务重放。
   - 生产验收运行 `python scripts/verify-live-baota.py collection-console`；探针使用固定宝塔项目与受限配置，先只读检查迁移表，再创建随机隔离样例并清理，不连接本机 MySQL。
6. 展开“批量安全重放”，只勾选当前死信页中的开放死信并填写原因；每批最多 20 条，第 21 个勾选框必须保持未选。预览必须列出死信数、根因、组织数和工作区数，确认时勾选影响范围并输入“确认重放”。快速重复点击确认只能触发一个批次执行循环。执行后核对每条来源任务分别新增一个重放任务、独立幂等记录、事件和审计；失败条目逐条显示原因并保留以便修复后重新选择，成功条目不得重复克隆。

UI第二阶段的来源空态修复仅更新Web条件渲染，未改后端、配置、排序、分页或批量重放；不需要新增环境项/迁移，也不要求单独重启Worker/Python。由既有宝塔发布链上线，整体部署的停启和既有迁移预检仍需执行。

回滚：模块级数据库回退才在备份与授权后先回退 Web/API，再执行 `0021_collection_console_m06_03.down.sql`；单纯回退上述Web空态改动不执行数据库down迁移。已有来源、任务、尝试、死信、质量事实与平台审计不删除。

## 取消指定快照的未开跑采集积压

### 维护暂停领取

- 部署包含维护开关的运行包后，SSH 进入固定生产 `/www/wwwroot/ai选品/backend`，使用既有 Node 和受限配置运行 `node --env-file=/www/wwwroot/ai选品/config/product_scout.env scripts/collection-claim-maintenance.mjs status`。默认未暂停，不新增环境变量。
- 用本次维护 UUID 执行同一命令的 `pause UUID`，核对返回 `paused:true`；同一 UUID 可重试。标记固定在 `/www/wwwroot/ai选品/runtime/verification/collection-claims.pause`，不直接手建、删除或替换。领取事务和开关共享 MySQL 会话互斥锁；暂停确认返回后，已提交的领取仍算在途，不会被中止。
- Node Worker 暂停新采集领取轮询；独立浏览器领取暂停。Python 仍可领取有同组织、工作区、有效 Worker 父租约的浏览器子作业；已领取作业的执行、心跳、回写和释放不经过开关。Amazon 浏览器健康检查若因维护不能领取，返回 409，不覆盖来源健康记录。暂停不更新任务行、不中断进程、不修改来源熔断。
- 确认在途采集、调度租约、档案租约、已领浏览器作业和人工接管均排空，再进入正式发布或取消流程；只用原清单和 SHA。标记不随固定目录切换丢失。确认取消审计后用同一 UUID 执行 `resume UUID`，再用 `status` 核对 `paused:false` 并观察后续正常领取；切换开关本身不重启。
- 首次上线开关仍需正式发布并由宝塔加载 Node API/Worker；Python 代码及接口字段不变。**未安装开关的旧运行包不会识别该标记**，不得先写标记并据此宣称旧 Worker 已排空。首次发布前仍须取得安全空窗。回退到不识别开关的版本会恢复领取，不得在要求保持暂停时无提示回退。

- 先在固定生产根目录的 `runtime/verification` 内保存权限为 `0600` 的冻结清单 `collection-backlog-<batch_uuid>.json`，内容包括 `schema: 1`、`batch_id`、UTC `captured_at`，及 `rows` 中的任务 `id`、`organization_id`、`workspace_id`、`version`、`status`。冻结时仅选经批准的活动范围及未开跑任务；清单不导出生产，记录 SHA-256 后不再更新。一次最多 2,000 条。
- 通过正式发布链先上 `0076_collection_backlog_cancellation.up.sql` 和同版本 Node/Web。迁移只追加 `cancelled`，MySQL 5.7 不支持在线变更时失败关闭，不回退到表复制。发布前检查真实在途租约和浏览器接管会话为空；不能为了取消待办而中断在途。工具执行本身不需要重启，也不自动执行取消。
- SSH 进入固定 `backend` 目录，沿用运行时 Node 和受限环境，先执行 `node --env-file=/www/wwwroot/ai选品/config/product_scout.env scripts/cancel-collection-backlog.mjs SNAPSHOT SHA256`。无 `--apply` 只读。批准范围与预览一致后，使用**同一**文件、哈希追加 `--apply`。
- 只遍历清单内 ID，按行锁实时检查状态、版本、作用域、尝试、租约、浏览器任务、子查询和采集证据。清单生成后的新任务不进入；已启动或已产出则跳过。每 50 条一个事务，任务终态与 `collection.task.cancelled` 审计同事务，包含原状态、批次和快照哈希；不删除任务、历史或证据。中途失败只用原批次重跑，已提交记录不会重复取消。验收看 `cancelled` 的去重审计回执数和 `eligible_remaining=0`，另报受保护数；不是把全局队列长期保持为零。
- 回滚运行包仅允许保留 0075/0076 兼容边界，不回退 0076 数据库枚举、不改写已取消记录、不自动重排。若操作中止，先停止执行并核对同批次回执，不清审计或做逆向批量 UPDATE。
