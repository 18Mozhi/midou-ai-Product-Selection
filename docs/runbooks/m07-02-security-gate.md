# M07-02 安全门禁 Runbook

## 执行

在本地、CI 或宝塔面板创建的受限发布任务中运行 `npm run verify:module -- M07-02`。网络需允许 npm 依赖公告查询；MySQL 5.7 与 Redis 使用 P00 已验证的受限连接。通过时保存模块报告的 `run_id` / `trace_id`，失败时按报告中的 check、file 和 code 修复后完整重跑，不可手工放行。

宝塔网站发布前，把 `infra/baota/nginx/scoutops.conf.template` 合并到站点配置并执行面板内的 Nginx 配置检查和重载。CSP 如需新增外部来源，必须先证明页面实际需要并同步策略测试；不要通过通配符放宽。

## 故障与恢复

- npm 审计超时或输出无法解析：保持发布阻断，恢复网络后重跑，不把扫描器异常当作零漏洞。
- 高危/严重漏洞：保持阻断；确认锁文件和实际依赖路径，再按依赖变更规则审批升级。
- 秘密命中：立即阻断；只显示文件与规则代码。若是真实凭证，先轮换，再移除历史暴露。
- `browser-sensitive-storage`：只允许主题模块的枚举主题 ID、选品旅程模块中经过 UUID v4 校验的未完成旅程 ID，以及实时指标模块中不含身份与业务内容的当前标签页连接计数；任何 Token、Cookie、用户资料、请求标识、通知正文或凭证仍保持阻断。允许文件、键、调用数量或写入表达式变化后必须先更新合同测试并重审。
- 权限、SSRF、CSRF、SQL 或日志测试失败：停止发布并按对应既有模块 Runbook 排查，不通过前不得跳过。
- Nginx 配置检查失败：不重载，保留当前有效配置，修正模板后复测。

## 回滚

安全扫描器与策略回滚只需恢复上一签发构建；没有数据库 down、队列清理或数据删除。若新响应头造成已验证页面不可用，在宝塔恢复上一份站点配置并重载，然后保留失败证据、修正最小 CSP 来源后重新走 M07-02。不得用移除全部安全头作为长期回滚。HSTS 当前未启用，因此不产生浏览器长期缓存回滚风险。
