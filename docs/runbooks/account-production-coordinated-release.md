# 账号切换：正式协调发布入口

正式协调器独立校验当前运行的 0076 采集积压处理基线及完整构建 SHA；旧增量发布工具的 0075 常量不作为迁移授权。两者任一不符均在上传和停写前拒绝。

正式入口：`python -B scripts/deploy-account-baota.py --execute --expected-previous-sha <当前正式构建SHA> --plan-sha256 <账号迁移清单SHA256>`。只接受干净的、与批准 `origin/main` 一致的本地提交和确切在运行的基线，不要用旧发布命令绕过。

入口从本地构建，严格校验 SSH 主机，独占上传并复核候选，准备依赖与路由，停止宝塔写入端，在同一 MySQL 会话审核及迁移。安装过程中数据库锁仍持有；正向验真后，替换固定运行目录、刷新 Nginx、启动宝塔新版。新版 Node 还必须返回账号模式标记并证明两个旧组织入口没有注册，才启动 Python 及记录 `runtime_ready`。最后校验公开版本、健康和路由。业务记录、审批及证据保全由迁移执行器检查。没有备份副本、隔离环境或新增常驻进程。

停服前使用正式基线已有的领取暂停工具，以本次唯一标记暂停新领取。必须观测同一个存活 Worker 连续四次无活跃队列或有效租约；宝塔停止 Python 后、停止 Node 前再次核验。计数不全、心跳过期、进程更换或暂停归属变化均不进入迁移。旧写入端确认停止后，在替换旧工具前仅撤销本次暂停；迁移前失败可在证明原版和旧结构未变后恢复原运行状态，不接管其他操作者的暂停。沿用原发布排空采样次数和间隔，不运行或依赖备份。

新版启动后，只有同一正式 Worker 进程使用本次构建和账号模式、且其两次有效队列快照时间确实前进，才记作 `runtime_ready`。等待有界，不创建任务做探针，不需要调整配置或额外重启。Worker 证明失败时保留当前发布阶段供核对，不自动重跑迁移或启动旧版；快照通过也不等于真实采集结果已经完成。

发布阶段写入受限 `config/account-release-state.json`，不得删除阶段记录来强行重跑。在发出正向请求之前，只有确认原版 SHA、旧表和审批类型仍 intact、且正向回执为 0，才恢复原来正在运行的组件。进入 `applying_database` 后失败，不自行启动旧版，不自动重跑任何迁移，先核对实际数据库和日志。

账号发布的 Nginx SPA 路由从同一功能路由表排除旧组织、工作区与资源授权页。直接访问旧收藏地址应返回 404；已打开的 SPA 在收到账号模式回执后同样退役这些路由。选品、个人中心和平台账号入口保留。无新增配置；由协调发布刷新 Nginx 并安装新版前端，不手动编辑正式配置。

本地验证：`python -B tests/unit/test_baota_account_release_coordinator.py`。正式入口已实跑到源码门禁；当前工作树混有未提交改动，命令以 `account_release_source_must_be_clean` 退出，未连接 SSH、上传、停机或迁移。

采集运行预检：`python -B scripts/deploy-account-baota.py --inspect-crawler` 只能走固定正式节点和业务账号的只读连接。若有孤立 `running` 记录或独立活跃租约，正式入口在上传及停机前拒绝发布；停写会话也在前置 DDL 与归属回填前重查，避免不可逆迁移后 API/Worker 才因同一状态拒绝启动。此前只读实测 4 条旧 `running`、0 条独立活跃租约。用户明确授权删除后，在一个事务内重查完成回执、外键和结构化引用，删除这 4 条记录及专属的 22 条租约获取／心跳记录（无其他记录依赖）；未删除采集任务、结果或业务审计，未补造终态。正式回读孤立运行和独立活跃租约均为 0。此次清理未部署账号迁移。

## 2026-11-25 已批准的维护暂停首次加载

用户已确认当前维护窗口，只重启 `ai选品` Node；Python、1688、并发与数据库不变。
既有领取暂停只拦采集，不能让旧Worker的其他队列排空，因此新增精确首次加载入口，不降低常规四次全零标准。

`python -B scripts/deploy-account-baota.py --collection-maintenance-bootstrap --expected-previous-sha 1b622274a6871d9d1ac3986223359b539a82aa76 --expected-module-sha256 189741ab72172b40773d501bfa24c13be157fc751b2f127ca9de007980b8562d`

入口仅在严格匹配当前旧模块、干净已验证且origin/main同提交的代码上执行：

1. 通过已有工具创建本次独占领取暂停，核对相同存活Worker和新鲜心跳，连续四次确认所有业务任务/租约为零。
   首次加载前允许旧Worker仍运行未领取业务的轮询；这是用户专门批准的首次加载边界，不适用于后续正常发布。
2. 只原子替换Worker入口与queue-scheduler两个模块，经宝塔重启Node加载维护暂停；仍持有原暂停。
3. 新Worker每tick在派发前检查原暂停文件；不终止已有运行，不更改轮询间隔/并发/优先级/错峰，继续发布真实心跳与活跃数。
   文件不可读或类型异常均暂停，不假报任务完成；只有文件不存在才允许新派发。
4. 连续四次验证包含全部Worker活跃数、趋势活跃数和业务租约的完整全零，最终再次复核，才继续安装Amazon健康/采集引擎两个固定模块。
   只再次重启Node，保持暂停，再验证四次完整全零和最终快照后，才撤销本次自己的暂停。
5. 发布失败若已可能加载新版，保留拥有者标记及采样回执供续接，不强行解锁、重放租约或重启Python。

协调器一次远端操作上限900秒（覆盖两次有界Node重启及排空），不改变业务任务超时、重试或并发。
不新增环境变量、依赖、接口字段或数据库结构；原暂停路径不变。API/OpenAPI和Python任务输入无变化。
正常运行无暂停文件时行为不变；维护后去除本次标记即可恢复原调度，无需额外调参或重启。
