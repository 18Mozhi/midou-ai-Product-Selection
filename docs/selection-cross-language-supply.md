# 中英文货源标题分类与原始报价

本项处理通用品英文 Amazon 标题与中文 1688 标题无法依靠共有英文词匹配的问题，同时修复普通 makeup case、pencil case、storage case 被旧 `case` 关键词错误归入手机壳费用范围的问题。仍未部署，真实同款、一般品类费用和每日整链百品验收尚未通过。

## 处理链

自动评估保留既有独立报价样本、标题词法匹配和 p75 路径。通用品不能通过原匹配时，在 SQL 事务之外读取同组织、工作区、机会的主品原始标题和最新 1688 报价标题。按最新货源去重和报价资格过滤后，最多60个候选，每批最多10个，找到通过代码检查的报价后停止；后续批次前校验并续租，见 `selection-supply-batching.md`。手机壳不走此备用路径。

模型仅返回商品类型与明确属性的分类，不接收报价，不返回价格、销量、利润或相似度百分比。`compatible` 至少包含商品类型和另外两个不同属性种类；每种依据必须逐字存在于双方标题，不得重复或包含另一属性引用。这个校验只能约束分类依据，不能保证模型翻译正确或证明精确同款。

代码再次验证主品证据 ID 和标题、货源链接和证据 ID、最新原文、正数人民币报价与非新人价；双方标题规格数字集合必须一致，不做单位、型号、包装数量换算。按输入来源顺序选取首个满足条件的真实报价，模型返回顺序不参与选价，也不自动选择最低价。该分支是一条具体货源报价，样本数为一，相似度未知，不冒称三个独立样本的 p75。

原词法与分类两个通用品路径共用明示材质、规格数字冲突校验。材质对照覆盖尼龙、硅胶、皮革、聚酯、棉、不锈钢、塑料、玻璃、木及铝的有限中英文词表；识别到的材质集合必须一致，一方缺失不自动补造。词表以外的材质与单位语义没有被此硬校验证明，仍不能宣称精确同款。

写入使用原 `opportunity_cost_inputs`，来源引用为 `1688:<offerId>:classified-title:v1`，金额逐项取当前原始报价。与价格同事务写 `opportunity.supply_title_classified` 事件，保留主品和候选原文、分类依据、原始证据引用、匹配方式及空相似度。人工复核输入不覆盖；证据变化不套用旧分类；审计失败整体回滚。模型阶段不持数据库事务，写入前按机会行、任务租约顺序加锁并检查未过期的当前租约。

分类价格不是精确 SKU 确认、真实到岸成本或采购决策。手机壳既有严格型号规则继续生效；手机壳费用不外推到通用品，未知物流、佣金、汇率和利润仍未知。不会因此直接推荐、自动采纳、下采购单或计作整链完成。

## 配置与运行

复用现有 `AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY`、`AI_TIMEOUT_MS` 与 `AUTOMATIC_SELECTION_EVALUATION_LEASE_SECONDS`。本分支请求超时取现有 AI 超时和评估租约一半中的较小值；默认分别为 30 秒和 120 秒，因此单次模型等待最多 30 秒。分类异常保留错误码并继续既有证据评估：真实售价和非利润评分不受阻，无匹配就不写采购价；后续新证据或刷新沿原队列唤醒机制再次评估。数据库等评估错误继续使用原最多四次尝试与退避。未新增环境变量、依赖、表、迁移、生产服务或 Python 输入。

仅 `Qwen3.5-*` 或 `Qwen/Qwen3.5-*` 模型的货源分类请求增加官方非思考参数 `chat_template_kwargs: { enable_thinking: false }`；依据 [Qwen 官方模型卡的非思考模式说明](https://huggingface.co/Qwen/Qwen3.5-9B/blob/main/README.md#instruct-or-non-thinking-mode)。其他模型及同一模型的情报关联、主品选择请求不增加该参数。线上当前自托管模型已实测支持；若改用其他托管商，需按其实际接口契约重新验证，不能直接假定厂商扩展通用。

现有利润 API 的 `current_inputs` 与 Web 成本区直接消费原价格记录，无新增公开 API 字段；模型地址、模型名和凭证不下发浏览器。OpenAPI 扩展仅记录内部事件契约。

发布须使用固定本地构建与 `python scripts/deploy-baota.py` 流程，随后由宝塔重启 Node 项目 `ai选品`；API/Worker 在同一运行包中。无需 Python 重启。本项没有修改线上配置、生产数据或发布状态。

## 验证边界

单元测试覆盖分类输出严格结构、真实原文、独立属性、过时证据、无效新报价、新人价、币种和规格冲突、模型返回排序、普通 case 分类、事务外模型读取、过期租约、人工输入保护、原始金额和来源审计同事务回滚；并回归原手机壳、利润未知和情报关联流程。

这些使用明确的合成夹具与模型 HTTP 替身，证明实现约束，不能替代真实模型质量、实际中英文同款、源站长期稳定性或每天百品验收。每天百品继续按已确认的“完成整条流程，含低分和不推荐”统计，具体见 `selection-daily-production.md`。

本轮实际结果：116 项相关测试通过；22 个工作区完整构建通过，最终 Worker 修改另编译通过；格式、静态分析、文档、路由、运行文档和 OpenAPI YAML/Feature Map 解析通过。没有为此次 Worker 改动重复运行全部历史测试或无关浏览器截图。

服务器端使用真实已配置模型、合成英文主品和三条合成中文标题做探针，不写数据库、不部署文件。`/models` 返回 200 且包含已配置模型；原思考路径在 30 秒及诊断用 90 秒内均超时。使用上述官方非思考参数后，同组输入在 1,769 毫秒返回唯一匹配的尼龙化妆包，排除真皮款与手机壳；通过严格输出验证。该证据只证明真实服务契约及本组合成分类，不证明实际图搜同款质量。

扩展到十条合成候选后，真实模型把硅胶包误判为兼容，并绕过材质引用而选择其他三项属性。该失败促成上述独立材质校验及永久回归测试。修复后重跑真实模型与实际报价选择函数：3,876 毫秒返回，原模型仍包含硅胶误判，但确定性校验拒绝该项，仅选中原尼龙报价。此结果证明必须保留代码证据校验，不能把模型分类当作事实。
