# 历史补偿先筛缺失任务，再解析主品图片

2026-10-18旧补偿查询在派生表中为所有趋势商品计算主品身份，然后关联历史任务判定是否需要补偿；即使没有缺失任务，也要完成全部主品解析和排序。生产执行计划估算扫描74,000余条子查询，原版SQL只读复测确认：原SQL移除FOR UPDATE后仍在3000ms限制触发ER_QUERY_TIMEOUT（3031ms）。此前尝试把来源恢复条件加入旧扫描的方案在单次10000ms限制内也未返回，没有发布该方案。

现在先按原同组织/工作区关联的竞品、自动找货种子事件、搜索及有效下游子查询筛出缺失任务，并排除非活动组织或工作区；仅把这些候选物化后解析主品身份、同主品图片。两层最大无符号LIMIT用于防止MySQL5.7合并派生表，不是业务数量上限。最后仍在图片可用和来源启用条件之后取20条可执行结果；不把20张缺失图片当作20个完成名额。已有正确图搜任务继续由原队列管理，故障恢复重排仍沿用独立的单条补偿。

外层关联真实competitors和sourcing_searches记录，竞品使用STRAIGHT_JOIN及PRIMARY索引保证候选驱动的主键关联，找货主键关联和原事务锁保留。搜索链接如已被其他任务更新即排除；竞品排队前在其记录已锁定的事务中对现有任务做当前锁定读取，避免物化候选过期后重复建任务。原required=true、supplier-keywords-v2、主品图片身份、事件、20次新任务后一次补偿的节奏及定期详情/发现交替不变。
