# 自动找货的历史补偿与来源收敛

2026-10-17，自动商品发现只向已启用的 `1688_search` 排队找货，不再自动分流 Made-in-China、EC21 或 DHgate。其他来源的后台登记、历史证据和人工采集接口未删除。

首次发现有主图的 Amazon 主品时，沿用现有找货任务与四字段 LAN 图搜合同。没有主图或 1688 尚未启用时保留缺失状态，不改来源开关、不虚构报价、不排队其他供应商来源。

历史补偿复用趋势 Worker、现有租约和事务。它按组织、工作区和主品 ASIN，从关联 Amazon 证据选择主图，只允许现有图搜支持的两个 Amazon 图片主机，不用最新竞品图片代替主品。补偿对象必须有未删除且属于该商品的搜索；旧关键词任务不能阻止首次正确图搜。同一搜索因多个竞品进入同一批时只排队一次，任务、搜索链接在同一事务内写入，失败整体回滚。

已存在含图片的有效 1688 任务仍由原队列重试和死信规则管理，不无限重放。没有可用来源或主图的记录不占用本轮 20 条可执行补偿名额；两个下游来源都未启用时直接结束，不扫描历史队列。队列空闲时立即补偿；持续繁忙时每领取 20 个投影任务给补偿一个执行轮次，再继续处理新任务。同一轮不重复补偿；补偿失败由原轮询器报告，下轮仍允许新任务前进，不永久卡在补偿前置阶段。20 是与补偿批次一致的内部调度上界，不新增配置项，不改变第三方限流、来源审批或每日产出事实。

## 查询与验证

MySQL 5.7 将主品身份在派生表中物化一次；其中最大无符号 LIMIT 用于阻止优化器合并派生表，不是采集数量配置。找货事件和下游子查询先按租户与业务键聚合后关联，避免为每个商品反复解析整个事件集合。

最初直接嵌套的版本在真实 MySQL 5.7 只读运行中超过 5 秒，未作为通过结果。调整后，EXPLAIN 与实际只读 SELECT 合计约 1529ms，返回 20 条可执行记录、20 张主品图片。SELECT 移除了 FOR UPDATE，不领取任务、不写生产数据；生产队列调用设备并持久化返回证据仍未验收。六台单图实测见 `docs/selection-lan-1688-validation.md`。线上版本仍为 c26e2b522bc616cbc2a67b01185d832f93789174。

`npm run build:worker` 通过；`node --test tests/unit/automatic-sourcing-recovery.test.mjs tests/unit/trend-projection-worker-scheduling.test.mjs tests/m04-01/trends.test.mjs tests/unit/core-workspace-crawlers.test.mjs` 共 46 项通过，覆盖首次找货、来源与图片缺失、重复排队、租户与删除边界、可执行批次、失败回滚、持续繁忙公平补偿和原采集投影合同。自动评分、LAN 图搜、情报关联、公开信号与竞品策略另 55 项通过；Backend 编译及静态分析通过。

## 使用与部署

无新环境变量、依赖、API 字段或数据库迁移。沿用 `LAN_1688_TOKEN` 和 `LAN_1688_TIMEOUT_MS`；密钥只在宝塔受限配置维护。需本地构建 Node 包，通过固定脚本上传，再由宝塔重启唯一 Node 项目：

`/www/server/panel/pyenv/bin/python /www/server/panel/script/restart_project.py nodejs ai选品`

Python 不因本项重启。本轮未部署；此前阻止提交的旧 UI 校验已逐项修复，整套覆盖与失败复测结果见 `docs/selection-ui-validation-boundary.md`。此修复不能作为全站重制、连续自动运行或每日百品的完成证据。
