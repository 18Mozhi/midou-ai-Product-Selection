# Amazon 主图的属性边界修复

## 事实与改动

2026-10-18 通过现有浏览器运行器和全局租约对真实 ASIN B09HL7C2FP 进行匿名核验。一次仅标题节点探测返回，一次30秒导航超时；一次60秒上限的完整片段核验返回250000字节DOM，耗时约58.6秒。结果仅证明该次可获取部分页面，不证明浏览器采集已稳定或接入自动选品。

真实 landingImage 标签长1740字符，onload 属性含有大于号。旧 `<img ... [^>]*>` 正则在第436个字符提前结束，因此漏掉后面的真实 id 和图片地址。现在按完整的单双引号属性值扫描图片标签，再从真实属性边界读取 id、data-old-hires、src。属性值内部伪装的 id 或 src 不再被当作属性。

主图仍必须是 leftCol 内 id 严格等于 landingImage 的图片，并满足既有 Amazon 图片域名与路径限制。不补其他商品或推荐区图片，不把缺失价格变为零。实际片段回放中，原来为空的主图已正确恢复为对应Amazon图片；评价数2761、星级4.7保持一致，价格仍为未知。

适配器版本从 v11 升为 amazon-public-product-adapter-v12。原始字段、source_paths、标准化 schema amazon-public-product-v5、健康规则和数据契约保持不变，不需要改动来源 parser_version。

## 仍未完成的部分

片段达到既有250KB上限，价格区域没有进入截取范围；这与图片标签解析是两个问题。当前匿名浏览器验证不等于 Amazon 浏览器自动任务已接通：现有 authenticated-browser-job-client 的请求与解析分派仅实现1688。不能只修改来源 access_mode 就宣称采集可用。HTTP详情健康复检仍为 permission_denied，熔断没有解除；每日100条完整链路未验收。

核验未导出当前Chrome的登录Cookie。临时档案为空tar归档，按既有服务加密保存、获取运行租约并结束运行；四个空档案资产及三个实际创建的档案均已撤销，保留真实操作和运行审计。没有活动档案租约。本次创建的浏览器临时文件由现有库回收；另有2026-09-04形成的历史目录，不属于本次核验，保留不动。

## 验证与运维

两个新增回归用例在旧实现失败，修复后详情事实17项及Amazon相关85项测试通过。真实DOM在本地使用编译后的实际解析器回放确认主图；没有把手工核验资料写成正常采集任务、补造详情证据或计入每日完成数。

无新增依赖、环境变量、API字段、权限、数据库迁移或Python输入，OpenAPI和环境示例没有对应变更。现有宝塔发布后需要重启Node加载适配器v12；无需用户调节参数。正式发布版本、运行与清理证据记录在对应发布收据，不能以本修复替代完整浏览器采集和整链验收。
