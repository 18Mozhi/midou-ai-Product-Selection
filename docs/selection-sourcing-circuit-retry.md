# 来源恢复后补齐被熔断挡住的自动找货

2026-10-18生产三个新主品的找货任务因source_circuit_open告警结束，随后找货投影标为succeeded_empty、报价数0。旧补偿只检查有没有正确图搜任务，因此保留的旧任务会永久阻止再次找货。空结果不是找到货源，更不能计入每日100。

在既有趋势Worker补偿轮次之前增加一个独立有界补偿，每轮最多一个。仅处理原Worker自动创建、completed_with_warnings、结果数0，且图搜子查询明确blocked/source_circuit_open的任务；搜索仍关联该任务、未删除、queued或succeeded_empty、没有任何报价候选，同组织和工作区均活动，机会仍为未删除趋势商品。1688必须enabled、条款有效、authenticated_browser，熔断记录真实closed且recovered_at晚于原子查询失败时间。真实空结果、其他错误、死信、已有报价、来源未恢复都不补偿。

先非锁定读取候选，再只按找货记录主键和租户锁定一行，重新验证全部条件及原任务链接。使用同机会同主品原始证据的当前主图，沿用Amazon两个既有图片主机和supplier-keywords-v2图搜合同。现有任务producer写required=true；若来源再次熔断，由原队列等待。找货链接、任务和sourcing.search.circuit_requeued事件在同一事务提交，事件保留旧/新任务及恢复时间；旧任务、原错误、尝试和事件均不修改。其他Worker抢先更新链接、条件失效或缺少主图时不排队；任一步失败全部回滚。新链接不再指向旧任务，后续轮次不会因旧失败重复排队。

没有新API、环境变量、数据库迁移、依赖或服务。OpenAPI仅记录内部事件合同，浏览器和Python不消费。由现有deploy-baota.py本地构建发布，宝塔Node项目必须重启以加载Worker代码；官方脚本执行该重启。生产验收查看既有找货任务、链接及sourcing_events，不需要用户手动重试或提供API。来源当前仍故障时保持等待，不人为改变来源或数据库来制造恢复。

## 验证与未完成事项

新策略在MySQL5.7真实三条记录上只读验证8种场景：当前熔断0、内联模拟故障后恢复3、恢复早于故障0、其他错误0、缺少Worker来源0、子查询有结果0、任务有结果0、其他终态0。模拟仅替换SELECT中的临时派生表，没有修改生产状态。最终独立完整候选查询2ms返回0；事务单元检查覆盖链接竞态、条件失效、非法图片、排队/更新/审计失败回滚及既有required任务producer。

曾尝试把规则并入旧的大范围历史补偿查询；完整只读查询超过3秒，单次有界10秒仍超时。该接法已撤下，最终代码不修改旧扫描SQL。旧扫描本身的性能问题仍待当前总目标后续处理，不能把本项写成全队列性能修复。96项Worker/找货/趋势/情报相关检查通过。真实来源恢复后自动重排、匹配报价、5–10竞品和每日百品仍须生产验收。
