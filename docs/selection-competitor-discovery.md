# 主品与 5–10 个独立竞品

2026-10-17 按用户当前要求重制。此项是完整自动选品链的一部分，不能代替情报关联、全量字段采集、每日百品或生产验收。

## 真实调用链

已启用规则发现有 Amazon 主品证据的候选后，`TrendProjectionPersistence.createDownstreamDiscovery` 在原事务内新增 Amazon 相关搜索任务：`projection_type=opportunity_competitors`，引用当前 `opportunity_id`，并携带来源 URL 中的 `main_asin`。主品详情任务与 1688 找货仍各自调度。

搜索任务终态后，`CoreCollectionProjectionWorker` 只读取本任务、本组织与工作区的规范化记录。先验证 Amazon 商品 URL 与 ASIN 一致，排除主品，按 ASIN 去重，最多选择十个。结果不足五个时不复制或虚构商品，保留真实 `item_count`，投影回执标记 `competitor_count_below_minimum`，Worker 返回 `discovery_status=insufficient`。数量达到五个只代表发现阶段满足最低数量，不代表详情或分析已完成。

每个实际选中的竞品获得独立的 `competitor_snapshot` 详情采集任务，以及任务事件、竞品事件和 Outbox。搜索快照可以先显示已获取的真实价格与评价，但不能被当作详情采集完成。详情结果继续走既有快照投影、比较、评估重排链；并发、超时、失败重试仍由既有采集调度器控制，不新增服务。

同一 ASIN 已属于另一个机会时，本轮不会夺取或改写其机会归属，也不会计入当前机会成功数量。跨机会共用商品的关系模型仍需继续完成，这一情况可能导致有效竞品不足五个。

## 读取、界面与质量门

- 既有机会列表/详情新增只读 `main_asin`，来源是本组织与工作区内持久化 Amazon 证据；未能识别时为 null。
- `competitor_count` 排除主品。详情竞争页单列主品，使用紧凑表格比较最多十个独立竞品的价格、星级、评论数与采集时间。未知字段保留“未采集”，过期与详情待采集分别标明。
- 既有竞品接口的 `latest_snapshot.detail_collected` 为只读、服务端推导字段。服务端从快照的真实采集任务引用检查同租户的 `competitor_snapshot` 与 Amazon 详情 URL，不接收客户端声明。`source_enabled` 单独反映来源当前启停状态，停用来源保留历史快照展示，但不计入有效分析数量。
- 详情证据还绑定相同竞品 ID、原始证据 ID、规范化记录 ID 和 `collection:` 引用前缀；竞品详情投影只接受目标 ASIN 本身的结果，不把首条其他商品写入当前对象。
- 竞争质量门必须同时满足：已有竞争评分、主品身份明确、至少五个独立 Amazon 竞品在当前已启用来源上具有 fresh/healthy 的详情快照，并具备价格、币种、评论数和星级。主品不计入五个；搜索快照、重复 ASIN、空指标、暂停或删除对象不能补足门槛。
- 首页推荐数、机会筛选、详情结论、机会采纳事务与选品流程采纳复用同一 SQL/读模型合同。观察、驳回流程不增加此限制。原始分数与权重不重写，仍以线上已确认的五维规则为准。
- 自动评估中的商品现货状态与评价回退只读取主品本身的快照，不再任取最新的另一个竞品；Amazon 的真实 `rating_value` 字段优先于旧别名。

`MINIMUM_SELECTION_COMPETITORS=5` 与 `MAXIMUM_SELECTION_COMPETITORS=10` 在 contracts 中共用。这是用户明确的产品要求，不是新环境变量。现行 fresh 标记仍沿用既有采集合同；持续刷新与按时间失效的完整验收尚未完成。
