# 主品证据驱动的选品候选

2026-10-17 本次用户要求优先于旧的“必须命中关键词规则且达到独立来源门槛才能评分”约束。关键词监控保留为可选采集入口，不能限制情报自动发现的商品进入选品流程。

## 实现

- `packages/database/src/selection-candidate-sql.ts` 统一 API 与 Worker 的主品身份条件：同组织、工作区和机会的有效规范化 Amazon 证据，十位 ASIN 与真实 `https://www.amazon.com/.../dp/ASIN` 或 `gp/product/ASIN` 商品 URL 一致。新闻标题、仅有关键词、错误域名、其他商品的 URL、跨租户和失效记录均不能替代主品。
- 自动评估、评分规则/成本规则更新后的批量评估、机会列表/筛选、详情、首页计数和采纳质量门复用相同条件，不再要求 `opportunity_rule_matches` 或 `recommendation_min_source_count`。最终建议采纳仍须五项质量门全部通过，包含至少五个独立有效竞品详情；人工采纳权限、事务审计和幂等不变。
- Worker 每轮以 100 条为上限补齐缺少评估记录的、未归档且待决策的真实主品；历史 `succeeded` 回执中只有精确 `result_json.skipped=not_rule_candidate` 才恢复排队并清除旧回执。不会重置 leased、失败或其他成功任务。
- 竞品发现、竞品详情和机会找货实际写入新结果后，在相同事务中唤醒本组织/工作区的对应机会评估。图片或关键词独立找货没有机会关联时不猜测归属；已有 leased 评估保留租约。
- 删除原来位于 Amazon 主品专用分支内、永远不可能触发的 1688 批量唤醒逻辑，以及详情中只用于旧来源门槛提示的聚合查询。持续采集结果通过真实对象关联唤醒。
- 首页推荐、采集与采纳计数不再通过规则关联表过滤。运行状态同时读取真实全量情报调度记录、来源是否可用和最近任务异常；零关键词规则不等于未配置。停止或出错的来源不会显示为正常运行。
- 首页不再自动打开必填关键词设置，关键词表单明确为可选监控，删除已经不再决定候选资格的来源数量控件。选品库文案统一为真实主品与五项质量门；缺少服务端阶段时不再通过命中规则数量猜测候选。
- 修复新版首页窄侧栏内的旧双列待办和宽版运行详情布局，确保桌面及手机的异常、进度和重试结果可见。

## 合同与使用

本次没有新增或删除 API 字段、响应枚举、数据库结构、依赖或环境变量。历史 `selection_stage=rule_candidate`、`selection_view=rule_candidates` 和 `rule_candidate_count` 保留字段名，现语义为已确认主品且仍在补齐质量门的选品候选；界面显示“选品候选”。旧监控请求字段 `recommendation_min_source_count` 保留兼容，当前表单沿用原默认值 1，不再将它作为评分或推荐前置条件。监控规则的开关、关键词、频率和来源审批仍有效。

使用现有情报来源即可自动发现商品；添加关键词监控是可选操作。评分权重、推荐/观察阈值和费用参数本次不改。通用品类费用及评分输入仍需继续完成，未知值保持缺失，不因去掉监控门槛而补造分数或利润。

配置读取、Python 和来源执行协议不变。发布时本地构建前端与 Node 包，按固定宝塔脚本上传，然后重启唯一 Node 项目：

`/www/server/panel/pyenv/bin/python /www/server/panel/script/restart_project.py nodejs ai选品`

当前尚未部署；线上只做只读验证，没有运行上述补偿写入，也没有修改生产配置或进程。

## 验证

定向测试覆盖无规则情况下的候选/推荐/采纳条件、五项质量门、真实来源调度状态、精确历史回执补偿和新证据唤醒。浏览器回归覆盖桌面与 390px 手机的首页读取/重试/轮询清理、可选监控表单、选品库筛选及主品/竞品对比。

线上 MySQL 5.7 已对首页两段读取和补偿任务两段 SELECT 做只读 EXPLAIN；同一主品 SQL 还使用 SELECT 内派生样本验证有效商品、ASIN 不符、域名不符、跨租户和失效记录五个情况，全部符合预期，不创建临时表、不写入生产数据。真实连续百品、来源恢复、费用与评分全链、旧模块清理和全站 UI 验收仍未完成。
