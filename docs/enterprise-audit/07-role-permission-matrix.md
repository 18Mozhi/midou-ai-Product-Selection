# 《角色权限矩阵》

## 1. 角色

| 角色                        | 类别 | 主要能力                                                  | 明确禁止                             |
| --------------------------- | ---- | --------------------------------------------------------- | ------------------------------------ |
| `member`                    | 组织 | 任务读写、趋势读、机会读/决策、竞品读、供应链读、本人通知 | 组织治理、平台后台、成本管理         |
| `selection_manager`         | 组织 | member + 指派、机会审批、团队管理、报表                   | 平台全局、超级管理                   |
| `procurement_member`        | 组织 | 任务、机会读、供应链、报价管理、成本确认                  | 机会审批、平台后台                   |
| `organization_admin`        | 组织 | 当前组织成员/角色/工作区/团队/令牌/审计等非平台能力       | 其他组织和平台全局                   |
| `auditor`                   | 组织 | 业务/报告/授权/审计只读                                   | 业务写入和授权写入                   |
| `platform_operations_admin` | 平台 | 平台运营、来源配置、采集重放、报表与业务只读              | 密钥明文、超级授权、安全专属处置     |
| `platform_security_admin`   | 平台 | 安全、会话、平台 Token、审计、密钥轮换和业务只读          | 业务内容修改、商业运营写入           |
| `platform_super_admin`      | 平台 | 全平台初始化、授权和紧急处置                              | 仍受审计、秘密不回显和最后管理员保护 |

## 3. 数据隔离

- 会话上下文绑定 `user_id + organization_id + workspace_id`。
- 数据范围支持 own/team/workspace/organization，并可叠加 resource grants。
- 平台角色不自动成为任意组织业务成员；业务写入仍需要明确合同。
- 列表、详情、写操作和下载都必须在服务端重新裁决，菜单隐藏不是权限证据。
- 跨租户测试以 tenancy/RBAC/resource-grants/各业务 repository 测试为证据；没有证据的长尾接口见 API-001。
