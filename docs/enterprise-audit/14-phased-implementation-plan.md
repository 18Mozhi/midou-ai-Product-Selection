# 《分阶段实施计划》

本计划只安排尚未关闭的企业级缺口，不重新重构已验收的 73 个页面。每批仍遵守“一页或一条完整链路、独立分支、验收后提交”。

| 阶段            | 范围              | 前置                           | 交付                                                    | 门禁                                 |
| --------------- | ----------------- | ------------------------------ | ------------------------------------------------------- | ------------------------------------ |
| S1 基线归零     | GAP-012           | 用户允许独立质量批次           | 静态分析、10 单测、favicon 各自修复                     | 不改业务语义；全回归                 |
| S2 接口证据     | GAP-001/008       | 生成稳定 operationId 清单      | 257 operation 结果 manifest、跨租户矩阵、覆盖页真实读取 | 正常/鉴权/参数 100%；写接口幂等/并发 |
| S3 邮件渠道     | GAP-003           | 用户选定测试 Provider 和测试域 | 投递、退信、投诉、延迟、失败、抑制与审计                | 禁止真实客户通知；全周期测试通过     |
| S4 1688 链路    | GAP-002 的 1688   | 测试账号/人工验证码/隔离档案   | 创建到重启恢复完整证据                                  | 不绕过风控；验收后才能启用           |
| S5 Amazon 链路  | GAP-002 的 Amazon | 测试账号/隔离档案              | 同上                                                    | 同上                                 |
| S6 Webhook 安全 | GAP-009           | 本地安全接收端                 | SSRF/签名/nonce/重放/重定向结果                         | 攻击集全拒绝，正常投递通过           |
| S7 容量基准     | GAP-005/011       | 明确目标峰值                   | API/Worker/DB/Redis/文件/浏览器压测与 soak              | 阈值签认                             |
| S8 生产演练     | GAP-004/006       | 宝塔维护窗和授权               | 发布、回滚、备份恢复、故障演练、404 HTTP 状态           | RPO/RTO、健康、核心链通过            |
| S9 可访问性     | GAP-010           | NVDA/高对比环境                | 关键链人工记录                                          | 登录→选品→任务→导出无阻塞            |

任何阶段失败都停在该阶段，不跳过验收进入后续阶段。
