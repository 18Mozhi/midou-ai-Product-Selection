# 《性能与容量风险报告》

## 风险清单

### PERF-001（P1）单机资源共享导致采集挤压 API

- 模块：Node 后端/Worker/Python/Chromium；类型：容量。
- 描述：生产边界是单机，浏览器采集、报表和业务 API 竞争 CPU/内存/IO。
- 复现：并发采集、报表导出和页面聚合同时运行，观察 `/platform-admin/capacity`、topology、MySQL/Redis。
- 预期：API 延迟仍在 SLO，调度器产生背压而非进程失稳。
- 实际：本地资源探针和有界并发存在，真实峰值未压测。
- 证据：queue registry、capacity audit；文件/接口/数据：Worker、capacity API/observations。
- 影响：全站；严重度：P1。
- 建议：上线前以目标峰值做 30/60/120 分钟分层压测，锁定 crawler/browser/report 的资源预算。
- 验收：P95/P99、错误率、队列延迟、内存峰值、句柄数、MySQL 连接和磁盘余量全部低于签认阈值。

### PERF-002（P2）聚合驾驶舱随数据增长退化

- 模块：首页、平台概览、组织概览、状态/容量；类型：查询性能。
- 描述：多业务聚合会随组织、任务、证据和日志增长而扩大扫描。
- 复现：构造百万级历史事实并运行首页/平台指标。
- 预期：分页/时间窗/投影索引保持有界。
- 实际：迁移有索引和投影，但未做生产规模基准。
- 影响：首页和运维判断；严重度：P2。
- 建议：建立固定数据规模基准，慢查询只通过索引/投影优化，不在 UI 隐藏真实数据。
- 验收：目标数据量下 API P95 达标且 explain 无全表扫描。

### PERF-003（P2）日志、审计和证据保留增长

- 模块：logs/audit/evidence/files；类型：存储容量。
- 描述：不可变审计、采集证据和导出会持续占用单机磁盘。
- 实际：保留期、容量页和文件观察存在；真实长周期增长未验证。
- 建议：按数据分类设置保留/归档/校验策略，任何删除都需审计和恢复窗口。
- 验收：容量预测覆盖至少一个保留周期，磁盘告警提前量满足运维窗口。

### PERF-004（P2）超大导入/导出和分页边界

- 模块：ERP 导入、报表、平台数据/日志导出；类型：内存/IO。
- 描述：大文件或大范围导出可能阻塞 Worker、占满临时目录。
- 实际：异步 Worker、行数上限、短期下载授权存在；峰值未压测。
- 建议：流式读写、每租户配额、临时文件总量限制、失败清理和磁盘预留。
- 验收：最大允许文件和最大行数下无 OOM，失败后临时文件归零。

### PERF-005（P3）前端长表格和多卡片渲染

- 模块：机会、任务、数据、日志、采集；类型：前端。
- 实际：服务端分页和前端预算检查通过；极端长文本/异常数据逐页有边界测试但未覆盖所有组合。
- 建议：维持服务端分页、稳定 key、有界文本和按需加载；不以删除字段换性能。
- 验收：常见四档分辨率无溢出，交互期间无长任务，首屏资源预算通过。

## 容量结论

当前可证明“单机有边界、有观测、有背压”，不能证明“已达到未知生产峰值”。上线必须先定义组织数、日采集量、并发浏览器、证据日增量、日志保留和导出规模，再执行容量签认。
