# 货源报价列表重制

## 参考与实际问题

当前用户要求所有样式、UI与布局重构，尤其产品列表，并严格精简非核心成员流程。本轮重新通过真实已登录Chrome查看Ecom168监控概览及选品库：前者可见统一列的监控对象表格，后者当前为空，仅核对筛选和信息层级，没有虚构同行商品数据。借鉴其紧凑操作与统一扫描结构，不复制其AI标记/装饰指标。

原货源候选使用两列大卡片，每项重复九格底色数据与六项缺失说明，桌面首屏只见很少报价；详情费用入口在长标题旁被挤窄。现在用SupplierOfferList替换原整段卡片模板：商品/供应商、原币报价、MOQ/交期、状态/观测时间、原商品/报价确认或对比统一成列。小屏转换为同一行事实的双列排列，没有第二套数据或页面横向滚动。长标题保留完整title与原生证据展开，价格条件单独显示，确认报价后不套用旧采集新人价。

证据、完整标题、规格、所在地、可信度、稳定性/风险、到岸价缺失、原始采集时间与采集/报价证据按行原生details展开，缺失项原样映射展示。折叠不改变任何事实/完整度或评分；展开不请求或写入API。报价确认、2–5家比较及分页/记录选择继续调用原composable，原币种金额与观测时间不重新计算。只保留页首费用规则链接并保留from返回位置；采集成功等已有任务状态翻译为中文，状态码本身不改。

移除旧supplier-cards、supplier-missing-actions和已不使用sourcing-actions共49个CSS选择器（203行旧CSS），保留其他报价比较/弹窗/主题样式。新样式只作用于货源列表，修正全局表单最小尺寸对复选框的影响，复选框16px、标签/操作与summary触点仍至少44px。
