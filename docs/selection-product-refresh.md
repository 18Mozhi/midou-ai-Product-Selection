# 主品与竞品详情周期刷新

首次自动选品原先只补齐缺失快照，已有快照不会持续重采。现复用趋势 Worker 的既有公平补偿轮次：先处理缺失下游任务，当前没有可执行缺失项时，按最旧 captured_at 为一个到期商品排队 Amazon 详情任务。主品和独立竞品均沿用 competitors 台账及 competitor_snapshot 投影，结果继续触发原评分评估与变化比较，不新增服务或外部 API。

只处理活动 Amazon 商品、未归档/删除的自动情报机会；机会、商品、快照、近期任务都按组织和工作区关联。URL 与 ASIN 必须一致，SQL 先排除无效身份，避免坏记录占住最旧位置。Amazon 来源未启用则不刷新，不改变来源开关或审批。事务中排队并保留原采集事件，失败整体回滚。

## 间隔和积压

服务端 COMPETITOR_REFRESH_INTERVAL_SECONDS 默认 3600 秒，可设置 300–604800 秒；这是重采间隔，不能承诺平台数据每秒更新。到期仍会受队列、公平补偿轮次、采集耗时及错误重试影响。近期已经派发过详情请求的商品在同一间隔内不重复入队，包括失败请求，防止绕过原重试或无限重放。

同组织有活动采集任务时等待；全局活动任务达到既有 AUTOMATIC_SOURCE_QUEUE_BACKLOG_LIMIT 时等待。每轮最多一个刷新任务，按最旧快照优先，保持现有固定单 Worker 拓扑。没有引入跨进程分布式并发承诺。首次缺失补偿与新情报投影继续先行；本项不保证每天达到 100 个合格新品。

## 验证和发布

配置默认值、边界、请求合同、隔离、冷却、缺失补偿优先、失败回滚与原采集/评分回归共 110 项通过。第一次逐商品相关子查询未通过真实 MySQL 5.7 的 5 秒验证上限，已替换为预聚合近期任务和组织积压的关联查询；最终 EXPLAIN 与只读 SELECT 合计约 102ms，返回 1 个到期候选。只读验证去掉 FOR UPDATE，未领取、写入、调用 Amazon 或触发生产刷新，不代表持续运行验收。

配置已同步 config/env.example、config/schema.json 和运行时读取。无数据库迁移、前端/插件/Python 字段变化，原投影消费者继续使用原任务合同。通过固定 python scripts/deploy-baota.py 本地构建发布后，在宝塔受限环境调整参数并重启 Node 项目 ai选品；Python 无需因本项重启。本轮未部署、没有临时文件或常驻验证进程。

## 乱序完成与重复任务

快照比较原先无条件更新 latest_snapshot_id，旧详情任务较晚完成会把当前数据倒退。现在在现有事务和商品锁内比较 captured_at，同时间按快照 ID 与证据读取保持一致的稳定顺序推进；已经是当前快照或更旧的任务只完成队列状态，不生成反向变化、告警或重复评估。不可变快照仍保留。首次快照及真正更新继续走原变化比较、当前指针更新与评分排队；评分排队失败整体回滚。快照读取同步显式约束组织与工作区。无新 API、事件名称、配置或数据库格式。

本地新增 7 项生产比较函数回归，覆盖延迟、重复、同时间顺序、首次/新快照和排队失败回滚；与竞品发现、自动评分和采集的相关 99 项检查通过；不等同于生产连续运行验收。发布仍由宝塔重启 Node，Python 无需因本项重启。

- 不足五个有效竞品或缺少相关性证明时，现可复用相同冷却间隔补采发现，并与到期详情轮换；资格扫描最多每分钟一次，见 `docs/selection-competitor-rediscovery.md`。不代表已经运行生产补采。
