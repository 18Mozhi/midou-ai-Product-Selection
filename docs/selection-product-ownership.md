# 选品独立商品记录

2026-10-19 用户授权自行审批实施决策。采用每个选品独立保存商品与快照，不搬迁旧归属、不共享其他选品快照，也不修改权限或完成门。

## 实际断点

当前选品 c8c10134-36cc-43c2-b0a8-aea3f40a73e6 的主品 B0FH4V325T 已被工作区内另一选品持有。旧唯一键只含组织、工作区、站点、市场和 ASIN；INSERT IGNORE 后的无选品条件查询取得旧记录，当前选品没有自己的详情。实际评估停在 amazon_competitor_snapshot_missing，即使该选品的 1688 找货任务已成功返回 60 条。

## 两步发布

1. 准备代码先上线：主品与竞品写入后的查询必须绑定 opportunity_id；未找到自己的真实行就不调度虚构 ID。未关联选品的手工新增先锁同组织工作区，再以当前锁定读取检查未关联的同市场、站点、商品身份，包含软删除记录；重复仍报既有 competitor_identity_conflict/409。
2. 再应用 0075：普通联合唯一键增加 opportunity_id。不同选品可各有一条同 ASIN 记录，同选品仍禁止重复；不新增业务列，不复制快照或分配历史任务。MySQL 的 NULL 不参与唯一去重，未关联新增由上述 API 事务串行化保护。

第一步兼容旧唯一键；旧键冲突时自动补建 INSERT IGNORE 返回未修复，继续其他任务。不能在第一步上线前执行第二步，也不能回滚至没有归属约束的旧代码。0075 的 down 在存在跨选品重复时失败关闭，不删除或合并商品。硬删除选品仍遵循原外键 SET NULL，历史商品保留；这些历史未关联记录不会被自动转交其他选品。

本地 MySQL 5.7.44 发现外键 SET NULL 后生成列唯一索引不能可靠去重，因此明确不采用生成列方案。普通索引迁移已用同版本业务账号和合成数据验证：原行/快照引用不变、同选品重复拒绝、跨选品新增成功、失败 down 保留新索引、无重复 down 成功、两个 API 并发未关联新增仅一个成功、外键置空保留。

## 自动补建与范围

复用既有下游修复事务。启用 Amazon 公开来源时，每次按选品主键游标扫描至多 20 条有该来源证据的选品，游标耗尽循环，从不因队首无主品而永久停住。只考虑有效组织/工作区、trend_topic、pending、非 archived/deleted 选品。每轮最多补建一个缺少当前主品身份的记录，且事务提交后才推进游标；重启从头扫描，已有记录与任务检查保证幂等。

非锁定扫描后按当前选品主键和租户加锁，重新验证可运行状态与该选品自己的主品原始证据、来源状态、ASIN、Amazon 商品 URL、非空实际标题。再次锁定查询同选品同身份，软删除也不重建。新记录 latest_snapshot_id=NULL，由既有 competitor.collection.auto_scheduled 生产者建立新详情任务，之后仍经过真实详情投影、竞品分类和原评分门；不重置旧任务或把补建记录计作完成。

全量非锁定扫描实测超出 5 秒只读查询上限；改为先按主键范围限制 20 条，再计算原主品身份。最终线上只读 EXPLAIN+SELECT 实测 1052ms，内层主键范围、外层 20 行。未扩大查询超时。

## 配置、消费方与验收

没有新增环境变量、外部请求字段、依赖、端口、来源节点或服务。前端、Python、插件请求不变；API 写入、Worker 主品与竞品生产者、自动修复以及原有按选品读取的详情/评估消费者已逐项核对。OpenAPI 仅补充原 opportunity_id 的身份语义。

按固定宝塔部署命令发布；准备代码和迁移发布均需由部署器重启 Node 项目 ai选品，API/Worker 同包。Python 不需单独重启。无需用户调节；已有来源开关、任务租约、重试、分类、评分、5–10 详情竞品、未知利润和每日首次完成规则保持原状。

准备实现及隔离数据库验证不等于线上整链完成；需继续核验当前选品独立主品、新详情任务、真实快照、竞品、报价与完成事件。每天 100 个及全部 UI 尚未验收。
