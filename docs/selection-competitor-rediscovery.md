# 不足竞品的周期补采

原周期补偿仅处理首次缺失详情/找货及已有商品的到期详情刷新。竞品发现不足五个、分类失败或历史没有相关性证明时，没有后续发现任务；仅增加质量门不能让链路自行恢复。本项在已有单 Worker 的下游补偿轮次增加有冷却的竞品补采。

## 运行顺序与范围

首次缺失任务仍优先处理。没有这类工作时，到期详情刷新与不足竞品发现轮换；每个事务最多新增一个周期任务，一条链没有到期工作时可以服务另一条。仅在事务提交成功后推进轮换和扫描时间，失败按原路径回滚。原忙队列每二十个投影任务服务补偿的轮次不变。

补采仅面向活动组织/工作区、未归档或删除的自动情报机会，要求已有有效 Amazon 主品 ASIN 和同一主品的非空原始 Amazon 标题；可编辑的机会名称不能作为补采搜索词。通过共享竞争质量 SQL 判断不足：少于五个具备当前相关性与详细健康证据的独立竞品才需要补采。先预聚合实际 Amazon ASIN 证据，物化当前主品身份，再复用该身份核对质量门；不重新定义主品或放宽证明。

同组织有活动采集任务或全局活动任务达到 AUTOMATIC_SOURCE_QUEUE_BACKLOG_LIMIT 时等待。按最近一次发现时间（没有时按机会创建时间）选最早到期者。最近发现任务包含失败和终态，冷却期内不创建新任务绕过既有重试。Amazon 停用时不扫描、不启用来源。已通过竞争门的机会不补采。

搜索词只读取本机会原始证据中的当前主品标题，按 ASIN、URL、原始证据、活动来源记录和组织/工作区绑定；缺失标题保持不足，不回退可编辑名称或历史关键词。

任务沿用 query、projection_type=opportunity_competitors、opportunity_id、main_asin 的真实已有合同和 competitor.discovery.auto_scheduled 事件。后续仍走原始证据、相关性分类、竞品投影、详情采集、评估重排和整链完成检查；不复制竞品、不抢占其他主品归属、不虚构数量。模型或数据仍不足时保留不足，不能保证每次补采成功。

## 间隔与调节

复用 COMPETITOR_REFRESH_INTERVAL_SECONDS，默认 3600 秒，范围 300–604800 秒；现在同时约束到期详情重采和不足竞品发现的冷却。修改示例已同步 config/env.example，配置键与默认值没有增加，config/schema.json 原键与边界继续适用。需要更频繁补采时可调小这个既有值，也会影响详情刷新。

较宽的竞品补采资格查询在单 Worker 内最多每六十秒执行一次，包括空结果；首次缺失补偿和原详情扫描不受该缓存限制。到期发现还受该扫描间隔、来源开关、队列积压和执行耗时影响，不能将冷却期说成精确更新时点。扫描缓存与轮换仅存在于现有单进程，重启后重新开始，不宣称跨 Worker 并发协调。

## 验证与边界

相关回归 113 项通过，22 工作区完整构建通过；最后原始标题修正后 Worker 重新编译和相关回归通过，覆盖首次修复优先、周期轮换、队列失败回滚、空查询节流、异常身份、分类和每日计数。缓存身份版本只替换固定 SQL 中的重复身份片段，默认 API/每日完成 SQL 不变，测试逐字比较替换前后其余条件。

在 MySQL 5.7.44-log 只读事务中，对实际生成的查询去掉末尾 FOR UPDATE，执行 EXPLAIN 和 SELECT；最终包含原始标题读取的查询返回一个候选，合计约 2038ms。最初重复主品查找约 3107ms，身份缓存约 1596ms，加 ASIN 证据预筛后约 1404ms，再补齐同主品原始标题读取约 2038ms，均为当次样本读数，不作长期性能保证。五秒 session 上限用于该验证连接，连接结束即释放，未更改全局配置。没有领取任务、插入采集记录、调用 Amazon 或运行生产补采。

本项不创建表、迁移、API 字段、前端入口、Python/插件输入、依赖或新环境键。API 的相关性与详情门仍为原消费者；无需浏览器重测来声称后端调度已真实运行。OpenAPI 同步自动补采说明，不改变字段合同。
