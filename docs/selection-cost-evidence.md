# 当前商品的采购成本证据

## 修复范围

自动成本输入必须属于选品库当前主品及其关联货源。旧评估器读取最后关联的 Amazon 趋势信号，可能与列表使用的主品身份不同；同时扫描工作区最近 500 条 1688 记录，可能将其他机会的相似货源用于当前机会。

现在 Amazon 输入复用 `selectionPrimaryAsinSql`，只读取同组织、工作区、机会下与主品 ASIN 一致且规范 URL 确认身份的有效记录。1688 输入沿 `sourcing_searches(input_type=opportunity,input_ref=机会ID)` → 当前找货任务 → 任务证据链接 → 有效规范化记录读取，并核对组织、工作区及原始证据 ID。独立图片/关键词搜索不猜测机会归属，删除的找货记录不参与。

同一 1688 `external_id` 的多次采集只保留最新观察，不算多个独立商品报价样本。先选择最新观察再检查价格、币种和标题匹配，不能因为最新报价失效而偷偷回退到旧低价。缺少链接身份或有效观察时间不计样本。三个独立报价、既有标题匹配和 p75 估价方法保持不变；不同链接也不等于不同工厂，本次没有新增这种保证。

接口实际返回的 `price_description=新人价` 保留在原始和规范化证据中，但不作为无条件的自动采购成本。若扣除这类报价后有效样本不足，沿用 `high_confidence_1688_match_missing` 等待真实依据。没有推算普通价、优惠资格或库存，也没有宣称其他未识别报价条件已经核验。

## 使用和运行

继续从当前机会发起或由自动链发起找货，结果会按现有任务关联进入成本分析；不再从其他机会或独立关键词搜索借用报价凑样本。现有人工确认成本不被覆盖。本次不增加 API、环境变量、依赖、数据库结构或迁移，不改评分权重、推荐阈值、手机壳费用适用范围和利润公式。

按项目固定部署脚本发布 Node 运行包后，由宝塔重启唯一 Node 项目加载代码：

`/www/server/panel/pyenv/bin/python /www/server/panel/script/restart_project.py nodejs ai选品`

无需重启 Python；本次未部署、未修改生产数据、配置或进程。历史已生成成本和利润不自动重写；新评估按新取证逻辑运行。重新评估发现有效货源不足时，若当前采购成本来自自动证据，则撤下仍待人工决策的旧“建议采纳”，保留旧事实和历史；人工确认采购成本和已决策商品不受这项撤下操作影响。通用品类费用、跨语言商品同款识别及历史数据修复仍须继续完成，不能以本项签收每日百品或整体重制。
