# 独立成员竞品监控页面退役

依据本次用户要求，成员功能围绕情报、商品、竞品对比、评分、1688 和选品库精简。独立的手工竞品监控和告警规则管理不再作为用户主流程；后台、账号、组织、采集来源、采集管理与运维继续保留。

## 当前运行行为

删除 CompetitorMonitor.vue、competitor.css、专用 competitor-review-tokens.css 及两个旧预览 CSS 注入模块，运行组件注册表和 Shell props 不再引用该页面。/competitors 与 /competitors/monitoring-rules 作为固定兼容别名打开 /opportunities，不挂载旧组件、不请求旧监控页面数据、不发写操作。别名与终点使用同一选品读取能力，旧有 competitor:read 不能绕过目标权限。

固定退役别名跳转统一清除旧 query/hash，避免 create=1 等跨页面含义触发新表单；/reports 同样适用。目标仍为目录中已校验的同 Shell 静态地址，外站、动态和链式跳转仍拒绝。

选品详情保留 SelectionProductComparison，主品及 5–10 个独立竞品、真实快照、公开评价、来源状态和缺失字段继续展示。概览“查看竞品对比”只在现有 competitor:read 能力下切换本详情 competition 标签，不进入另一工作台；采集操作仍按 competitor:manage 判断，后端权限不变。竞品准备度只检查既有竞争评分维度，不再读取或要求旧价格告警规则；配置准备度不代表真实竞品数据已齐，实际质量门仍要求至少 5 个独立详情快照。

后端 /api/v1/competitors、发现/详情投影、采集、变更 Worker 与历史记录因核心链路仍使用而保留；不改变 API 字段、权限或数据库，不删除持久化数据，不停后台任务。其他未精简成员模块仍按总目标继续清理。本项不代表全站重制完成。

## 发布与使用

用户从选品详情查看竞品对比。旧书签自动进入选品库，缺少选品读取权限则显示真实无权状态。没有新配置、依赖、API 字段、Python 或插件载荷变化。

本地 Web 构建后通过固定 python scripts/deploy-baota.py 发布静态文件和路由目录，浏览器刷新加载；本项无后端执行代码变化，不要求额外 Node/Python 重启。整批发布若包含前序 API/Worker 改动，仍按对应发布要求由宝塔重启唯一 Node 项目。本轮未部署。
