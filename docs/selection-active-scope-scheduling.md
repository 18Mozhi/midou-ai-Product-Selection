# 采集调度遵守组织与工作区归档状态

## 实际问题和修复

2026-10-18生产只读核查：9月2日已归档的历史验收组织仍有220条活动采集任务，最近在当天13:19继续被领取并成功执行。原调度只在初始化来源计划时筛选活动组织，已有计划、规则和领取链未重复筛选；全局积压也包含这220条。13:36只读快照总积压1385，活动有效范围1165，归档范围220。排除归档任务不会单独消除其余积压，也不能证明每日100品完成。

共用activeCollectionScopeSql要求组织存在且active、工作区存在且active，并属于任务的同一组织。scheduled/retry到queued以及queued到leased都在候选选择和主键复核检查；指定任务验证不例外。归档、缺失或错误所属范围不再领取、不消耗新次数，不更改其任务、结果和历史，也不删除组织或测试资料。已经执行中的任务按原租约收尾，不中途强杀。合法恢复active状态后自然参与原队列，无新恢复接口。

全量来源计划、规则的候选和到期数使用同样条件；全局积压、租户预算、来源恢复补采与竞品发现/刷新容量统计只计活动有效范围。排除归档不是排除来源暂时停用：有效组织中等待来源恢复的任务仍占用既有预算，原单机租约、FIFO轮次、来源熔断、重试与优先级保持。

## 使用、验证和发布

无需新增配置；AUTOMATIC_SOURCE_QUEUE_BACKLOG_LIMIT仍默认1000，可在现有宝塔受限环境中调整，统计口径改为活动有效范围。没有新增API字段、事件、数据库结构或依赖；前端请求、Python输入和既有组织管理归档API不变，OpenAPI补充任务调度说明，环境示例只更新已有参数注释。

定向验证覆盖入队与领取前归档、选中后归档、原排序/锁/次数、计划和规则到期数、来源补采容量；生产MySQL5.7只读派生场景验证活动、组织归档、工作区归档、外组织工作区及缺失组织/工作区六种情况，不创建表或记录。真实220条归档任务在新条件下可领取数为0。82项相关回归通过；竞品刷新及发现两条实际生成SQL在生产MySQL5.7执行只读EXPLAIN通过，新增范围关联均使用PRIMARY的eq_ref。模拟测试不替代上线后的真实执行证据。

正式发布复用本地deploy-baota.py全包构建上传，由宝塔重启托管Node/Worker；不手工启动新服务。上线后检查部署版本、Worker活性、归档范围新领取数、容量统计及真实业务队列，另行保持每日100完整流程验收。
