# 分类器修复后的自动评估恢复

## 问题与范围

2026-10-19T18:05:29Z，只读核对当前工作区仍有10条待处理选品停在waiting_evidence，结果明确记录supply_title_classification_failed。原入队只有新选品和新证据/规则唤醒，部署分类器修复不会自动恢复这些旧失败；此前首个整链商品通过原函数单条唤醒已验证实际结果。自动运行不应依赖逐条人工处理。

只有已配置供应分类器时启用恢复。候选必须为waiting_evidence、明确的上述失败、当前分类器修订尚未尝试，同时属于活动且匹配的组织/工作区、待决策未归档选品，并继续通过原Amazon主品证据资格。无分类器、当前修订、正常等待资料、超时/限流、已领取、排队中、成功、死信或终态记录均不恢复。

先普通SELECT读取最多100个候选，再按选品主键、组织和工作区逐条原子UPDATE，重新检查全部资格。只将原评估置queued，重置该次分析尝试计数，保留原结果中的失败信息供读取，清除队列顶层旧错误并写入已尝试修订；不改租约、不抢占执行中分析，不创建商品或采集任务，不修改证据、采购价、评分和完成事件。Worker仍按原资源调度、租约、重试和质量门执行分析。

## 修订与内部格式

代码固定修订为SUPPLY_TITLE_CLASSIFIER_REVISION=supply-title-disjoint-v1。内部automatic_selection_evaluations.result_json新增supply_title_classifier_revision，记录执行或恢复使用的分类器修订；原JSON字段及格式保留，没有新增表或迁移。完成任何配置了分类器的评估时写入此标记，错误仍为原公开口径。首次恢复即标记版本，同版本再次失败也不会每轮恢复或无限调用模型。今后真正更改分类器逻辑/提示时由代码发布显式更新此常量，不能按时间或启动随机变化。

API当前只投影结果中既有错误/进度字段，不透传结果JSON；前端、OpenAPI和Python合同无需新增字段。原利润未知、低分或不推荐可计入整链的口径不变。没有新环境变量、配置开关、轮询周期、超时、依赖、权限或运行服务。恢复复用现有自动评估轮询；通过固定deploy-baota.py发布并宝塔重启Node加载，无用户调节项。
