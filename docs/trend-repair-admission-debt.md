# 背压空领取保留历史修复轮次

现有热点投影每累计20次领取给历史下游修复一个优先轮次，但领取为空时会清零；达到20后，即使下游因满容量没有做任何工作，也会清零。在持续的容量波动中，修复计数无法累计，分页再发现可能一直等不到先于新热点的轮次。原编译Worker的无数据库/模型写入诊断复现：19和20两种起始计数，在空领取且修复无进展后都变0。

保留原20次界限，不调整采集优先级、工作区轮转、容量、模型、来源或质量规则。空领取只在下游修复确实提交了工作时清零；无工作/容量不足时保留累计数。到期修复先于下一次新热点领取，若没有进展仍保留到期状态，同时允许新热点继续尝试。修复抛出异常仍保留原失败让步行为：先清零再抛出，下一轮可处理新热点，避免异常修复永久挡住新工作。

内部enqueueMissingAutomaticDownstream现在返回boolean：找货熔断恢复实际重排、独立主品补建、详情/找货任务创建或周期发现/刷新真正提交才为true；没有来源、无合格项、只有扫描游标推进或容量等待均false。事务失败仍抛出异常，不报告成功。只有两个现有Worker内部调用消费返回值，没有新API字段、持久化格式、环境变量、配置、依赖或Python输入；env.example/OpenAPI和浏览器无需变更。
