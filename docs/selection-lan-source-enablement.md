# 1688 LAN 来源启用与调度边界

## 修正

原配置更新与回滚在启用 1688 时强制查询 Cookie 资产、浏览器档案、成功登录运行和旧 DOM 样本回放。这些条件与用户提供的六台局域网图片服务无关，会阻断已接入的图片找货。

现在 API 启动时只把既有服务端 `LAN_1688_TOKEN` 是否配置的布尔值传入来源版本仓库，不传递或返回密钥。启用与回滚到启用状态要求已配置授权；未配置返回既有 `provider_source_setup_required` 与配置提示。停用不依赖授权。原权限、同源、幂等、版本冲突、配置历史和审计流程保留，其他公开来源的条款及实测门不变。

配置检查没有联网，不证明设备在线或授权有效；实际请求仍由 Worker 按六台固定地址调用，保留超时、鉴权失败、解析失败、来源停用和熔断等真实状态。不得把“已启用”写成“采集验收通过”。

普通找货任务必须带主品 `image_url`。缺图以现有 `parse_failed` 失败，不再静默转入网页登录。关键词情报调度排除 `1688_search`，避免自动派发无法运行的无图任务；Amazon 主品投影后的图片找货继续走原补偿链。历史无图任务不删除、不伪造图片。

显式 `acceptance_run` 浏览器诊断保留，用于已有后台历史排查；其状态与固定样本不成为 LAN 启用证明。来源目录改为“局域网图片找货”，隐藏 1688 的网页登录配置入口，保留标为历史的浏览器样本与检查入口。数据库旧 `access_mode` 和历史记录保持兼容，不进行迁移。

## 使用与运行

1. 在宝塔受限 `product_scout.env` 配置既有 `LAN_1688_TOKEN`，沿用 `LAN_1688_TIMEOUT_MS`；不得将授权写进浏览器、文档或仓库。
2. 本地构建 API/Worker/Backend/Web，通过固定部署脚本上传。由宝塔重启唯一 Node 项目：`/www/server/panel/pyenv/bin/python /www/server/panel/script/restart_project.py nodejs ai选品`。API 与 Worker 同时加载配置；Python 不因本项重启。
3. 管理员在来源设置启用 1688，按现有版本与理由保存。检查真实图片任务、设备结果、JSON 证据和货源投影；如已有熔断，沿用受审计的来源恢复操作，本项不自动清除熔断或宣称健康。

无新依赖、环境变量、请求/响应字段或数据库结构。当前未部署，生产启用、队列调用和持续运行尚未验收。
