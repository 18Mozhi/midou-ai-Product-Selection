# 已审批公开RSS的临时故障自动恢复

## 问题与行为

2026-10-18实测Ars Technica内部审批仍有效，但累计网络错误后一直熔断，需要人工健康检查与恢复。这不满足连续自动运行。旧RSS健康检查只读取正文，还可能在robots禁止时误报ready；新增回归在修复前重现该错误。

现由已有Node API进程每轮最多检查一个已登记的自动RSS，不增加进程或生产服务。仅处理enabled、approved、版本非空且永久/未过期的syndication-feed-v1及google-trends-rss-v1来源，运行熔断错误必须为network_error、timeout或rate_limited。来源和上次检查均经过冷却；熔断后的blocked健康结果停止自动重试，待管理员修复。Amazon、1688、登录档案、自定义来源、未审批来源和永久权限/解析错误不自动恢复。

真实健康检查先验证固定目标地址，再检查当前robots并解析真实RSS。RSS适配器版本升至syndication-feed-adapter-v2及google-trends-rss-adapter-v2；标准化解析器字段版本不变。仅ready才能尝试既有审计恢复事务。事务锁住来源和熔断记录后，用同一主键FOR UPDATE当前读（避免MySQL5.7重复读快照读取过期审批）重新确认来源版本、有效审批、同一次熔断及临时错误，并要求健康检查晚于熔断；期间改配置、撤审批、发生新熔断或权限拒绝，均不恢复。

使用现有AUTOMATIC_SOURCE_SYSTEM_ACTOR_ID，且用户必须active；不创建账号、权限或凭证。后台不自动批准来源，不伪造健康、商品、评分或完成事件。关闭API时先停止定时器并等待有界检查完成，再关闭连接池；单进程最多一个探针在途。仅状态或来源变化时写一条结构化运行日志，首次idle可用于确认实际定时器已运行，不逐轮重复刷日志。所有来源仍遵守原采集频率、并发、租约、机器人规则和队列预算。

## 宝塔配置

| 环境项 | 默认值 | 调节范围与作用 |
| --- | --- | --- |
| PUBLIC_RSS_AUTO_RECOVERY_ENABLED | true | 仅production API启动；false关闭自动恢复，保留人工流程 |
| PUBLIC_RSS_AUTO_RECOVERY_POLL_MS | 60000 | 1000–3600000，每轮最多一个来源 |
| PUBLIC_RSS_AUTO_RECOVERY_COOLDOWN_MS | 300000 | 1000–86400000，熔断及上次检查的最短等待时间 |

配置位于既有宝塔受限product_scout.env；默认值即可运行，不需要填写新密钥。现有PROVIDER_ADAPTER_HEALTH_TIMEOUT_MS与来源timeout_ms继续限制网络检查。三项均只在后端读取，不下发浏览器。修改后需由宝塔重启Node项目ai选品；固定发布脚本执行该步骤，Python没有新配置。停用或回滚时设enabled=false并由宝塔重启Node；历史审计、健康版本和任务保持不变。

管理员继续在“采集程序”查看健康版本，在“采集调度”查看恢复时间与实际任务。自动检查使用public-rss-recovery前缀的操作幂等键，并沿既有健康版本、调度操作及平台审计留痕。未新增HTTP路由、公开字段、数据库迁移或依赖。

## 验证边界

定向检查覆盖robots拒绝/允许、网络错误、目标错配、冷却参数、无来源、开关、单探针互斥、关闭等待、健康受阻不恢复，以及事务中的审批/配置/熔断竞态。实际MySQL5.7只读夹具验证候选查询，不写生产业务数据。正式发布后需检查版本、运行健康及正常任务推进；没有自然故障时不主动破坏来源来伪造生产恢复验收。每日100个完整商品和全部UI重制仍独立验收。


手动重启仅使用宝塔入口，命令为 `/www/server/panel/pyenv/bin/python /www/server/panel/script/restart_project.py nodejs ai选品`。本次没有新增Python配置；正式部署仍由既有脚本处理运行包与托管进程。

扩大验证另发现旧Worker入口恰好400个非空行，触发现有小于400行门禁，该失败在改动前发布工作树同样存在。队列注册改为已有策略工厂的声明式批量入口，降为396行；19个队列的名称、间隔表达式和处理器实参逐词元核对完全相同，保留所有资源、开关、日志、重试与优先级策略，没有放宽测试门槛。

API来源运行对象的装配放入bootstrap/create-provider-adapter-runtime.ts，保留同一个服务实例、现有Amazon真实健康闭包及原关闭顺序，满足启动入口少于600行的原门禁。没有移动HTTP权限检查或改变公开契约。

全量单元验证还暴露旧UI证据的过期绑定：两个已删除旧选择器的共享样式更新当前精确指纹；P16未登记版本的历史源改为读取与原清单SHA完全匹配的Git字节；P37历史快照补入当时Vite配置；P38机器清单与其后文档的六行位置变化分别绑定各自原始输入；P65只读发布控件的当前指纹重新核对。原截图、原清单哈希、审批状态及未知版本拒绝均保留。这些是历史校验与新版源码的边界修复，不恢复旧样式，也不把历史截图签收为新版UI。
