# Amazon 搜索观测与商品详情

2026-10-18 07:15 生产只读核对发现，ASIN B0F7Z4QZTT 的实际详情在 22:06:32 UTC 采得 69.99 报价，23:10:11 UTC 的搜索观测却以同一 record_key 把该详情标记 superseded，活跃价格为 NULL。这不是原始报价消失，也不能把搜索页的缺失解释为商品降价或不可售。

## 写入与版本

Amazon 外部商品 ID 和 payload.asin 不变。只有实际 Amazon 商品 page_url 与 ASIN 一致的采集使用 amazon:detail:ASIN 记录键；无商品 page_url 的搜索观测使用 amazon:search:taskId:ASIN。调用方的 projection_type 不能伪装详情。其他来源及非 ASIN 外部 ID 保留原键。

同一商品的详情按原不可变版本机制更新；搜索任务之间、搜索与详情之间不再相互 supersede。Amazon 原始内容去重摘要同时带入观测键，防止相同重试字节命中旧未分型证据的唯一键；相同观测与字节仍幂等。其他来源去重规则不变，旧记录键、版本和历史不回填、不删除。record_key 是内部观测身份；没有数据库字段或迁移变化。

## 读取与后续流程

API、评分、货源分类及竞品分类共同使用 selectPrimaryObservation：较新的搜索确实具有非负数值价格和规范币种时仍选该真实更新，真实零值也不伪装成缺失；搜索缺报价则不能覆盖最新的真实详情。详情必须通过已有 competitor_snapshot 任务、商品 URL、任务证据关联、组织、工作区、ASIN 与原始证据一致性证明；active 与 superseded 的不可变详情可读，quarantined 不可读。返回选中观测自身的 raw_evidence_id、captured_at 和字段，不能用新搜索时间给旧详情背书，也不能用其他观测补齐选中记录的空值。较新的详情即使缺价格也不会回退至较早报价。评分仍执行既有正售价等门槛，不因此把零值当作可推荐商品。

竞品完整性及评分查询按采集时间选择最新的经证明详情，而非直接相信可被搜索覆盖的 latest_snapshot_id。即使最新详情缺价格，也不会退回到更早的有价详情。搜索投影仍保存原搜索快照、继续生成详情任务；已有经证明详情指针时，通过同竞争品主键范围锁保留指针，不让搜索快照覆盖。详情仍由原比较作业更新指针和变化记录。

旧手动快照和其他后台操作不被重写；自动整链只认原有真实详情证明。评分门、5–10 个独立相关竞品、未知利润的验收口径、来源健康、熔断、权限、重试及并发均不改变。

## 验证与运行

amazon-observation-lineage 测试覆盖观测键隔离、任务隔离、真实 URL/ASIN 校验、原报价与时间保留、缺失字段不拼接、搜索不覆盖详情以及原详情比较队列。主品 API、分类、评分、核心采集和相关性测试一并回归；生产 MySQL 5.7 使用绑定 Date 和 3 秒只读上限复核。

API 响应字段不变，仅 OpenAPI 补充事实选择含义，前端无需新字段。没有环境变量、依赖、Python 或外部接口变化。正式运行包发布后由宝塔重启唯一 Node 项目 ai选品，同时加载 API、Worker 与共享查询；用户无需调整配置。存在的访问拒绝和未公开字段继续显示缺失，不代表日百品已通过。
