# 首页统计查询的必要条件预检

## 实现边界

首页摘要和推荐清单使用新的 home-selection-sql。候选存在性直接复用原主品证据 FROM/WHERE，不再为了判断存在而排序；真正选择主 ASIN 的 SQL、顺序、状态和租户条件保持不变。其他列表、Worker、评分和完成事件继续使用原合同。

推荐门前增加只读竞品数量上界：同组织、工作区、机会的有效 Amazon 竞品，至少有一条价格、币种、评价数、星级均非空且新鲜健康的快照。按大写 ASIN 去重。历史快照可能高估上界，因此达到最小数量后仍必须执行原完整质量门，包括最新真实详情、主品身份、竞品相关性和评分／利润／风险事实。上界不足才可直接排除，不能用上界代替证据。

## 当前证据与限制

生产只读诊断中，29 个满足表面推荐字段的旧机会各只有 1 个可能具备详情的竞品。原摘要第一项统计超过 3000ms 诊断上限；使用相同预检的 SQL 约 1.2–1.3 秒返回。此时间仅是该次数据快照的测量，不是 SLA。

6 个 MySQL 5.7 只读派生表用例验证四／五个独立品、重复快照、跨租户快照、缺价格及已删除竞品。零评价和零星级仍按原 IS NOT NULL 合同参与上界，不新设阈值。

**首页整体尚未修复验收。** 后续 dailySelectionProductionSql 的历史主品去重仍超过 3000ms，只读诊断确认今日主品提取约 103ms，而历史主品提取单独超时。当前修改不替换该查询、不改每日发现数／合格数／首次整链完成数，也不把超时写成零。完整首页渲染和每日100品仍待验收。

## 运行与验证

无新增依赖、环境变量、API字段、权限或数据库迁移；OpenAPI、Python输入及环境示例无变化。配置仍沿用既有最少竞品常量，不新增用户调节项。部署后需要由既有宝塔发布脚本重启 Node 加载新后端；本地提交本身不会修改生产。

定向检查：build:database、build:api，然后运行 tests/unit/home-selection-query.test.mjs、home-daily-selection.test.mjs 和 tests/m02-06 下的首页合同测试。正式发布后必须独立验证首页接口总时长、真实指标和页面加载，不能用单项统计提速替代整页验收。
