# 首页统计查询的必要条件预检

## 实现边界

首页摘要和推荐清单使用新的 home-selection-sql。候选存在性直接复用原主品证据 FROM/WHERE，不再为了判断存在而排序；真正选择主 ASIN 的 SQL、顺序、状态和租户条件保持不变。其他列表、Worker、评分和完成事件继续使用原合同。

推荐门前增加只读竞品数量上界：同组织、工作区、机会的有效 Amazon 竞品，至少有一条价格、币种、评价数、星级均非空且新鲜健康的快照。按大写 ASIN 去重。历史快照可能高估上界，因此达到最小数量后仍必须执行原完整质量门，包括最新真实详情、主品身份、竞品相关性和评分／利润／风险事实。上界不足才可直接排除，不能用上界代替证据。

## 当前证据与限制

生产只读诊断中，29 个满足表面推荐字段的旧机会各只有 1 个可能具备详情的竞品。原摘要第一项统计超过 3000ms 诊断上限；使用相同预检的 SQL 约 1.2–1.3 秒返回。此时间仅是该次数据快照的测量，不是 SLA。

6 个 MySQL 5.7 只读派生表用例验证四／五个独立品、重复快照、跨租户快照、缺价格及已删除竞品。零评价和零星级仍按原 IS NOT NULL 合同参与上界，不新设阈值。

## 历史主品读取修复

后续定位确认旧历史身份查询在重复版本证据上逐个排序，直接阻塞每日统计。现在 dailySelectionProductionSql 读取按机会分组的主品身份集合：先从当前有效记录的既有作用域状态索引出发，再按既有版本索引关联种子记录、证据链接和机会。每日与历史采用原有绑定的组织、工作区和半开时间窗口；每日排除已归档／删除，历史仍包含它们以防重新发现旧品。

所有身份谓词复用同一组 SQL 片段。旧 scalar identity、candidate 和存在性三个导出字符串经与前一提交比较保持逐字节相同；Worker、机会详情和完成事件的身份路径不变。集合查询用原排序（链接创建时间升序、标准化创建时间降序）的第一个十字符 ASIN。GROUP BY 防止历史派生表被合并后针对每个当天品重复计算。若当前会话 group_concat_max_len 小于10，退回原标量身份 SQL，避免截断身份；不写任何会话、全局配置或数据库数据，不新增索引。

生产只读一致性快照内，136 个历史主品逐一与旧标量查询比较，全部一致，覆盖133个独立 ASIN。12组 MySQL 5.7 派生表用例共48次读取覆盖旧链接优先、同链接新版本优先、隔离记录、无有效当前版本、ASIN变化、非法原文地址、跨租户／工作区、非Amazon来源、归档历史、时间边界及重复有效版本；每组同时验证快速路径、强制回退和每日窗口。

完整 automaticSelection 只读诊断约2726ms，四条查询约1240／2／1480／2ms，返回发现11、合格0、整链完成0。数据会继续变化，此测量不是 SLA，也不能替代真实 HTTP 和首页渲染验收。**每日100个完整链路目标仍未达标。**

## 运行与验证

无新增依赖、环境变量、API字段、权限或数据库迁移；OpenAPI、Python输入及环境示例无变化。配置仍沿用既有最少竞品常量，不新增用户调节项。部署后需要由既有宝塔发布脚本重启 Node 加载新后端；本地提交本身不会修改生产。正式发布版本与线上检查以对应发布收据为准。

定向检查：build:database、build:api，然后运行 tests/unit/home-selection-query.test.mjs、home-daily-selection.test.mjs 和 tests/m02-06 下的首页合同测试。tests/m02-06/home-primary-identities.fixture.mjs 导出只读 MySQL 用例运行器，由验证器传入编译后的实际 SQL，不创建表或写入数据。正式发布后必须独立验证首页接口总时长、真实指标和页面加载，不能用单项统计提速替代整页验收。
