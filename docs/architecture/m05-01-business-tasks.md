# M05-01 业务任务中心架构

业务任务使用 `tasks`、不可变 `task_comments`、`task_events` 与幂等 `task_operations`，所有查询和写入同时约束 organization_id/workspace_id。状态只含 todo、in_progress、paused、completed、cancelled；SLA 是由真实 due_at 派生的 on_track、due_soon、overdue 或 not_set，不补造期限。写事务同时写 `audit_logs` 与 `outbox_events`，请求保持 request_id/trace_id。

M04-06 的 `sourcing.purchase_task.queued` 由宝塔 Node Worker 以租约投影为 `sourcing_purchase` 任务，唯一来源约束保证重放不重复；MySQL 5.7 中采购 ID 的 `ascii` 字符集在生成中文标题和说明前显式转换为 `utf8mb4`。投影成功后仅使用 `sourcing_outbox` 已存在的状态与租约字段完成确认并释放租约，不依赖表中不存在的发布时间字段。浏览器只调用 API；读取 `task:read`，创建 `task:create`，更新/评论 `task:update`，转交 `task:assign`。M05-02 审批、M05-03 通知 Outbox 消费和 M05-04 SSE 不在本模块实现。

任务列表使用 `/tasks`，任务详情使用可直接分享和恢复的 `/tasks/{taskId}` 独立前端路由；详情消费 `GET /api/v1/tasks/{taskId}`，不预读被详情路由隐藏的任务列表与汇总。列表状态、搜索、排序与分页分别同步到 `status`、`query`、`sort`、`page` 查询参数，并由 MySQL 在组织和工作区范围内先筛选、排序再分页；`paused` 与 `cancelled` 都是可直接过滤的真实状态。详情链接只接受 `/work` 或 `/tasks` 列表及其查询参数作为 `from`，嵌套详情或其他路径回退到 `/tasks`。详情为加载、任务不存在、无权限、会话失效、限流和依赖失败提供可见且可重试的独立状态。列表行和详情内的删除入口都收进命名操作菜单，避免与打开/运行任务的主操作竞争；进度主表达使用待开始、执行中、已暂停、已完成或已结束阶段，百分比用辅助进度条表达。SLA 同时展示期限、等级和下一步，事件与评论按真实时间合并为带中文动作和操作者标签的任务活动；评论内容由不可变 `task_comments` 展示，对应的 `task.comment.created` 技术事件继续保留在后端审计但不重复渲染。审批只有进入任务事实后才会出现在该活动流，不额外拼造审批记录。

任务转交、延期、暂停、取消和进度更新统一使用结构化可审计表单，不再要求操作者输入账号编号或 ISO 字符串。`GET /api/v1/tasks/member-options` 只返回当前组织中活动、且拥有组织级或当前工作区数据范围的活动账号；后端执行转交时仍再次执行相同范围校验。延期使用本地日期时间控件并由前端提交 ISO 8601，进度表单分别提交整数百分比和进展说明；`task.progress` 的不可变事件、审计和 Outbox payload 同步保存当次 `progress_note`，不从任务当前值反推历史。详情更新、评论、动作和删除先锁定当前组织/工作区内的任务行，再在同一事务连接上复用已有幂等结果，因此相同幂等键的并发请求返回同一结果而不是版本冲突；不同幂等键仍通过版本号实施乐观锁。

列表批量操作复用单任务动作接口，支持暂停、继续、取消、延期与负责人调整。页面先固定选择范围并展示可执行与跳过数量，再逐项使用各自版本号、独立幂等键和独立审计执行；批量延期共用显式新截止时间，批量负责人调整只能选择当前工作区成员。任务详情固定展示“阻塞原因 / 下一负责人”：阻塞原因仅在 paused 状态读取最近一次持久化 `task.pause` 事件的 reason，非 paused 明示未阻塞；下一负责人使用当前 `assignee_id` 对应的成员目录标签，目录不可用时不猜测姓名。

前端按职责拆分：`TaskWorkspace.vue` 继续拥有路由、API、版本锁与动作编排；`TaskListPanel.vue` 只渲染筛选、选择和列表；`TaskBatchActions.vue` 只承载批量操作入口、影响预览与受控输入；`TaskDetailPanel.vue` 只承载任务事实、动作表单和活动流。子组件通过 typed props/emits 交互，不复制请求逻辑，也不改变任何任务状态或接口字段。

导航守卫返回的能力事实同时传给任务页面：`task:create` 控制新建，`task:update` 控制选择、批量以及详情的状态、编辑、进度、评论与删除，`task:assign` 单独控制负责人调整，`report:read` 控制导出任务视图。只读角色仍可查看范围内任务，但不会看到会被 API 拒绝的写入口；API 授权继续作为最终安全边界。创建、批量和每一种详情写请求在进行中锁定提交，详情刷新完成前不会再次发送相同操作；批量动作逐项保留幂等键与版本锁，并明确汇总成功、失败和跳过数量，不把部分成功误报为全量成功。
