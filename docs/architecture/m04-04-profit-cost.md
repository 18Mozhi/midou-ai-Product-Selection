# M04-04 利润与成本架构

## 合同与边界

费用规则由组织与工作区隔离，并进一步按市场、平台和版本区分。四类费用必须显式提交；系统不保存默认费率，也不把缺失值按零处理。规则需 `selection_manager` 与 `organization_admin` 两类真实角色分别审批，发布与回滚只改变后续任务选用的活动版本。

成本输入保存金额、币种、来源类型、来源标识、证据 ID、观测时间和版本。跨币种计算只使用状态为 `enabled` 且字段声明包含 `exchange_rate` 的 Provider 历史报价。汇率按计算日期选择不晚于当日的最近一条，报价 ID 写入分项快照。

## 数据流

1. Node API 在同源、权限、幂等和版本锁后写入规则、汇率或成本输入。
2. 发布规则、确认成本或人工重算会创建 `opportunity_profit_jobs`。
3. 宝塔 Node Worker 租约领取任务，固定计算：含税售价 − 采购 − 物流 − 平台费 − 支付手续费 − 税费 − 履约成本。
4. 缺少任一输入或汇率时保存 `insufficient_data` 运行和逐项缺失原因，不生成数值 ROI。
5. 输入齐全时，例如 100 USD 售价、40 CNY 采购按 0.14、5 USD 物流、10% 平台费、3% 支付费、5% 税费和 2 USD 履约成本，总成本为 30.6 USD，净利润和净利率均为 69.4。

## 持久化与恢复

MySQL 5.7 是规则、审批、历史汇率、输入、任务、运行和分项真相源，字符集为 `utf8mb4`。Worker 使用 1/5/15 分钟退避、租约恢复、终态失败与死信；审计事件和 Outbox 与业务事务一起提交。Redis 不保存利润事实。

页面只读取 `/profit-analysis` 返回的最后一次不可变运行，不在浏览器重复计算。M04-04 不实现 M04-05 竞品快照或 M04-06 供应商搜索与报价比较。

机会页面保留数据加载、写入和标签切换编排，利润摘要、缺失项、成本分项与成本输入由 `OpportunityProfitPanel.vue` 独立渲染。该拆分复用原对象和事件，不增加浏览器计算，也不改变利润 API 或输入合同。费用规则页直接消费全局 `--so-*` 语义令牌，不再通过独立主题补丁覆盖硬编码浅色样式。
