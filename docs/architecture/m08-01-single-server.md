# M08-01 S0 单机运行基线

## 范围

ScoutOps 长期只运行在当前惠州单台服务器上，所有生产对象继续由宝塔管理。M08-01 提供当前 Node API 的稳定身份、API 与 Worker 分层健康、统一 Worker 队列调度、受 `platform:operate` 保护的审计运维视图，以及宝塔单上游 Nginx 的生产证据门。

本模块不启用负载均衡、不创建备用服务器、不把同机候选发布槽当成第二节点，也不声明多节点、高可用或 10,000 用户能力。`capacity_claim` 固定为 `unverified`。

## 运行合同

1. 宝塔 Node API 使用稳定的 `RUNTIME_NODE_ID` 和 `RUNTIME_HOST_ID`，启动后写入 `runtime_nodes` 与追加心跳。
2. 健康判定只接受配置中的当前节点和当前主机；历史节点、同机候选槽或不同主机身份不能替代它。
3. 心跳过期、节点停止、身份不匹配或没有记录时，`GET /api/v1/health/nodes` 返回 503；ready 时返回 200。
4. 公开健康接口只返回状态和计数，不返回节点、主机、构建或内部端口。
5. `GET /api/v1/platform/operations/topology` 要求 `platform:operate`，读取同步写入 `runtime_topology_views` 和平台审计。
6. API、Worker、Crawler、MySQL、Redis 与文件目录保持本机私有；公网只通过宝塔网站 Nginx 进入。
7. `/health/live`、`/health/ready`、`/health/available` 分别表示进程存活、同步依赖就绪、后台业务可处理；三者不得相互替代。
8. Worker 的所有处理器通过单一声明式注册表进入同一个调度器；每类队列独立声明并发、超时、重试、连续失败熔断、优先级老化和卡死阈值，同时受全局并发配额约束。停机向活动处理器传递取消信号，低优先级队列会随等待时间提高有效优先级。运行快照同时保留基础优先级、有效优先级、老化间隔、最大老化增益和实际调度延迟；页面以二者之差显示已获得的老化保护，仅当队列达到自身最大老化增益后仍在等待时标记饥饿风险，不设置另一套猜测阈值。
9. 调度器将等待数、运行时长、疑似卡死数、熔断、超时、重试、一分钟失败率和队列摘要原子写入受限运行目录。快照写入失败只增加观测告警，不得把已成功任务改记为失败。
10. Worker 调度心跳过期或停止时业务可用性失败关闭；连续重启、背压、卡死、队列熔断、快照异常和最近失败统一进入运行告警，但不会把任务载荷、Cookie、Token 或原始错误对象写入状态文件。
11. 授权运维读取会把监督器提供的 API/Worker 状态与累计重启数写入五分钟观测桶；页面读取最近 24 小时最多 600 条观测并计算非负增量。监督器重启导致累计数回落时记录 `counter_reset`，不会伪造负重启或把当前 PID 当成长期进程身份。
12. Worker 轮询结果只按队列白名单提取状态、稳定错误码和最多四个业务对象标识；调度快照拒绝未知对象类型、超长值、外部地址和原始结果载荷。背压、最近失败、卡死与熔断告警关联实际命中的队列；最近一分钟内带稳定错误码的业务失败结果额外关联精确业务对象。采集任务、业务任务和机会使用既有详情路由，没有精确对象或稳定详情入口时保持空链接，不按队列类型猜测具体对象。
13. 现有宝塔 Node API 在监听成功并写入首次运行心跳后，按配置周期并发探测固定的本机 `live`、`ready`、`available` 三个 HTTP 端点。每轮最多三个请求且上一轮未结束时不重入；超时由 `AbortController` 中止客户端请求。样本只保存端点枚举、结果枚举、HTTP 状态码、毫秒耗时、correlation 和观测时间，不读取或保存响应正文。
14. 运维视图读取配置窗口内的样本，按端点计算样本数、成功数、HTTP 异常数、超时数、网络错误数、可用率与 P50/P95/P99/最大耗时。样本按配置保留期由探测写事务分批清理；汇总读取失败只把连续探测标为不可用，不覆盖节点心跳、进程和队列事实。进程内探测无法在事件循环完全停止后继续写样本，因此整进程失联仍以节点心跳过期为权威判断。

## 数据与兼容

`0030_load_balancing_m08_01.up.sql` 已在生产 MySQL 5.7 执行，文件名和校验和作为历史事实保持不变。运行节点、心跳和读取审计表继续使用；其中 `load_balancer_observations` 为停用兼容表，单机运行代码不再读取或写入它。`0062_runtime_process_restart_observations.up.sql` 只新增脱敏的进程名、状态、累计重启计数、五分钟桶和 correlation，不保存 PID、命令、路径或原始失败文本。`0063_runtime_health_endpoint_probes.up.sql` 新增固定端点枚举的有界健康样本，不保存 URL、响应正文、主机、凭证或业务载荷。不得为了改名重写已执行迁移。

## 失败和回滚

- Node API 心跳停止：健康门变为 stale/503，在宝塔检查项目和日志后恢复。
- 连续探测超时或网络失败：在运行拓扑按端点核对超时量和 P95/P99；先检查对应健康接口及同步依赖。连续探测本身不可用但节点心跳仍新鲜时，核对 `0063` 迁移、业务账号表权限和 API 日志，不得把空样本解释为健康。
- Worker 调度心跳过期：`/health/available` 返回 503；在宝塔检查统一 Node 后端和 `/www/wwwroot/ai选品/runtime/worker-scheduler.json`，不得另起 Worker 绕过并发门。
- 队列背压：先按优先级下钻失败队列和依赖；只有确认 CPU、内存、磁盘及站点配额允许后才调整 `WORKER_MAX_CONCURRENCY`。
- 队列饥饿风险：按有效优先级从高到低核对实际调度延迟；达到最大老化增益仍未运行表示现有老化保护已经用尽，先检查高优先级持续占用、全局并发和依赖阻塞，不得手工修改状态文件或任务优先级。
- 队列熔断或疑似卡死：在运行拓扑查看队列运行时长、连续失败和超时计数，先修复依赖与租约，再由宝塔重启统一后端；不得手工改状态文件或启动旁路 Worker。
- 业务结果失败：先从运行告警打开允许列表中的关联业务对象，再核对技术详情中的稳定错误码和发生时间。告警没有对象时只能按关联队列继续查日志，不得把上一次处理对象解释为当前故障对象。
- 子进程重启趋势上升：核对新增重启数与最近失败；出现“计数器重置”表示监督器本身重新启动，需要同时检查宝塔 Node 项目日志，不能把计数回落理解为故障已消失。
- 主机身份错误：健康门变为 blocked，修复宝塔受限环境中的稳定 ID 后重启 Node API。
- Nginx/TLS 失败：生产证据不得签发；只通过宝塔修复网站配置。
- 应用回滚：在宝塔切回已验证版本并保留心跳、审计和证据记录；数据库 down 迁移仅在确认没有下游依赖且完成备份后执行。

## 明确限制

单机运行门通过只证明当前服务器和当前 API 可用，不保护整机、磁盘、网络或机房故障。停机恢复依赖宝塔重启和现有同机加密恢复能力。
