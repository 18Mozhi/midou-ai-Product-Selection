# M00-07 验收框架范围

## 目标

提供真实执行的 `verify:module`、`verify:phase`、`verify:all`。模块注册表必须登记 A01–A17 的证据与命令；阶段从计划文件读取模块顺序；全量固定从 P00 执行到 P08。成功模块和阶段原子写入状态并由下游复用；任一失败、超时、缺失注册表或前置未完成都会返回非零退出码。

## 非目标

- 不把人工勾选、计划文本或失败报告当作通过结果；只复用由成功执行器写入的状态。
- 不开放浏览器或运行时 API 来触发任意命令；只有本地/CI/宝塔受控发布任务可执行。
- 不在报告中记录密码、Cookie、Token、API Key 或私钥，不绕过未完成阶段。

## 对象与状态

- `ModuleRegistry`：模块、阶段、依赖、17 个原子证据、实际命令。
- `VerificationState`：已通过模块与阶段；执行器仅在全部命令成功后原子更新，失败命令不能篡改。
- `VerificationReport`：`run_id`、`trace_id`、范围、状态、命令耗时、退出码、脱敏尾部输出、失败码与时间。
- 状态：`running`、`passed`、`failed`、`blocked`。`blocked` 仅用于前置/注册/计划缺失，不能伪装为 passed。

## 安全与数据边界

报告目录必须位于仓库内并默认写入被 Git 忽略的 `.artifacts/verification`。详细报告不由 Web 静态站点公开。数据库表只索引报告元数据；组织发布任务适用时必须写 `organization_id`，平台全局代码验收允许为空。
