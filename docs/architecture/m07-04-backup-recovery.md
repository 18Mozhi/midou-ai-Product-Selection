# M07-04 备份与恢复架构

## 范围与事实边界

M07-04 覆盖 MySQL、证据文件、导出文件和不含秘密的版本化配置。按当前明确范围，备份与恢复均在惠州现有 S0 主机内完成：密文副本使用与在线目录分离的宝塔受控根目录，恢复使用临时隔离数据库和隔离文件根目录。它只保护逻辑误删、应用发布或数据损坏，不保护整机、磁盘或机房故障，也不声明异地灾备、多节点或高可用。备份和演练只由宝塔计划任务执行，不增加常驻服务。页面和 GET API 只读，要求 `platform:operate`，不返回文件路径、主机、密钥或组织级明细。

MySQL 目标为 RPO 不超过 15 分钟、RTO 不超过 240 分钟。`backup_recovery_runs` 分别记录目标值和实际 `actual_rpo_minutes/actual_rto_minutes`、备份或隔离演练结论、request_id/trace_id 和四项恢复核验；`backup_recovery_assets` 记录区域、对象类型、密文/明文哈希、大小和保留期。组织或工作区资产必须携带对应范围；平台全库备份使用 `scope_type=platform`，其组织边界在隔离恢复时按业务表核验。

## 数据流与失败关闭

宝塔任务生成逻辑备份或文件清单，`scripts/backup-recovery.mjs` 使用 AES-256-GCM 加密并校验 SHA-256，随后写入当前主机内独立的恢复副本根目录。业务元数据连接继续固定为 `product_scout@127.0.0.1`；只有 `mysqldump`、binlog 切换和隔离恢复库等管理员步骤通过 `BACKUP_MYSQL_SOCKET` 指向的本机 Unix socket 使用宝塔受限 root 凭据，禁止为此新增 `root@127.0.0.1` 或把全局权限授予业务账号。只有恢复副本完整性通过，且 90 天内同机逻辑隔离恢复对业务数据、审计链、证据哈希和权限边界全部通过，API 状态才为 `verified`。无记录为 `empty`，缺同机恢复副本或演练为 `blocked`，过期演练为 `stale`。

密钥只来自宝塔受限环境 `BACKUP_ENCRYPTION_KEY`，不得进入数据库、浏览器、日志或 Git。异步备份由宝塔计划任务承担，因此 Worker/Crawler/Outbox 对本模块不适用；这不是绕过异步要求，而是生产管理边界决定的有限任务模型。

只读状态链也必须有界且保持事实一致：API 为单次读取设置 14 秒 `AbortSignal`，客户端断开时同步取消；`backup_recovery_runs`、`backup_recovery_assets` 和成功读取审计使用同一连接、同一事务顺序执行。取消、超时或依赖故障回滚事务，不补写迟到的“成功”审计。连接类依赖故障映射为脱敏的 503 `backup_recovery_dependency_unavailable`，超时映射为 503 `backup_recovery_read_timeout`，不得返回 SQL、驱动、连接、主机、账号、路径或凭证。

浏览器刷新为单飞，15 秒后中止当前请求。首次读取仍显示加载或明确失败态；已有可信快照时，429、503、网络故障和超时只显示行内提示并保留上次事实，防止事故期间页面闪空。401/403 属于权限边界变化，必须清空旧平台事实；会话失效提供重新登录入口。序列号和组件卸载取消确保迟到响应不能覆盖较新状态。

备份资产在桌面端使用表格，在窄屏使用摘要卡片和详情抽屉；对象、存储角色和阻断原因显示中文业务名称。API 按服务端观测时间、最近演练完成时间和既有最大演练年龄计算 `drill_age_days`、`drill_expires_at` 与带正负号的 `days_until_drill_expiry`，页面始终展示到期时间和剩余天数，因此无需另造“即将到期”阈值或常驻提醒任务。原始对象代码、存储角色代码、阻断代码和 request_id 仅保留在折叠的“技术详情”中，既避免内部代码占据主流程，也保留运维追踪入口。该展示和刷新韧性调整不改变备份、恢复、加密、成功 DTO 或数据库结构合同。

## 回滚

先在宝塔停用 M07-04 计划任务，再回退 API/Web 发布。确认没有引用后执行 `0025_backup_recovery_m07_04.down.sql`；删除表前必须导出审计记录和恢复证据。密文备份不得因代码回滚自动删除，按保留策略处置。配置回退仅移除 M07-04 变量，不触碰已有数据库、证据与导出根目录。
