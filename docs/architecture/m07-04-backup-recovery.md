# M07-04 备份与恢复架构

## 范围与事实边界

M07-04 覆盖 MySQL、证据文件、导出文件和不含秘密的版本化配置。按当前明确范围，备份与恢复均在惠州现有 S0 主机内完成：密文副本使用与在线目录分离的宝塔受控根目录，恢复使用临时隔离数据库和隔离文件根目录。它只保护逻辑误删、应用发布或数据损坏，不保护整机、磁盘或机房故障，也不声明异地灾备、多节点或高可用。备份和演练只由宝塔计划任务执行，不增加常驻服务。页面和 GET API 只读，要求 `platform:operate`，不返回文件路径、主机、密钥或组织级明细。

MySQL 目标为 RPO 不超过 15 分钟、RTO 不超过 240 分钟。`backup_recovery_runs` 分别记录目标值和实际 `actual_rpo_minutes/actual_rto_minutes`、备份或隔离演练结论、request_id/trace_id 和四项恢复核验；`backup_recovery_assets` 记录区域、对象类型、密文/明文哈希、大小和保留期。组织或工作区资产必须携带对应范围；平台全库备份使用 `scope_type=platform`，其组织边界在隔离恢复时按业务表核验。

## 数据流与失败关闭

宝塔任务生成逻辑备份或文件清单，`scripts/backup-recovery.mjs` 使用 AES-256-GCM 加密并校验 SHA-256，随后写入当前主机内独立的恢复副本根目录。只有恢复副本完整性通过，且 90 天内同机逻辑隔离恢复对业务数据、审计链、证据哈希和权限边界全部通过，API 状态才为 `verified`。无记录为 `empty`，缺同机恢复副本或演练为 `blocked`，过期演练为 `stale`。

密钥只来自宝塔受限环境 `BACKUP_ENCRYPTION_KEY`，不得进入数据库、浏览器、日志或 Git。异步备份由宝塔计划任务承担，因此 Worker/Crawler/Outbox 对本模块不适用；这不是绕过异步要求，而是生产管理边界决定的有限任务模型。

## 回滚

先在宝塔停用 M07-04 计划任务，再回退 API/Web 发布。确认没有引用后执行 `0025_backup_recovery_m07_04.down.sql`；删除表前必须导出审计记录和恢复证据。密文备份不得因代码回滚自动删除，按保留策略处置。配置回退仅移除 M07-04 变量，不触碰已有数据库、证据与导出根目录。
