# M05-05 自动化规则架构

`automation_rules` 只监听已由 M05-03 投影为通知的事务 Outbox 事件。规则与执行都限定在当前 `organization_id + workspace_id`，规则版本在发现事件时固化到执行记录。

支持的触发器为审批超时、审批驳回、竞品告警和任务创建；条件只匹配持久化通知的严重程度。安全动作只有通知规则负责人或创建待人工处理任务。任务来源固定为 `automation`，任务触发器禁止再次创建任务，避免循环。自动化不能批准审批、改变机会结论、覆盖原始事实或代表用户作业务决定。

创建或编辑规则时可调用 `POST /api/v1/automations/preview` 试运行。该接口先复用完整规则校验与成员范围校验，再按 Worker 的真实连接关系 `notifications.source_event_id -> outbox_events.id` 匹配事件类型和严重程度；返回最近 30 天命中数、当前限流窗口命中数、限流后最多动作数以及最多 5 条通知样本。试运行固定为只读，不创建 `automation_executions`、通知、任务、审计或 Outbox；页面明确拆分预计人工任务数与负责人通知数，操作者可沿样本深链核验来源后再保存规则。

Baota Node Worker 以 MySQL 5.7 行租约执行。`(rule_id, notification_id)` 唯一键实现发现去重，规则时间窗限制成功动作数，失败按配置重试后进入 dead letter。暂停与恢复使用乐观版本和必填原因，并写审计与全局 Outbox。

规则列表同时返回当前范围内最近一次执行的状态、更新时间和稳定错误码，页面把错误码翻译为业务提示，原码只放在技术详情。执行详情可返回触发通知与来源链路；动作真实创建人工任务时，可直接进入该任务。平台级告警不复用成员自动化入口。

S0 仅承诺单主机 Worker。该实现不宣称多节点或 10,000 用户容量；P08 软件完成也不扩展此声明。
