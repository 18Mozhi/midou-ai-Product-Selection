# M02-03 三套导航壳层

## 范围与视觉依据

本模块交付普通成员、组织管理员和平台管理员相互独立的顶部身份条、横向模块索引、移动导航与路由状态。生产布局依据 `design-plans/ui-redesign-2026-09-05/` 的 73 个桌面页面、73 个移动页面和 13 张系统审查图；图片中的指标、头像、通知数和业务数据均不作为事实，真实页面继续消费现有 API 和权限合同。

## 服务端 Guard 与数据边界

- `GET /api/v1/me/landing` 先验证 HttpOnly 会话，再按真实平台角色、当前组织管理员角色、普通成员上下文的优先级返回 `/platform-admin`、`/org-admin`、`/home` 或 `/select-context`。没有已选上下文时，服务端额外检查活动组织成员资格：有成员资格才进入 `/select-context`，完全无成员资格则进入账号级 `/me`。公开根路径 `/` 和登录/MFA 成功后都消费该结果，不再默认打开成员壳层或设备会话。
- `GET /api/v1/me/navigation?shell=member|organization_admin|platform_admin` 再由 `AuthorizationService.guardNavigationShell` 读取真实角色、能力及可选租户上下文。
- 成员壳层要求活动成员资格和已选组织/工作区；组织后台默认要求 `organization_admin`，唯一只读例外是同时具有 `auditor` 角色与 `audit:read` 能力的活动成员进入 `/org-admin/audit`。审计员只获得带 `audit:read` 的组织审计目录和路由，空能力的组织管理路由继续失败关闭，顶部也不展示邀请成员写入口。平台后台要求任一真实平台角色，且不依赖组织上下文。
- 每次允许或拒绝写入现有 `authorization_decisions`，保留 actor、组织/工作区（适用时）、代表能力、结果、原因、`request_id` 与 `trace_id`。账号级落地记录 `landing_account_only` 拒绝业务能力，同时只放行会话级个人资料、设备会话和 MFA，不产生任何组织数据权限。前端菜单只是服务端结果的展示层，不能代替后续 API/Worker/导出/文件/事件/SSE Guard。
- 菜单只使用服务端返回的 capabilities 过滤。三个壳层不会互相混入菜单，也不读取其他组织数据。

## 持久化、异步与配置

导航摘要从 M01 的会话上下文、成员、角色、能力和平台角色实时派生，无需新增数据库迁移；审计复用已有决策表。本模块为同步只读请求，不新增 Worker、Crawler、Outbox、Redis 队列、文件、导出或 SSE。浏览器继续只使用既有 `VITE_API_BASE_URL`，无需新增环境变量、密钥或面板外服务。

## 页面与异常状态

桌面采用顶部身份条、横向模块索引和账页主内容区；成员壳层提供搜索、创建、通知和个人入口，组织/平台后台不暴露需要成员工作区上下文的搜索与通知入口。模块按任务域排列，当前组只高亮而不自动展开遮挡内容；点击组名展开方形索引页，拥有八个以上可见入口时可按菜单名称或分组名称筛选。页面标题使用账页序号和中文标题，上下文轨展示当前范围、任务域、信号状态和中文角色。成员“创建选品”打开权限过滤的快捷创建对话框，平台超级管理员“新建组织”直达 `/platform-admin/organizations/new`。840px 及以下切换为抽屉，三个壳层统一显示最多四个有权主入口和一个“更多”；抽屉自动展开当前任务域。加载、401、403、409、429 和依赖失败均提供文字和下一步，关联编号收进“故障详情”。

浏览器历史由 Vue Router 管理，`apps/web/src/route-catalog.ts` 是页面标题、壳层、面包屑、前端能力提示、页面组件标识 `surface`、缓存策略 `cachePolicy` 和侧栏目录的单一配置；侧栏能力直接从对应路由元数据派生，不能维护第二份权限表。导航壳按 `surface` 选择页面组件并统一传入作用域参数，不再维护逐页面的巨型渲染条件链。成员与组织页面使用 `reset_on_scope`，平台页面使用 `preserve`，公开和账号页面使用 `none`；业务组件按路由名称和当前租户生成缓存键，并由最大 12 项的 `KeepAlive` 保留有界页面状态。同源业务跳转显式使用 `RouterLink` 或 `router.push/replace`，入口不再使用全局点击拦截兼容普通 `<a>`。未知地址只进入专用 404 状态且不得默认高亮第一个菜单。`docs/feature-map.json` 的前端路由路径必须唯一；采集调度菜单与页面一级标题统一为“采集调度”，页面内部模块标题不得冒充第二个页面标题。

壳层内部按权限、路由装配、主题和发现状态拆分：`navigation-shell-permissions.ts` 只消费服务端 Guard 返回的能力并过滤路由目录；`navigation-shell-route-state.ts` 解析兼容路由、页面摘要、实体参数和页面组件属性；`use-navigation-shell-theme.ts` 管理带版本锁的主题读取、保存和失败回滚；`use-navigation-discovery.ts` 管理搜索、快捷创建和 Ctrl/Cmd+K。`NavigationShell.vue` 继续拥有 Guard 请求、壳层布局与页面挂载，但懒加载候选不重复注册已经由 `App.vue` 独立加载的账号、登录、租户选择、引导、主题、404 和开发态页面，避免把无用加载映射打入导航壳 chunk；该拆分不增加第二份权限表或路由目录。

成员、组织和平台模块索引按任务域分组；平台后台收敛为“业务运营、采集与数据、治理与安全、高级运维”四组，让日常业务入口与基础设施运维入口分层，索引和平台首页快捷入口都按服务端返回的能力过滤。账号与组织拆为 `/platform-admin/organizations`、`/platform-admin/users`、`/platform-admin/admins` 三个可深链页面，组织创建与详情继续使用独立地址，旧地址继续兼容。凭证入口只在来源管理上下文出现；采集与系统运维继续复用各自二级索引。组织、平台和个人中心继承当前纸张主题，后台只切换紧凑密度。`/me` 使用独立横向账号分区索引，不要求组织上下文；个人资料读写、设备会话和 MFA 属于账号级能力，其余权限与数据边界不变。

成员完整路径（含筛选和分页）与最近有效站内路径写入限定名称的 `localStorage` 键，只保存同源绝对路径，不保存身份、权限、查询结果或其他敏感数据；根路径在服务端返回成员首页时恢复最近成员页，404 使用最近有效路径提供恢复操作。组织最近使用顺序同样只保存最多五个组织 ID，用于当前账号的选择页排序，不改变服务端返回范围。从平台后台返回成员工作台仍必须先进入 `/select-context` 选择目标组织与工作区，成功后按受控 `return_to` 回到原页面。`/select-context` 位于三套导航壳之外，切换时旧 `NavigationShell` 及其内部 `KeepAlive` 会整体卸载；新范围返回业务页时重新挂载页面实例，禁止复用旧组织或旧工作区的页面缓存。`return_to` 只接受同源绝对路径，不允许协议相对地址。
