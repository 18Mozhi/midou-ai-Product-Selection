# M02-02 认证与入驻页面

## 范围与依据

本模块将 P01 已实现的本地账号、邮箱验证、密码重置、MFA、组织/工作区选择合同组合为完整入驻体验，并增加不写业务数据的三步快速引导。布局依据概念图 01–10、高清图 `02_scoutops霓虹科技登录页.png` 与 `03_scoutops_深海蓝注册向导.png`；图片中的手机登录、Google、Microsoft、SSO、认证徽标与示例品牌没有真实合同，因此不显示为可用入口。

登录页使用完整中文信息层级；桌面主标题的两个语义短句各自保持完整，避免单个汉字孤立换行。装饰轨道缩减为辅助图形，账号保护术语收敛到必要说明；移动端“忘记密码”入口保持单行并且不挤压表单主操作。

## 数据、API 与异步边界

- 登录、注册、找回、验证、重置和安全设置继续使用 M01-01/M01-02 的 `users`、会话、单次令牌、安全事件、投递 Outbox 与 MFA 表；组织/工作区继续使用 M01-03 的租户表和事务审计。本模块不新增迁移。
- 前端只发送 OpenAPI 已定义字段，不接触或保存 HttpOnly 会话 Cookie。组织和工作区列表由服务端活动成员范围决定。
- 邮件投递仍由既有受控 Outbox 承担；Provider 未确定时显示受阻，不新增 Worker、队列、事件或重试规则。三步引导只改变当前页面步骤，不落库、不产生权限或业务结论。
- 不新增 API、环境变量、权限、文件、导出或 SSE 合同，因此 OpenAPI 与 `config/env.example` 无字段变更。

## 页面与异常状态

登录、注册、找回、验证、重置、MFA 挑战、组织、工作区和引导均支持桌面与 390px。401/无效凭证、429、503/网络失败、链接过期、无组织、无工作区、无权与工作范围就绪分别提供文字、下一步和可用时的 `request_id`，不只依赖颜色。
