# 平台组织、用户与管理员管理

平台超级管理员在 `/platform-admin/accounts` 使用同一个“小白化”页面管理组织、用户和平台管理员。三个页签分别回答“有哪些团队”“谁能登录”“谁能进入平台后台”，不把会话表、角色表或数据库字段暴露给操作者。

`GET /api/v1/platform/accounts` 只返回账号元数据与聚合数量。创建组织会在一个 MySQL 5.7 事务中创建组织、默认工作区、当前超级管理员成员关系、组织管理员角色和组织级数据范围；停用用户会同时撤销该用户全部活动 `user_sessions`。平台角色只能从运营管理员、安全管理员、超级管理员三种固定角色中授权或撤销。

平台创建组织使用两步向导：第一步只填写并校验组织名称与英文标识，第二步选择首位组织管理员并明确展示将同时创建默认工作区和组织级数据范围。向导只在最终确认时调用原有创建接口，仍一次提交 `name`、`slug` 和可选的 `initial_admin_user_id`，不拆分后端事务，也不产生半成品组织。

所有写操作要求 `platform:superadmin`、同源 Origin、Idempotency-Key 和 2–300 字原因，使用 `platform_account_operations` 幂等，并写入 `platform_audit_events`。当前账号不能停用自己，也不能撤销自己的超级管理员角色。

管理员、组织管理员和普通成员继续使用三套独立导航。平台主导航只显示平台概览、组织与用户、热点来源、采集任务、数据质量、安全与审计、高级设置；Redis、MySQL、文件与容量等技术页不再占据小白用户的一级菜单，但历史受保护路由未被删除。
