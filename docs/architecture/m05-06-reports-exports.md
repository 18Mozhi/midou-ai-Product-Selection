# M05-06 报表与导出架构

`/api/v1/reports/{type}` 在当前 `organization_id + workspace_id` 内直接聚合已落库的机会、趋势、成员与任务事实。机会报表展示决策和推荐分布，趋势报表展示主题、信号、来源与置信度，团队报表展示活动成员的任务状态。空值保持 `null`，页面显示“数据不足”，不生成预测或示例指标。

当前接口没有可选日期窗口，三类报表统一使用“当前工作区全部已落库记录”口径，并用 `observed_at` 标示事实截至时间。页面固定展示报表类型二级导航、口径和结论摘要，不把全量口径伪装成最近 7 天或最近 30 天。

导出请求持久化为 `report_exports`，由宝塔 Node Worker 以 MySQL 5.7 租约异步生成 CSV。列表和详情按 Worker 的全局领取顺序计算活动任务的 1 基队列位置，但只向用户返回当前工作区自己的记录，不暴露其他组织的任务。预计完成时间只在存在成功历史时提供：API 读取全局最近 20 次成功导出的 `created_at -> updated_at` 实际完整耗时，以中位数顺序推算当前活动队列；响应同时给出样本数和中位耗时。没有成功样本时 ETA 保持 `null`，页面明确显示暂无法估算，不用轮询间隔、租约上限或常量伪造速度。估算是观测值而非 SLA，重试、行数和依赖变化都可能使实际完成时间偏移。文件路径只由配置根目录、组织、工作区、导出 ID 和服务端文件名组成；CSV 单元格防公式注入，超出行数上限会失败而不是截断。创建与完成写审计和全局 Outbox，幂等键去重创建请求。

同一操作者、路由和幂等键的并发请求可能同时通过首次回读；其中一个事务提交后，另一个事务会在 `report_export_operations` 唯一键处失败并回滚自己的导出、审计与 Outbox。仓储随后回读已提交操作并返回同一个导出结果，禁止把合法并发重放暴露为 500，也不会留下第二份任务。

下载端点重新执行会话、`report:read` 和组织/工作区隔离，只有未过期的 succeeded 文件可下载。Worker 会删除到期文件并将状态改为 expired。S0 只使用单主机宝塔 API/Worker 与本地受限目录，不宣称共享存储、多节点或 10,000 用户能力。

页面把 `queued`、`leased`、`retry_scheduled`、`succeeded`、`dead_letter` 和 `expired` 映射为用户可理解的排队、生成、等待重试、可下载、生成失败和已过期状态；活动记录同时展示队列位置、预计完成时间及历史样本依据，内部错误码只放在折叠的技术详情中。重新生成只接受已过期（包括文件有效期已到但 Worker 尚未完成清理）或 `dead_letter` 记录；API 读取原记录的报表类型和格式后创建全新的队列任务，旧记录及文件生命周期保持不可变。相同操作者、来源导出和幂等键只返回同一次新建结果，审计与 Outbox 使用 `report.export.regenerated` 并保留 `regenerated_from_export_id`。

导出详情使用 URL 中的 `export` 标识并重新读取受权限保护的详情接口，刷新和浏览器返回后仍能恢复；抽屉使用原生模态对话框，支持 Escape 关闭和焦点返回。自动轮询与手动刷新只更新事实和导出状态，不把已展示报表切回整页加载态；快速切换报表时使用请求序号丢弃过期响应。网络中断或依赖不可用统一显示“报表服务暂不可用”，不得误报为某个导出尚未就绪。下载期间同一页面只允许一个下载动作，避免重复点击产生并行文件读取。

成员任务中心的“导出任务”视图复用同一份 `/report-exports` 生命周期事实，只汇总展示状态与下一步；下载、重建和技术详情仍返回报表页处理，不复制或伪造业务任务记录。
