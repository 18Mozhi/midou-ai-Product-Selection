# M02-06 首页与移动壳

## 范围与依据

本模块实现 `/home` 的自动选品决策入口、其他待办、数据健康和空状态布局，以及 390px 首页和机会详情路由骨架。首屏把“待人工采纳的自动推荐”作为唯一主任务；运行规则、补证中和待采纳只保留一行事实摘要，完整采集步骤、候选数、已采纳数、采集时间和投影生成信息通过原生折叠区按需查看。四个事实摘要分别直达待采纳、规则命中候选、采集中和规则管理，避免用户先进入总列表再筛选；推荐队列为空但仍有候选或采集任务时，只显示一个与当前真实进度对应的入口。推荐项使用分隔行而不是卡片套卡片，其他待办与异常下移到次级区域。每条事项继续使用投影自带的真实站内 `route`，全链路教学只属于首次引导，不进入首页。视觉直接参考高清“今日行动中心驾驶舱”和概念图 11–14、53–54；业务真相遵循总纲 3.2。P03–P05 尚未交付的趋势、机会、任务和来源数据不会用示例指标替代。

## 真实读取模型

今日行动不再等待缺失的首页投影生产者：仓储直接合并当前用户负责的未完成 `tasks`、当前节点由用户处理的 `approval_requests`，以及命中当前组织与工作区选品规则、待决策且持久化评分结论为 `recommend` 的本人机会。系统生成的证据补采、选品复核、采购和采集跟进任务沿用任务详情，因此阻断项可以一键打开完整业务与关联采集上下文。普通待处理、手工或 ERP 导入机会不会再冒充首页“推荐清单”；`automatic_selection.recommended_items` 为首页提供最多五条真实推荐。`home_dashboard_items` 继续承载可重建的变化、关注、健康和兼容行动投影，保留组织、工作区、受众、站内路由和来源版本。

`GET /api/v1/me/home-dashboard` 先解析活动会话上下文并同步审计 `task:read` 授权，再按精确组织、工作区、当前责任人和 capability 查询。健康项必须精确命中当前用户；其他存储投影允许工作区共享或当前用户受众。行动先按 `逾期 > 阻断 > 高风险 > 高价值 > 普通`，同级再按持久化风险、机会评分、截止时间和观测时间排序，按详情路由去重后最多返回五项。没有机会评分或截止时间时返回 `null`，不填充默认值。

`HomeDashboard.vue` 负责读取、规则创建/恢复和页面编排；`HomeAutomationOverview.vue` 只通过显式 props 接收自动选品摘要并呈现紧凑状态与可展开运行详情，不发请求、不维护业务状态。该拆分不改变 API、路由、数据库、评分、推荐或采纳契约。

运行详情的步骤完成态也只来自摘要事实：只有 `enabled_rule_count > 0` 时“监控平台”才显示已完成；未配置工作区必须显示零条规则且步骤未完成，不能仅因页面渲染成功而伪装为监控已启动。

## 生产者、异步与非目标

本模块只提供同步跨模块读取，不创建 Worker、Crawler、Outbox、队列、事件、文件、导出或 SSE。任务、审批和机会仍由各自模块维护；首页不复制或改写业务事实。机会详情只展示所属机会模块已经持久化的内容，不在首页计算评分、利润或风险。

无任何可见行动、变化、关注或健康数据时返回四组空数组，前端提供“开始一次选品、添加竞品、从 1688 找货”入口。无新增环境变量或密钥，浏览器继续只使用既有 `VITE_API_BASE_URL`。
