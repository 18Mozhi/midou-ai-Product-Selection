# M06-06 配额管理

本模块只建立配额方案、组织配额、用量和人工调整的运营边界，不实现计费或支付扣款，也不定义价格、币种、税率、发票或支付 Provider。平台运营管理员通过 `/platform-admin/commercial` 和 `/api/v1/platform/commercial/*` 操作，统一要求浏览器会话与 `platform:operate`；写操作还要求同源、`Idempotency-Key`、原因和版本锁。

## 数据与真相边界

- `commercial_plans` 保存版本化方案名称、说明和配额 JSON；没有系统编造的默认方案或默认价格。`plan` 是现有 API 和持久化字段名，不代表已接入计费套餐。
- `organization_plan_assignments` 保存组织当前配额方案及明确统计周期；`commercial_quota_adjustments` 保存带原因、有效期和撤销状态的人工增减量。
- 方案读取按“启用、草稿、退役 + 更新时间 + ID”稳定排序并服务端分页，方案汇总不受当前筛选或分页截断；调整历史有独立分页。有效配额单独聚合当前分配下全部已生效且未失效的调整，不能用当前历史页推导。
- 组织深链接、方案搜索、状态和两套页码写入 URL，刷新、前进和后退恢复同一读取上下文。读取会确认组织真实存在；不存在返回 `organization_not_found`，不得伪装成未分配组织。
- 当前计量项固定来自已有持久化事实：`collection_tasks`、`open_api_usage` 和 `report_exports`，分别映射 `collection_tasks`、`open_api_requests`、`report_exports`。读取按组织与当前账期聚合，不用 Redis 或浏览器值替代事实。
- 有效配额等于方案基础配额加当前有效人工调整，并以零为下限。模块不自动阻断业务请求；它提供后续策略可消费的真实配额视图，避免在没有业务规则时猜测强制行为。
- 页面在写入前根据当前读取结果生成只读影响预览：方案编辑展示仍处于活动或暂停分配状态的组织数量及各计量项前后值；组织换方案、改账期、人工调整或撤销展示目标组织、有效配额和余量前后值。账期变化时不猜测未来用量，只明确提示变更后按新周期重新统计。预览不替代服务端版本锁、权限或最终写入校验。
- 读取写 `commercial_views`、平台审计和 `commercial_events`。变更同时写平台审计；组织级变更还在同一事务写 `outbox_events`。全局套餐事件允许 `organization_id` 为空，组织分配与调整必须有组织范围。
- 浏览器读取使用 15 秒超时、取消前次请求和响应序列保护；超时或失败时保留最后一次成功数据。创建和确认操作在请求期间禁用重复提交，并在同一次确认重试时复用同一个幂等键。
- 商业配额服务只把已知 MySQL 连接、连接池、死锁和查询超时错误映射为 503 `commercial_dependency_unavailable`，提示写操作使用原幂等键重试；业务错误和未知编程错误不被吞并。

## API、权限和状态

读取接口可选 `organization_id`；不带组织时只返回配额方案，不查询任何组织用量。创建方案为草稿；页面可编辑配额并生成新版本。组织可首次分配，也可通过同一受控接口变更配额方案和统计周期，并可暂停、恢复或结束；调整及撤销同样使用版本化写入。相同 actor、路由和 Idempotency-Key 返回原结果，并发写由 MySQL 唯一键串行化。

页面依据 `images-html` 概念图 70 和 71，使用暗色卡片与配额比较层级；导航和页面统一标记为“配额管理”，提供方案编辑、组织配额分配/调整、暂停/恢复/结束、`loading`、`empty`、字段错误、`rate_limited`、依赖 `blocked`、确认、影响范围预览和恢复状态。用户界面不展示会员、续期、计费套餐、价格或支付结论。390px 下表单、方案、用量、影响预览与调整记录改为单列，状态文字和数值不依赖颜色。

## 异步边界

M06-06 没有支付结算、周期重置或额外 Worker/Crawler。用量在 Node API 中从 MySQL 同步聚合；组织级变更只投递既有事务 outbox，由已有宝塔 Node Worker 基础设施消费。不得为本模块创建面板外服务。
