# M06-01 组织管理后台

前端按成员、角色、工作区、团队、审批治理和组织数据拆分展示边界：`OrganizationAdminCenter.vue` 保留路由、API、审计写操作与跨分区编排；`OrganizationMemberPanel.vue` 展示单个或逐条落库的批量邀请、邀请撤销、成员筛选分页和成员动作；`OrganizationRolePanel.vue` 展示固定角色、能力矩阵、实际数据范围和指定资源授权生命周期；`OrganizationWorkspacePanel.vue` 展示当前组织工作区目录、创建入口和归档恢复影响；`OrganizationTeamPanel.vue` 展示当前组织团队目录、创建入口、负责人和成员关系；`OrganizationApprovalPanel.vue` 展示模板版本差异和审批记录；`OrganizationDataPanel.vue` 展示跨工作区规模和最近导出履历。子组件不直接请求接口，也不绕过成员、角色、工作区、团队、数据范围、资源授权、审批或报表合同。

成员列表同时返回用户显示名、账号状态与组织成员状态。页面按“成员停用优先，其次账号锁定/停用”的规则展示有效状态；姓名与邮箱均可检索。批量邀请复用单邀请 API，按邮箱逐条生成独立幂等键并展示逐条结果，避免用一个批次结果掩盖部分失败。待接受邀请可通过带版本号、审计原因和幂等键的动作接口撤销；创建邀请在组织行锁内复查操作记录和重复邮箱，防止并发产生重复待处理邀请。撤销邀请、成员状态动作和角色分配都会在资源行锁内再次读取幂等结果；角色分配也携带成员版本，确保同键并发复用结果、不同键并发仅一个写入成功。

组织后台浏览器请求采用 12 秒失败关闭超时。超时会映射为可恢复的 `organization_request_timeout`，无法建立网络连接时映射为 `organization_network_unavailable`；背景刷新保留已加载事实并提供重试提示，首次加载失败进入明确的暂不可用状态。这个前端保护不改变 Node API、MySQL 或 Worker 超时配置。

## 范围与事实边界

本模块实现当前组织的资料、成员与邀请、固定角色模板、工作区、团队、审批事实、组织数据入口、组织 Token 元数据和组织审计。所有查询以服务端会话解析出的 `organization_id` 为范围，不接受浏览器指定组织覆盖。平台驾驶舱、开放 API/Webhook、支付和多节点能力不属于本模块。

组织资料、成员、工作区和团队管理使用独立子路由。普通管理界面以工作区名称、成员邮箱、团队名称、中文角色和中文能力名称表达业务对象；工作区和成员 UUID 仍作为既有 API 写入值，但只允许出现在折叠的“技术详情”或表单选项值中，不作为选择或识别对象的主文案。审批主列表展示申请标题与当前阶段，资源和模板 UUID 只放在折叠的技术详情中。

成员页在浏览器内按姓名或邮箱、状态、角色和团队筛选，并把邀请分为“待接受”和“已失效”；角色页可检索固定角色和中文业务能力，按业务域筛选能力矩阵，同时读取当前会话授权、实际成员范围、工作区以及资源授权事实。审批模板继续复用既有工作区审批合同，组织后台只提供跨工作区的只读治理视图；每个模板读取当前版本及最近的上一版本，按节点顺序比较节点新增/移除以及名称、审批人、处理时限和超时接收人变化。成员名称来自当前持久化档案或账号，不向主界面下发 UUID；首版模板明确没有上一版，同内容版本明确无变化。`/org-admin/data` 使用 `report:read` 权限返回当前组织各工作区的热点、机会、未删除任务和报表导出计数，以及最近导出记录；响应携带 `observed_at`，不以缓存或示例数据冒充实时事实。

组织资料、成员、角色、工作区、团队和 Token 的写入使用 `Idempotency-Key`、原因与适用的乐观版本锁。同事务写业务表、`audit_logs`、`outbox_events` 和幂等结果；组织资料在锁定组织版本后会在同一事务内再次检查幂等结果，使并发提交的相同幂等键复用首个成功响应，不产生第二次业务写入。Outbox 由宝塔管理的 Worker 消费，本模块不创建面板外服务。邀请邮件 Provider 未确认，因此状态保持 `pending_delivery`。

## 组织概览交互状态

`/org-admin` 首次进入时读取 summary、profile 与 workspace 三组当前组织事实。手工刷新使用后台刷新状态：既有指标和组织资料保持可见，刷新按钮在请求完成前禁用并显示“正在刷新”，较早请求的迟到响应不能覆盖较新的页面事实。刷新完成后展示服务端 `observed_at`，不把浏览器点击时间冒充数据时间。

组织资料保存与读取状态分离。浏览器先校验 Logo 仅允许 HTTPS、名称/时区长度、数据保留范围、默认工作区和变更原因；后端仍执行同一验证与乐观版本锁，并在 400/404/409 错误响应的 `message` 中返回可直接展示的中文说明。400/409 等写入失败只在表单上方展示中文错误、操作建议与请求编号，不清空已加载事实或隐藏表单；401/403 才替换为登录失效或无权限状态。写入成功后重新读取 MySQL 事实，但保留“已写入审计”的成功提示和本次写请求编号，便于核对 `audit_logs` 与 `outbox_events`。

## 角色、数据范围与资源授权

`/org-admin/roles` 不创建可漂移的自定义角色。角色模板仍由后端固定目录提供，页面使用主从布局展示角色职责和能力分组，并保留完整矩阵用于横向对比。能力搜索同时匹配中文动作和技术能力名称；技术名称只在折叠详情中出现。能力目录补齐热点、竞品和数据来源管理动作的中文业务名称，不再把已知能力笼统显示为“其他授权”。

数据范围页展示 `own`、`team`、`workspace`、`organization` 四级边界、当前会话实际范围以及成员事实分布。角色决定动作，数据范围决定记录集合；前端展示不替代服务端授权。成员搜索和范围筛选都只作用于已从当前组织接口返回的事实。

指定资源授权复用 M01-05 的既有接口和表，不增加数据库结构。角色页按 20 条一页读取服务端分页，状态标签的数量来自各状态查询的真实 `meta.total`，不会把当前页数量冒充组织总数；搜索明确只作用于当前页，生效、到期和撤销筛选会回到服务端第一页。工作区与目标成员显示业务名称和邮箱，UUID 只用于表单值或折叠技术详情。拥有 `role:manage` 的操作者可以创建、延长和撤销授权，写请求继续携带 `Idempotency-Key`、原因和适用的版本号。资源类型与动作白名单由既有资源授权合同限定；资源必须属于所选工作区，目标必须是同组织活动成员，到期最长 30 天，下载、导出、凭证和任务重放不在例外授权范围内。所有写入完成后重新读取服务端事实，并保留写请求编号供审计核对。

## 工作区治理

`/org-admin/workspaces` 读取现有工作区接口返回的数组事实，并在路由编排层保留为 `workspaces` 集合，避免响应形状转换后把真实列表误判为空。页面按名称或英文标识搜索，按正常使用或已归档筛选，支持名称、明确范围人数和最近更新时间排序，并按八条一页展示；统计中的“工作区范围分配数”是各工作区明确范围人数的合计，不宣称跨工作区成员去重。

新建工作区继续调用既有创建接口。浏览器先校验名称、1–63 位小写英文标识和创建原因，非法英文标识不会发出请求；后端仍执行同一验证。归档与恢复继续携带审计原因、幂等键和当前版本。组织默认工作区在页面上明确标识并禁用归档，直接调用接口仍由数据库事务返回冲突；历史业务事实不会因归档被删除。工作区 UUID 和英文标识只放在折叠的技术详情中，团队成员与负责人维护仍属于独立的 `/org-admin/teams` 页面。本次页面治理不修改 API、数据库结构、Worker 或爬虫配置。

## 团队治理

`/org-admin/teams` 读取当前组织团队数组与活动成员事实，按正常使用或已归档筛选，可按团队名称、负责人邮箱或默认流程键搜索，支持名称、成员关系数量和最近更新时间排序，并按八条一页展示。团队统计中的成员关系数量是各团队 `member_count` 的合计，不宣称组织成员去重；负责人覆盖和默认流程覆盖都只依据接口实际字段。

新建团队继续调用既有创建接口。浏览器把名称限制为 120 字符、默认工作流程键限制为 80 字符、原因限制为 500 字符；后端仍执行相同边界及同组织活动成员校验。选择负责人后，数据库事务会同时建立该负责人的团队成员关系。成员分配和移除继续通过既有接口填写审计原因并携带幂等键；`INSERT IGNORE` 与条件删除保证重复请求不会产生重复成员关系，同键并发会在目标行锁内复用首个结果。Outbox 分别使用 `organization.team.member_assigned` 和 `organization.team.member_removed`，避免动态拼接产生不可消费的错误事件名。当前列表合同只返回成员数量，不返回成员明细，页面明确说明这一限制；服务端也没有负责人变更、默认流程变更或团队归档写接口，因此页面不提供虚假按钮。团队和成员关系 UUID 只放在表单值与折叠技术详情中。本次页面治理不修改 API、数据库结构、Worker 或爬虫配置。

## 审批治理

`/org-admin/approvals` 使用 `opportunity:approve` 能力读取当前组织最近 100 条审批记录、状态汇总、审批模板及版本节点事实。页面是跨工作区的只读治理视图：审批决定继续在 `/tasks/approvals` 完成，模板发布、回退或编辑继续由既有业务合同承担，组织后台不提供绕过原审批流的写按钮。

审批记录可按标题、工作区、资源类型和状态检索或筛选，可按申请时间、更新时间或标题排序，并按八条一页展示；模板可按名称、工作区、资源类型和生命周期状态检索或筛选，可按更新时间、名称或版本排序，并按六条一页展示。当前视图、筛选、排序和页码写入 URL 查询参数，刷新、返回与多标签页不会丢失上下文。模板主从视图比较当前版本与最近的持久化上一版本，明确区分首个版本、无差异、节点新增、节点移除和字段变更。工作区、模板、审批和资源 UUID 仅保留在折叠技术详情中。

状态标签逐项覆盖 `pending`、`approved`、`rejected`、`cancelled` 与模板 `published`、`draft`、`archived`，未知状态保留原始值而不误报为已知业务状态。无记录、筛选无结果、加载、后台刷新、接口失败、超时、离线、未登录和无权限状态均使用既有组织后台请求状态合同。本次页面治理不修改 API、数据库结构、Worker 或爬虫配置。

## 组织数据治理

`/org-admin/data` 使用 `report:read` 读取当前组织各工作区的热点、机会、未删除任务和全量导出计数，以及最近 100 条导出记录。页面汇总只对本次响应中的工作区事实求和；任务计数延续仓储层 `deleted_at IS NULL` 条件，导出总计与“最近导出”列表条数分别表达，避免把接口最近 100 条上限冒充全量。

工作区比较支持名称搜索、正常或归档状态筛选、名称及各类计数排序和八行分页；最近导出支持工作区、报表类型、生成状态、关键字筛选、时间或行数排序和十条分页。视图、筛选、排序和页码写入 `org_data_*` URL 查询参数，刷新与多标签页保留上下文。移动端把宽表转换为逐工作区事实卡片，避免固定最小宽度导致整页横向溢出。

状态标签逐项覆盖 `queued`、`leased`、`retry_scheduled`、`succeeded`、`dead_letter`、`expired`，报表类型覆盖 `opportunity`、`trend`、`team`；未知值保留原始值，不误报为已知状态。当前接口不返回数据质量规则、缺失率、异常结论、文件地址或新建导出合同，因此页面明确“数量不等于数据质量”，不虚构评分、下载或写操作；真实导出创建与下载继续前往 `/reports`。加载、后台刷新、空数据、筛选无结果、失败、超时、离线、未登录和无权限状态继续复用组织后台请求合同。本次页面治理不修改 API、数据库结构、Worker 或爬虫配置。

## 安全与失败

## 组织令牌治理

`/org-admin/tokens` 只治理当前组织的系统读取凭据。页面汇总全部、活动、七天内到期、从未调用和历史生命周期记录，并按名称、前缀、scope 或状态搜索，支持生命周期、固定读取范围、排序和六条分页；筛选与页码写入 `org_token_*` URL 查询参数，刷新、返回和多标签页保留上下文。令牌记录 ID 与版本只在折叠技术详情中显示。

创建表单必须显式勾选至少一个固定只读 scope，不再在空选择时静默补入 `task:read`。有效期继续使用既有 1–365 天合同，名称、原因和到期日期在提交前集中核对。创建或轮换成功返回的明文只在一次性提示区出现，操作者可以复制并主动清除；页面离开后无法找回。轮换确认明确说明旧令牌立即失效，撤销确认明确说明不能恢复，两个动作继续携带审计原因、幂等键和当前版本。

接口仍为 `GET/POST /api/v1/org/admin/tokens` 与 `POST /api/v1/org/admin/tokens/{id}/actions`，权限仍为 `organization_token:manage`，数据库仍为 `organization_api_tokens`。服务端会话确定组织边界，创建、轮换和撤销在同一事务写事实、`audit_logs`、`outbox_events` 与幂等结果；持久化与日志只保留哈希、前缀和生命周期元数据，不保留明文。本次页面治理不修改 API、数据库结构、Worker、爬虫或配置。

- 路由分别要求 organization、membership、role、workspace、team、approval、organization_token、audit 或 report 能力；`/org-admin/data` 单独要求 `report:read`。
- 自我禁用、移除最后一位活动组织管理员、归档默认工作区、跨组织负责人/团队成员全部失败关闭。
- Token 只允许 `task:read`、`trend:read`、`opportunity:read`、`report:read`；明文仅返回一次，数据库只保存 SHA-256 哈希和前缀。
- 空结果保持空数组或零，不填充图片示例数据；409 冲突保留当前表单并要求刷新真实版本后重试。

## 数据与回滚

迁移 `0019_organization_admin_m06_01` 增加邀请、团队成员关系、组织 Token、幂等操作以及组织 Logo/团队负责人字段，兼容 MySQL 5.7 和 utf8mb4。回滚前先关闭 `/org-admin` 写入口并撤销仍在使用的组织 Token；导出需留存的审计证据后，执行 down migration。审计记录不得为掩盖失败而删除。
