# 来源与采集后台导航重制

## 依据与布局

用户要求所有UI和布局重制，主要参考已登录Ecom168的工作区组织方式。2026-10-18再次实看监控概览：固定主导航、内容区完整展开、指标和筛选沿同一内容轴线组织。本站来源定义和采集程序仍有220px蓝色二级侧栏与28px列间距；其余来源及采集页还叠加旧边框标签、横向滚动和居中限宽，视觉与布局不一致。

来源设置、采集程序、来源频道、1688检查、凭证，以及采集总览、任务详情、网页登录采集共八个现有入口统一为内容区顶部的横向导航。选中状态使用文字和底部标线，取消蓝色侧栏、圆角按钮和并列第二侧栏。桌面内容占满可用宽度；手机两列换行，标签不截断，保留至少44px操作高度和键盘焦点。继承现有主题、字体和颜色，不引入字体服务、动画、渐变或依赖。

新样式集中在provider-runtime-navigation.css，由已有commerce-workspace.css引入。删除四份旧样式中36条导航/双栏规则及空媒体分组，并移除三个采集页原1160px居中宽度限制。其他表格、筛选、编辑器、状态和业务样式保留。两个路由承载组件、模板、原始链接、aria-current和superadmin条件均未改变。

## 验证与交付边界

runtime-navigation-layout.spec.ts在桌面和390px共16个场景验证八入口的导航位置、内容全宽、选中路由、透明背景、44px高度、焦点、无横向溢出及无写请求。测试明确使用受控读取失败，只证明布局和恢复导航，不证明真实授权、采集或生产写入。首次验证定位到三个采集页仍有居中限制，移除后16项通过。历史截图、清单及审批未改；共享焦点合同仅更新当前platform-operations.css的精确指纹，原拍摄输入继续由Git历史核验。

没有新增API、事件、数据格式、配置或Python输入，OpenAPI和环境示例无需新增字段；功能调用方和消费方不变。正式发布仍走既有本地deploy-baota.py构建上传，由宝塔管理运行对象；该全包发布会处理托管重启，应合并发布，避免无必要打断正在运行的采集。上线后还须以真实页面核对普通数据状态；本地布局通过不等同于全产品重制或每日100整链验收。
