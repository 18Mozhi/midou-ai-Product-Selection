# 竞品相关性证明接入推荐与整链完成

用户要求每个主品有 5–10 个相关竞品。此前新发现投影已经按类型与用途筛选，但共享质量 SQL 只核对独立 ASIN、真实详情和健康快照，旧的未分类记录仍可能填足数量。现将同一相关性证明加入推荐竞争门及每日整链完成的竞品查询。该证明与详情采集是两个独立条件，不能相互替代。

## 证明范围

复用既有 opportunity.competitors_classified 事件、competitor-title-v1 合同和原证据链接，不建表、不修改归属、不回写旧数据。检查当前主品 ASIN、同组织/工作区/机会、实际发现任务和子查询、来源、原始记录及原始证据。原始商品 URL 必须对应当前竞品 ASIN；分类输入中的引用、ASIN、完整标题，以及同一分类对象内的 substitute 与原文须一致。不会用另一数组元素的 substitute 为当前商品补证据。支持现有平铺与 fields 包装的规范化格式。

同一子查询只接受最新审计；同一主品和竞品有更新的分类任务时，旧任务的相关结论也不能继续通过。其他主品、其他商品及其他租户的新事件不覆盖当前证据。缺失、用途不同、附件、不确定、原文改变、身份不符或审计不完整均保持不足，不补数量。模型只分类既有事实，不提供价格或评分。

成员选品库沿用原 API 的 selection_stage 和 quality_gates.competition，字段与类型不变；列表的已有记录数量仍是记录数量，不能代替质量门。竞品详情中的 detail_collected 继续表示已采到对应详情，不改写成已验证相关。低分/不推荐仍可完成，明确利润未知仍可完成；五个有详细证据的独立相关竞品、情报、实际货源与采购价等其他条件不放宽。历史数据不会因为本次代码发布自动获得分类证明；历史回填仍未完成。

## 验证

91 项相关 Node 回归通过，包含原未知利润与低分整链完成、去重、事务回滚、推荐视图及分类投影。22 工作区完整构建通过。MySQL 5.7.44-log 的只读事务直接执行永久夹具导出的 37 个纯派生表 SELECT，37 个预期全部吻合；其中有缺失/外租户/外主品/外任务、跨数组、原文篡改、新旧事件、跨任务更新、嵌套字段与 URL 身份案例。没有创建测试表、写入业务记录或修改数据库配置。

初测发现外层别名在关联子查询 ON 中不可用，以及 ASCII/UTF-8 正则排序规则冲突，移到 WHERE 并对正则两侧显式转换字符集后复测通过。真实 API 仓库生成的 recommended/rule_candidates/evidence_pending 三个视图各两条语句，加推荐门与整链竞品查询，共八条 EXPLAIN 通过。此为语法与绑定验证，不证明生产查询性能或真实分类质量；没有把派生夹具称为真实商品验收。

夹具位于 tests/fixtures/competitor-relevance-sql.mjs，可在相同只读事务中逐条执行导出的 sql 并比对 expected。它与单元测试是永久交付，没有本轮临时脚本、日志、图片或常驻进程。

## 使用与发布

没有新增环境变量、依赖、API 字段、Python 输入或 CLI 项；OpenAPI 同步描述质量门，环境示例无需改动。生产者仍为原采集分类器，消费者为 API 竞争门及 Worker 整链检查。前端/插件/Python 没有新输入或动作。固定宝塔脚本发布后须重启唯一 Node 项目：`/www/server/panel/pyenv/bin/python /www/server/panel/script/restart_project.py nodejs ai选品`，无需 Python 重启。

本项尚未部署，不启动生产采集、不回收或重放历史任务、不改变同 ASIN 跨主品归属。每日百品、历史回填、同款货源及全站 UI 仍未完成验收。原 verification/state.json 保留且排除提交；前序清理被拒目录未动。
