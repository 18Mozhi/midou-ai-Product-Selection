# 商品价格与费用适用范围解耦

## 现状与修复

用户要求主品找到 1688 货源后形成采购价格，不能让旧手机壳试运行范围阻断通用品。此前自动评估在查询货源和保存价格之前检查费用规则；没有费用规则、不属手机壳或费用政策未齐时，已有真实商品价格也不会写入成本详情。

现在先沿当前主品与当前机会找货任务读取证据，按既有规则记录 Amazon 售价和符合既有匹配条件的 1688 采购价，再检查费用范围、物流及汇率是否支持利润计算。售价不依赖匹配成功；无有效采购匹配时不写采购价。无适用费用仍发布非利润证据评分，利润输入保持未知，不排利润任务、不据此推荐，也不把商品算作每日合格百品。

沿用原价格版本表、确认模式、证据引用、观察时间、租户与事务：人工复核输入不覆盖；相同值、币种、证据和来源不重复建版本；写入失败回滚，不提交等待终态。没有新增数据库字段、环境变量、依赖、API 字段或事件名。

## 未改变的依据和边界

采购仍要求三个独立链接的有效报价、既有标题匹配置信度至少 80，保留 p75 及其选中链接证据；不将图搜第一条直接宣称同款。新人价排除、失效新报价不能回退旧价、跨机会证据不能借用的约束不变。通用品英文标题样例证明该流程能运行，不代表真实中英同款已验证；不同链接不等于不同工厂。真实跨语言匹配和一般品类费用仍须继续完成。

手机壳专用费用仍仅作用于原适用范围；未编造其他类目的运费、税费、佣金或汇率。历史成本和利润不批量重写；本轮只改变后续评估执行顺序。评分权重、推荐阈值与人工采纳不变。

## 使用与发布

继续通过现有选品自动评估和找货链运行。在选品详情“利润与成本”中可看到已记录售价、采购价及来源，即使没有利润运行也显示；利润区域保留数据不足提示。价格记录不代表完整到岸成本。

API `GET /api/v1/opportunities/{id}/profit-analysis` 原 `current_inputs` 已能在没有费用规则或利润运行时返回价格，Vue 原成本区已消费这些字段；无需改前端实现或 API 结构。没有 Python 任务输入或插件载荷变化。

本地 Worker/Backend 构建后通过项目固定 `python scripts/deploy-baota.py` 发布，宝塔唯一 Node 项目 `ai选品` 需重启：`/www/server/panel/pyenv/bin/python /www/server/panel/script/restart_project.py nodejs ai选品`。无需 Python 重启、配置调节或新服务。本轮未部署、未改生产数据或配置。

## 验证

新增测试覆盖通用品无费用规则、只有手机壳费用、未配物流政策、来源价格幂等、空价/不匹配/新人价不写采购、价格写入失败回滚、实际利润读取仓库返回价格且不要求费用规则。Vue 浏览器验证价格可见但无利润摘要，并回归利润读取失败、迟到响应及登录失效。夹具仅证明代码，不替代真实找货或持续采集验收。
