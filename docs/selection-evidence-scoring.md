# 自动证据评分与费用解耦

## 问题与行为

此前自动评估先要求活动费用规则，并校验手机壳专用费用范围；不满足便结束，市场、竞争、风险和数据质量也不评分。这会把不相关的费用条件变成通用品类的评分阻断。

现在仍要求当前工作区活动评分规则、有效 Amazon 主品证据和该主品快照。费用规则缺失、不适用品类、有效货源不足、费用政策未齐或利润运行未完成时，复用原 `crawler-evidence-v1` 公式写入有事实依据的非利润维度，并通过原评分任务计算覆盖情况。缺失评价等事实仍缺失；数据质量受阻时不提供可用分数。

利润输入保持 null，成本证据列表为空，缺失字段保存具体原因。利润缺失立即将待决策商品的旧推荐标为证据不足，不能暂借旧分数继续推荐。成功取到适用成本和有效利润运行后，仍走原完整评分。等待任务保持原等待、重试与租约行为；相同证据重复评估不新增相同评分输入或重复排队。

部分评分变更写入既有 `opportunity.automatic_quality_evaluated` 审计事件，保留公式版本、证据指纹和利润缺失原因。事务失败应整体回滚。没有新的事件名称或外部 API 字段。

## 保留的边界

- 活动规则决定维度、权重与推荐阈值，本项不创建或改写规则；测试权重仅用于夹具。
- 手机壳费用匹配、三个独立高置信度货源、新人价排除及人工确认成本保护不变；不将费用估值推广其他品类。
- 利润未知不等于零利润。五项推荐质量门和人工采纳不变，部分分数不能作为合格商品或每日百品验收。
- 没有新依赖、环境变量、数据库迁移、路由或 API 结构。前端与评分 Worker 继续消费原版本化输入和评分运行，不需要新增消费字段。

## 验证与运行

定向验证使用 `node --test tests/unit/automatic-evidence-scoring.test.mjs tests/unit/automatic-selection-evaluation.test.mjs`，覆盖通用品类、没有费用规则、质量阻断、评价缺失、重复评估、原手机壳计算与人工成本保护。新增 12 项、原自动评估 10 项，以及评分、利润、选品质量门和采集回归 91 项，共 113 个不同用例通过，0 跳过。新增用例还直接调用生产评分投影函数，证明缺成本时不会推荐，并覆盖写失败回滚与审计记录。Worker/Backend 编译、文档/路由地图、静态分析通过。没有重跑无关的历史截图套件，也不将本地夹具当作生产运行证明。

本项未创建临时脚本、截图、报告或服务。此前被自动审批拒绝删除的手机截图仍在 `.artifacts/playwright/m04-06-sourcing-source-pri-e85d8-elabelling-confirmed-quotes-mobile-390/sourcing-price-conditions.png`，未绕过该拒绝。已有 `verification/state.json` 改动不提交。
