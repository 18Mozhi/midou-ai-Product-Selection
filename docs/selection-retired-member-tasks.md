# 成员业务任务界面退休

## 需求与当前行为

用户要求成员功能只保留连续情报、商品发现、主品与 5–10 竞品分析、评分、1688 找货和选品库。此前只移除了新建入口，旧今日工作、全部任务、任务详情仍保留指派、进度编辑、评论、批量操作和导出。这些界面现在整体退休。

删除 TaskWorkspace、五个专用子组件、任务类型文件、页头样式和两份专用样式及 token，共 11 个运行文件；共享成员样式中的失效任务规则同时删除。运行注册表不再载入任务组件。

- /work 固定转到 /home。
- /tasks 和 /tasks/:taskId 固定转到 /opportunities。
- 旧查询、哈希不带入目标，不能恢复编辑器。目标继续使用其现有权限检查，不以旧 task:read 代替选品权限。
- 商品评分保留历史阻断状态、下一步和进度说明，删除通往旧任务编辑器的链接。后端 task_id、task_status、progress_percent 等历史字段保留；仅将“可查看任务记录”的旧指引改为缺少有效证据的事实说明。
- 全局搜索不再联合旧 tasks 表，search_documents 中历史 task 投影在分页前排除；不删除投影数据。resource_type=task 仍兼容接受，真实仓储返回空结果，参数枚举不改。浏览器删除旧任务选项和专用状态映射；机会、证据和采集任务搜索保留。

## 保留范围

/tasks/approvals 独立审批界面、/org-admin/approvals 组织审批、后台采集任务、任务后端 API、权限、组织数据、审计和历史通知均保留。旧通知里的业务任务地址按同一固定跳转处理；审批地址不被动态任务别名吞掉。不会修改数据库、迁移、运行密钥、依赖、来源状态、任务租约、评分规则或现有业务任务终态。

既有业务任务服务和仓储测试继续验证当前后端；已退休前端的历史结构检查从固定 d206bb018442bb2d4d24fc92c85de6fe41c55a7a Git 对象只读获取，明确标识为历史，不能算当前批准或重新放回产品。旧截图与批准登记保持原样。八个旧捕获命令在启动服务或创建输出前拒绝任务界面捕获。

## 验证与使用

旧书签直接跳转核心工作区，无任务 API 读取、写入和缓存界面；缺少目标权限时继续拒绝。商品阻断事实不因删除链接消失。组织审批回归需确认 /tasks/approvals 仍可使用。

先验证删除/跳转/归档/搜索 SQL 参数和捕获拒绝，再运行桌面手机实际 Vue 路由、商品、搜索及审批回归，以及相关 Node 合同和构建。模拟 UI 不能代表真实业务数据；只读 MySQL 核验与正式发布记录另行区分。

无新增配置或环境变量，env.example 不适用；Python 任务合同未改。需要通过既有宝塔脚本重建 Web/API 运行包并重启唯一 Node 项目 ai选品，浏览器刷新静态资源；Python 不需要因本项独立重启，整体部署按官方脚本执行。此项不是全站 UI、数据完整度或每日百品验收完成。
