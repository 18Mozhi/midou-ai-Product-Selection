# 商品详情直接查看货源报价

依据用户“情报—Amazon主品与5至10竞品—评分—1688货源—选品库”流程，原商品详情只显示关联找货与候选数量，查看规格报价还要跳到供应链工作台。本轮在已有“货源与利润”分区加入只读货源报价表，保留原利润、成本及人工复核。

## 数据与使用

父工作台保留既有GET /api/v1/sourcing/searches读取，将input_type=opportunity且input_ref严格等于当前商品ID的记录传入新OpportunitySupplyPanel。用户打开货源与利润后才GET /api/v1/sourcing/searches/{id}；默认取既有服务created_at/id倒序返回的第一条关联记录，不额外排序报价。通过“找货记录”切换历史记录，一次只读选中的一条，无逐条扇出、预取或新轮询。API返回的id、input_type、input_ref再次全部验证，不一致不展示。

表格展示供应商、商品标题、规格、报价与币种、原始报价说明、MOQ、交期、地点、原始货源链接、采集时间以及可展开证据。null保持未提供，0保持0。detail.1688.com标识1688；其他合法公开货源保留，不冒充1688。外链只允许无内嵌凭证的HTTPS URL，不展示可执行协议链接。已有报价使用API的当前报价值，附保存版本及报价证据；未保存者明确为采集报价。候选关联不等于同款确认，不进行币种、单位或规格换算，不直接修改采购价、利润或推荐。

没有sourcing:read时不发列表或详情请求。列表失败、详情失败、空记录和读取中分别呈现，失败可显式重试，利润仍独立可看。切换找货记录/商品/分区、停用缓存页或卸载时取消请求并按代次拒绝迟到响应；重新激活后重读。所有请求继续使用现有鉴权客户端和后端组织、工作区作用域。
