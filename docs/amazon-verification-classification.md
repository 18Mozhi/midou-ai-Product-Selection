# Amazon 验证页面的错误分类

## 真实依据

2026-10-18 生产标准健康页曾返回 HTTP 200、2238 字节、空白标题、零 ASIN，head 中为 refresh meta，URL 含 `bm-verify` 参数。原解析器将其归类为 source_changed，会使 Worker 执行页面结构变化的全局停用流程。它实际是访问验证页面，不是商品事实，也不能证明解析模板发生变化。

同日 05:45 北京时间的真实健康检查恢复 ready，已使用现有配置服务将 Amazon 从停用版本 12 恢复为启用版本 13。此后自然队列已有成功采集。历史 Porsche 目标的原失败 HTML 未保存，仍不能断言其原失败原因。

## 修复边界

仅在 Amazon 商品解析入口检查真实 head 中的 refresh meta，其目标明确含 `bm-verify` 查询参数时，使用既有 permission_denied 分类并停止事实解析。属性顺序、大小写、空格、单双引号及实体编码不影响该识别。注释或脚本中的示例标签、描述中提及该字样、普通 refresh 不触发。

- 不请求 refresh 目标，不提交验证参数，不解码或执行验证，不重试该拒绝页面，也不用控制页商品替换目标。
- 即使页面含商品形似标记，也不保存为事实、不评分、不计整链完成。
- Worker 继续记录访问失败、保留原熔断阈值和权限保护，只是不误入 source_changed 的结构停用流程。
- 无识别标记的未知 HTML 仍按原结构失败处理，保留结构停用及审计。
- 适配器版本升为 `amazon-public-product-adapter-v9`；字段解析版本仍是 `amazon-public-product-v5`。

## 验证与运行

`tests/unit/amazon-verification-page.test.mjs` 使用脱敏的合成刷新标记验证拒绝及反例；`amazon-target-drift.test.mjs` 同时覆盖 Worker 不写事实、不执行结构停用、仍增加访问失败计数。原局部解析失败、控制页策略及真实结构变化检查保留。

运行入口、环境变量、API 字段、OpenAPI、数据库、前端和 Python 合同无变化，无新增配置项或依赖。正式发布需重建并通过现有宝塔部署脚本更新 Node；启动不自动批准、启用或恢复熔断。来源恢复仍需真实健康检查及现有审计服务。

米兜本次停用影响的 30 个旧情报任务状态为 failed_terminal，既有手工回放服务只接收 dead_letter。本修复不扩大回放权限、不修改任务终态、不伪造成功；受控补采仍须另行完成。健康恢复和自然任务成功不等于已经取得主品、5–10 个竞品、评分与货源的完整链路，日百品验收仍未完成。
