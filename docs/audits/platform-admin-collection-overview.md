## 问题记录

### P39-01（P1）50 条上限使历史尝试和死信不可达

- 所属页面 / 类型：采集总览 / 核心运营事实完整性。
- 复现步骤：准备超过 50 条尝试和死信，选择“全部时间”。
- 预期 / 实际：应到达全部记录；修改前接口和页面固定只返回 50 条且无总数、页码或下一页。
- 截图 / 日志：修改前全页；数据库最初 66/58，而接口为 50/50；修改后随 Worker 生命周期增长为 75/59，页面分别为 50+25、50+9。
- 涉及文件 / 接口 / 数据：控制台组件、服务/仓库/路由、OpenAPI；console GET；attempt/dead-letter 表。
- 影响范围 / 等级：历史故障、重试和死信遗漏，P1。
- 修复建议 / 验收：独立服务端分页、精确总数和 URL 页码；全部事实可达、刷新保持，已通过。

## 单页优化方案与不变能力

- 页面定位 / 使用者 / 核心任务：平台采集运营总览；运营管理员先判断“哪个来源受阻、根因是什么、哪些事实需要下钻或安全重放”。
- 应保留：精确原始错误码、来源/组织/工作区过滤、24h/7d/30d/all、来源和尝试技术详情、质量摘要、6 个受控页面链接、单任务重放事务、幂等键、影响确认和历史保留。
- 应删除或合并：不删除业务字段或功能；只把散落的刷新/范围反馈合并到页面首部，把两个大集合各自补齐分页。
- 新信息架构：标题与可靠刷新 → 可见范围筛选 → 受控页面链接 → 来源/状态/质量 → 精确根因 → 尝试分页 → 死信分页与批处理 → 观测时间/request_id。
- 主要操作：刷新、应用/重置范围、根因下钻、翻页、查看详情和确认批量重放；次要操作为列设置、密度和技术详情。
- 状态设计：首次 loading/empty/error/expired/forbidden/blocked；已有事实刷新失败/离线/超时均保留旧数据；每个事实区有独立空态。
- 动效与反馈：不增加装饰动效；使用按钮 busy、live alert、焦点聚焦/返回和确认对话框，避免信息密度损失。
- 响应式：1440 双列事实区，1180 以下单列，760 以下数据卡，390 筛选抽屉；所有页面宽度无横向溢出。
- 权限差异：`platform:operate` 是页面与接口真实边界；批量写操作继续由单任务路由校验 `collection:replay`，不靠隐藏入口授权。
- 数据状态变化：console GET 只读业务事实并写读取审计；只有确认重放写原任务/死信、新任务、事件、Outbox 和 operation。
- 与其他页面联动：不复制来源配置、任务详情、浏览器运行或数据质量写能力；全部使用现有链接和真实接口。
- 验收标准：全部事实可分页到达；URL 恢复范围；15 秒失败保留事实；blocked 语义正确；20 条上限无漂移；双击只执行一轮；三档分辨率无溢出；权限与审计可验证。
