## 页面定位与证据

- 页面：采集调度；路由：`/platform-admin/crawler-scheduler`；组件：`CrawlerSchedulerCenter.vue`。
- 使用者：具备 `platform:operate` 的平台运维角色；平台超级管理员本地隔离测试账号已验证。

- 证据环境：隔离 MySQL 5.7、Redis、API、Worker、Python Crawler 与真实浏览器；未连接生产，未触发真实第三方采集、通知、支付或不可逆操作。

## 问题记录

### CRS-P1-001 并发刷新与失败覆盖已核验事实

- 类型/等级：功能、可靠性、性能 / P1。
- 复现：成功加载后连续点击刷新，并让后续 GET 阻塞、429 或 503。
- 预期：一个在途请求，旧快照保留，失败可重试。
- 原实际：按钮可连续点击，多个 GET 可并发；刷新进入加载态并隐藏已核验事实，后返回响应可覆盖新结果。
- 修复：页面实例单飞、序列和 AbortController、15 秒上限、在途禁用；非权限失败保留快照并显示 request_id。
- 影响/API/数据：采集调度 GET；只读事实和读取审计，无数据库结构变化。
- 验收：真实锁等待证明原按钮未禁用且 loading 替换结论；双项目 E2E 验证单飞与快照保留。

### CRS-P1-002 无服务端读取上限且取消后可能晚写成功审计

- 类型/等级：接口、性能、审计一致性、安全 / P1。
- 复现：阻塞 `crawler_scheduler_leases` 查询或使 MySQL/受控目录失败。
- 预期：有界 503、错误脱敏、取消后不写成功观测/审计。
- 原实际：GET 无上限；客户端离开后查询链可能继续并写入成功事实；依赖异常落入通用 500。
- 修复：14 秒 API 上限、连接关闭 Abort、九组事实复用一个只读可重复读连接、查询阶段与事务提交前中止检查、稳定脱敏错误码。
- 验收：Node 定向测试覆盖超时、Abort、依赖 503 无 SQL/凭证泄露和取消后 record=0。

### CRS-P1-003 恢复成功可被后续刷新失败覆盖

- 类型/等级：功能、幂等与操作反馈 / P1。
- 复现：恢复 POST 成功，紧接的 GET 返回网络或 503。
- 预期：操作成功事实、旧快照和刷新失败同时可见；结果不确定的重试复用原幂等键。
- 原实际：恢复后 `load()` 清空消息并切换失败态；每次用户重试生成新键，无法安全确认不确定结果。
- 修复：成功消息与刷新错误分离；网络/5xx 保留操作幂等键，明确 4xx 或成功后释放；提交函数有重复执行守卫。
- 验收：桌面与移动 E2E 验证 POST 仅一次、成功消息和 ready 快照在后续 GET 503 时仍可见。

### CRS-P2-004 启用来源全量直出导致操作路径过长

- 类型/等级：UI、性能与企业级可用性 / P2。
- 复现：真实隔离库启用 144 个来源后打开页面；桌面双列和 390px 单列均需滚动极长距离才能到达回执、趋势与告警。
- 证据：`after-desktop-1440.png` 与 `after-mobile-390.png` 的完整页面截图；接口真实返回 `providers.length=144`。
- 预期：不丢字段和来源的前提下，可按来源 code/名称、熔断、排队、活动租约和风险快速定位，并能直接跳到后续全局面板。
- 当前实际：固定按 code 排序后全量渲染，无搜索、筛选、折叠、分页、虚拟列表或面板锚点；新用户难以确认应先处理哪个来源。
- 影响/API/数据：来源配额区；未来如采用服务端分页会涉及 GET 查询参数和总数合同，当前批次未获授权，未修改。
- 优化与验收：优先增加客户端关键词搜索、熔断/排队/风险筛选和“仅看异常”，再按真实性能决定 20/50/100 分页或虚拟列表；顶部保留总来源/命中数量和清除筛选，URL 保存筛选状态，键盘可达；任一来源的现有全部字段、解除熔断入口与排序事实不得丢失。144 个来源下首屏交互稳定，三次以内操作可定位异常来源并跳到告警区。

## 页面级优化方案与验收标准

页面定位、角色和核心任务保持为“先判断单机采集是否可继续，再下钻来源/租约/回执证据”。保留全部来源字段、排队摘要、进程与租约关联、资源/回执/趋势/告警、强确认恢复和技术详情；不删除或合并业务能力。当前批次信息架构仍为结论 → 四项指标 → 来源与档案 → 回执 → 趋势 → 活动关联 → 告警，仅在页头后增加刷新失败横幅。后续页面级布局应在来源区标题下增加关键词、异常/熔断/排队筛选、重置、命中数和分页或虚拟列表，并提供“回执 / 趋势 / 活动租约 / 告警”锚点；主要操作仍是刷新，危险次要操作是回收过期租约，单来源恢复只在真实熔断时出现。

加载、空、错误、超时、无权限、成功和失败反馈各自独立；刷新失败不改变旧数据状态，权限失败清除数据。桌面保持双栏和高密度来源卡，390px 单列，不隐藏风险、数值或 CTA。验收要求：一个在途 GET；客户端 15 秒/API 14 秒；依赖错误脱敏；取消不写成功审计；恢复幂等且反馈不丢；`platform:operate` 不变；Node Worker=1、Python Crawler=1、来源并发=1、数据库结构和 Worker/Crawler 生命周期不变。
