# `/platform-admin/governance` 逐页面 UI 与功能审计

审计批次：页面 42；环境：仅本机隔离 MySQL 5.7、Redis、Node API、Node Worker、Python Crawler 与 Vite；测试账号为本地临时账号。本文不记录密码、Cookie、Token、密钥或完整个人数据。

## 页面记录

1. 页面名称和路由：平台后台 / 数据治理 / 质量与规则，`/platform-admin/governance`。
2. 服务角色：具备 `platform:operate` 的平台超级管理员和平台运营管理员；普通成员、仅安全角色与未登录用户不可读。
3. 业务目标：跨组织核对评分、费用风险、审批模板、自动化、发布回滚和来源配置版本事实，再进入原业务工作台执行受控写操作。
4. 当前截图：修改前桌面 `output/playwright/platform-admin-governance/before/desktop-current.png`，修改前 390px `output/playwright/platform-admin-governance/before/mobile-current.png`，修改前移动详情 `output/playwright/platform-admin-governance/before/mobile-detail.png`；修改后桌面 `output/playwright/platform-admin-governance/after/desktop-1440.png`、桌面详情 `after/desktop-detail.png`、移动首页 `after/mobile-390.png`、移动筛选 `after/mobile-filter.png`、移动详情 `after/mobile-detail.png`。
5. 可操作入口：刷新事实、搜索、状态筛选、应用筛选、重置、五个治理分类、上一页、下一页、查看详情、技术详情、当前分类工作台、来源版本管理、关闭详情。
6. 控件结果：见“逐功能记录”；任何通过项必须同时具备浏览器、网络请求或日志证据。
7. 调用接口：`GET /api/v1/platform/management?domain=governance&section=<section>&page=<page>&page_size=20&query=<query>&status=<status>`；只读、`private, no-store`。
8. 数据表：`score_rules`、`cost_rules`、`approval_templates`、`automation_rules`、`deployment_releases`、`provider_versions`，并通过组织/工作区外键读取展示名。
9. 权限和隔离：平台全局只读面，API 强制 `platform:operate`；不依赖当前组织会话，不返回凭证或原始爬虫 payload；本页没有跨租户写入口。
10. 正常状态：摘要、当前分类 20 条以内记录、事实时间、分页和工作台入口同时可见。
11. 空数据状态：保留摘要与分类，列表显示“当前分类没有匹配记录”，分页显示 0 条，可重置筛选。
12. 加载状态：首次加载显示“正在读取治理事实”；后台刷新禁用重复触发但保留已有事实。
13. 接口失败状态：首次失败显示恢复动作；已有事实刷新失败保留上一份结果并显示可操作提示。
14. 超时状态：浏览器等待 15 秒后安全取消，保留上一份事实并明确说明。
15. 无权限状态：403 显示无平台治理权限；安全角色直接 API 403，未登录 401。
16. 表单校验：搜索最多 120 字；服务端拒绝缺失/未知分类、跨分类状态、无效页码和每页数量。
17. 重复提交：刷新、切换、筛选和分页在请求进行中禁用，单飞处理。
18. 刷新和返回：分类、已提交搜索、状态、页码写入 URL；刷新及浏览器返回恢复同一范围。
19. 分辨率：验证 390×844、768×1024、1024×768、1440×900；760px 以下使用摘要卡和具名详情抽屉，不出现横向宽表。
20. UI/交互问题：修改前摘要计数受 40/30 条 SQL 上限截断、页面一次渲染 40 条、状态选项混用且重复、原始状态未翻译、URL 不持久化、刷新覆盖旧事实、发布版本显示 `v—`、通用“编辑”入口语义不实。
21. 功能问题：修改前无法看到第 41 条后的治理事实；分类切换后同一状态可能形成非法或无意义筛选；刷新会丢失当前分类和筛选。
22. 性能问题：修改前一次并行读取五张列表并渲染大表；修复后只读取当前分类一页，摘要使用单条计数查询。
23. 安全问题：未发现本页返回秘密；继续要求技术编号默认折叠、平台权限失败关闭、查询使用参数绑定与固定分类 SQL 白名单。
24. 企业级缺失项：本页不提供批量修改、直接发布、直接回滚或审批，属于有意边界而非缺失；原模块承担版本锁、审批、幂等、审计和写权限。
25. 优化建议：保持只读核对定位；后续若新增跨模块变更编排，必须先形成独立业务契约和审批模型，不应在本页拼接现有写 API。

## 页面优化方案

- 页面定位、使用者、核心任务：平台运营与超级管理员在一个只读索引中发现当前治理版本和异常状态，再进入责任工作台。
- 应保留：五类事实、来源版本摘要、组织/工作区、状态、版本、更新时间、详情、原工作台入口、权限与审计声明。
- 删除或合并：删除跨分类混合状态列表；不再一次加载五类大列表；把发布、审批等非自动化行的“编辑”改为真实的“进入工作台”。
- 信息架构：顶部目标与刷新/工作台；全量摘要；分类；当前分类筛选；当前分类分页结果；来源配置版本；权限与事实时间。
- 新布局：桌面保持高密度表格；移动端为单列摘要卡和详情抽屉。摘要不参与当前筛选，使用“总量”明确其口径。
- 主要操作：切换分类、应用筛选、查看详情、进入工作台。次要操作：刷新、重置、分页、技术详情、来源版本管理。
- 表格字段：名称、组织/工作区或阶段、类型、状态、真实版本、更新时间、操作、折叠技术信息。
- 筛选条件：名称/版本/组织/工作区关键词与当前分类真实状态；筛选草稿在提交前不改变已展示结果。
- 表单字段：搜索 0–120 字、分类固定枚举、状态按分类固定枚举、页码正整数、每页 1–100（UI 固定 20）。
- 弹窗/抽屉：桌面原生具名详情弹窗；移动端响应式具名详情抽屉；Escape/关闭后焦点回到触发按钮。
- 各种状态：首次加载、背景刷新、空筛选、401、403、400、503、网络离线、15 秒超时均有独立且不误导的反馈。
- 成功/失败反馈：成功更新事实时间和请求编号；失败保留旧事实，提示恢复动作，不把旧事实标成最新。
- 动效：沿用系统已有抽屉/弹窗过渡，不新增妨碍高密度核对的装饰动效。
- 响应式：760px 以下表格替换为卡片；筛选进入抽屉；操作按钮占满可用宽度；技术编号仍折叠。
- 权限差异：平台运营和超级管理员读取相同全局治理事实；本页不扩大两者的写权限；其他角色失败关闭。
- 页面联动：评分、费用、审批、自动化、发布、来源版本分别进入现有工作台，URL 只携带现有工作台支持的参数。
- 接口及数据状态：本页只读 GET；状态变化必须在原模块提交后，通过本页刷新重新读取 MySQL 事实。
- 验收标准：真实 55 条分类数据能以 20/20/15 三页读取；摘要显示 55 而非 40/30；非法状态 400；401/403/503 可验证；URL、刷新、返回、移动抽屉、桌面弹窗、控制台和服务日志均通过。
- 不应改变：业务写入口、版本锁、审批、幂等、审计、表结构、来源采集和 Worker/Crawler 生命周期。

## 问题记录

### GOV-P1-001（P1）治理事实被硬上限截断

- 所属模块/类型：治理中心 / 核心事实完整性。
- 描述：修改前各规则列表最多 40 条、发布最多 30 条，摘要直接使用返回数组长度；真实 55 条时仍显示 40/30，第 41 条后不可访问。
- 复现：隔离库每类写入 55 条；读取治理接口并核对页面摘要与行数。
- 预期：摘要为真实总数，所有记录可分页访问。
- 实际（修改前）：摘要 40/40/40/40/30；首屏一次渲染 40 条且无分页。
- 证据：修改前截图；API 基线响应；Node API 日志；隔离 MySQL COUNT。
- 涉及文件：治理组件、平台 Dashboard service/routes/MySQL repository、OpenAPI、Feature Map、测试和本文。
- 涉及接口/数据：GET platform management；五张治理表和 provider_versions。
- 影响：平台运营无法核对被截断规则与发布事实，可能误判治理覆盖。
- 建议：当前分类独立 COUNT + 参数化 LIMIT/OFFSET；摘要使用无截断 COUNT。
- 验收：55 条显示总量 55，三页 20/20/15，页码越界安全归一。
- 修复后实际：摘要 55/55/55/55/55，三页返回 20/20/15；`page=999` 归一到第 3 页。结论：已修复并通过。

### GOV-P2-002（P2）筛选状态与页面上下文不一致

- 所属模块/类型：治理中心 / 功能与可理解性。
- 描述：修改前所有分类共用混合状态，存在重复“启用”，缺少待审批/驳回/发布阶段，部分状态直接显示英文。
- 复现：切换五分类并打开状态筛选；观察列表中的 pending_approval/rejected。
- 预期：只显示当前分类可用状态且中文可读；服务端拒绝跨分类组合。
- 实际（修改前）：选项混合且重复，非法组合可提交，原始状态暴露。
- 证据：修改前桌面/移动截图和浏览器 DOM 取证。
- 涉及接口/数据：GET platform management；各表 status。
- 影响：筛选无结果且原因不明，治理状态被误读。
- 建议/验收：分类状态白名单前后端一致；跨分类状态 400；页面无原始状态值。
- 修复后实际：五类选项与真实集合一致，`automation_rules + approved` 返回 400，页面无原始英文状态。结论：已修复并通过。

### GOV-P2-003（P2）刷新丢上下文且失败覆盖可用事实

- 所属模块/类型：治理中心 / 恢复能力。
- 描述：修改前分类、搜索、状态和页码不写 URL；刷新回到评分规则；后台刷新失败会清空已加载事实。
- 复现：切到自动化并筛选暂停，刷新；或加载后停止测试数据库再刷新。
- 预期：URL 与结果一致，失败保留旧事实并说明时间/恢复动作。
- 实际（修改前）：URL 不变，刷新重置；失败切换整页错误态。
- 证据：修改前浏览器 URL/页面取证；依赖故障回归日志。
- 涉及接口/数据：GET platform management；无写数据。
- 影响：运营核对范围不可复现，短暂故障降低可用性。
- 建议/验收：URL 状态、15 秒取消、单飞、已有事实保留与事实时间全部可验证。
- 修复后实际：页 2 和中文筛选刷新保持；离线、15 秒超时及真实 MySQL 停止均保留 20 行和原摘要。结论：已修复并通过。

### GOV-P3-004（P3）版本与操作语义不准确

- 所属模块/类型：治理中心 / UI 内容准确性。
- 描述：发布记录使用通用 revision/version 字段显示为 `v—`；审批、版本代码和构建号混用；非自动化记录统一称“编辑”。
- 复现：切到灰度与回滚、审批工作流并检查版本列和操作。
- 预期：不同分类使用真实版本事实；只有支持深链编辑的自动化称编辑，其余为进入工作台。
- 实际（修改前）：发布版本缺失、入口承诺过度。
- 证据：修改前页面与字段响应。
- 影响：用户无法正确核对发布构建，也可能误以为本页直接编辑。
- 建议/验收：版本按分类格式化，工作台入口与实际能力一致。
- 修复后实际：评分/费用/审批/自动化显示业务修订号，发布显示应用版本，构建 SHA 与版本代码默认折叠；只有自动化使用“编辑规则”。结论：已修复并通过。

### GOV-P2-005（P2）中文搜索触发 MySQL 排序规则冲突

- 所属模块/类型：治理中心 / 接口国际化与数据库兼容。
- 描述：首次真实回归发现中文 `query` 与状态联合请求返回 503；直接仓储诊断为 `ER_CANT_AGGREGATE_2COLLATIONS`，ASCII 技术列与 utf8mb4 参数执行 `LIKE` 时冲突。
