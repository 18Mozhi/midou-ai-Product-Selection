## 联合流程测试

### 链路 A：平台事实 → 页面 → 筛选 → 导出 → 审计

- 前置条件：隔离 MySQL 5.7、Redis、API、Worker、Crawler、Vue 全部运行；平台超级管理员本地登录。
- 操作步骤：读取 129 条/实体事实 → 切换机会 → 筛选已采纳 → 翻第 2 页 → 刷新 → 导出 → 检查 CSV → 查询平台审计。
- 预期结果：页面只展示当前筛选最近 100 条并按 20 条分页；刷新保持；导出范围一致、防公式注入；审计记录操作者、筛选、原因和行数。
- 实际结果：机会 adopted 32 条，第 2 页 12 条且刷新保持；CSV 101 行、BOM/公式保护通过；审计 row_count=100。
- 涉及页面 / 接口 / 数据：本页；management GET、export POST；四类业务表、组织/工作区和 platform_audit_events。
- 后台任务 / 日志：Worker 与 Crawler 同时健康运行；本链为同步只读/导出，不伪造 Worker 领取。
- 结论：通过。

### 链路 B：业务深链 → 证据 → 下载 → 质量治理 → 审计

- 前置条件：3 份真实本地证据文件、规范记录、字段溯源、核对运行和开放问题。
- 操作步骤：`evidence_id` 深链 → 详情 → 下载授权/下载 → 核对运行下钻 → 单条解决 → 批量归因/指派/关闭。
- 预期结果：深链直接进入目标视图；文件校验后下载；治理只追加原因、状态、事件和审计，不删除证据。
- 实际结果：证据详情与文件下载成功；核对运行下钻 7 条；单条解决和三类批处理均返回成功，原证据仍存在。
- 涉及页面 / 接口 / 数据：质量子视图；data-quality、evidence、resolve、batch；raw_evidence、file_assets、normalized_records、field_provenance、reconciliation_runs、data_quality_issues。
- 后台任务 / 日志：当前治理同步写 MySQL；未触发真实第三方请求或通知。
- 结论：通过。

## 问题记录

### P41-01（P1）四类页面状态与数据库真实状态不一致

- 所属模块 / 类型：全量记录 / 功能与数据语义。
- 复现：依次打开机会、竞品、供应商；观察大量“其他状态”，选择页面旧状态后返回空。
- 预期 / 实际：应按表字段可筛选；修改前机会使用 draft/reviewing/approved 等错误集合，竞品和供应商同样错配。
- 证据：修改前状态截图与四接口真实状态集合。
- 涉及文件 / 接口 / 数据：页面、service；management GET；decision_status、competitors.status、sourcing_candidates.status。
- 影响 / 等级：核心平台数据筛选不可相信，P1。
- 修复 / 验收：按实体固定真实状态字典，API 拒绝错配；四实体无“状态未知”且非法组合 400，已通过。

### P41-02（P2）最近 100 条一次性渲染，移动端形成超长列表

- 复现：390px 打开供应商；修改前一次渲染 100 张卡。
- 预期 / 实际：受控列表应分页；修改前页尾只有“最多 100 条”说明，无分页。
- 证据：修改前/后移动截图。
- 涉及：页面与质量子视图；无数据库结构影响。
- 影响 / 等级：移动可用性和 DOM 成本，P2。
- 修复 / 验收：业务事实 20 条客户端分页；质量 API 使用 20 条服务端分页；390 无溢出，已通过。

### P41-03（P1）`evidence_id` / `issue_id` 隐藏入口落到错误视图

- 复现：从机会或发现链进入 `/platform-admin/data?evidence_id=...`。
- 预期 / 实际：应打开证据或问题；修改前父页固定显示业务记录，子页只识别 `evidence`。
- 证据：修改后证据深链截图和 issue 精确查询 1 行。
- 涉及：两个页面组件；证据详情 API；证据与质量表。
- 影响 / 等级：业务到证据的关键链断裂，P1。
- 修复 / 验收：三种 evidence/issue 参数自动切质量视图并定位，已通过。

### P41-04（P2）刷新/失败/超时清空已验证事实

- 复现：已有数据时刷新并停止数据库或挂起请求。
- 预期 / 实际：应保留旧事实；修改前 state 立即 loading，失败后表格消失且无超时取消。
- 证据：数据库失败与超时截图。
- 涉及：页面请求状态；management GET；无数据写入。
- 影响 / 等级：平台排障时丢失最后观测，P2。
- 修复 / 验收：15 秒 AbortController、busy guard、失败保留旧事实，已通过。

### P41-05（P2）数据库断开返回通用 500

- 复现：真实停止隔离 MySQL 后读取管理数据。
- 预期 / 实际：依赖故障应 503；修改前 API 日志 statusCode=500。
- 证据：修改前后服务端日志，修改后 statusCode=503。
- 涉及：platform dashboard routes；management/export；MySQL 连接。
- 影响 / 等级：告警、重试和用户提示错误，P2。
- 修复 / 验收：仅已知数据库连接错误映射 `platform_data_dependency_unavailable`，认证/业务错误保持原码，已通过。

### P41-06（P2）未提交筛选草稿会改变导出范围

- 复现：输入搜索或切状态但不点筛选，直接导出。
- 预期 / 实际：导出当前已显示范围；修改前输入双向绑定到导出参数，页面与文件可能不一致。
- 证据：修改后 query/status draft 与 applied 状态分离测试。
- 涉及：页面与 export POST；审计 metadata。
- 影响 / 等级：受控导出范围不可核对，P2。
- 修复 / 验收：只用已提交筛选导出，重置/实体切换同步状态，已通过。

### P41-07（P2）导出缺少客户端同步重复提交锁

- 复现：同步双击“导出表格文件”。
- 预期 / 实际：只打开一个原因流程并发一个 POST；修改前函数入口没有 open/busy guard。
- 证据：浏览器实际 dialogCount=1、posts=1。
- 涉及：页面、export POST、platform_audit_events。
- 影响 / 等级：重复文件和审计噪声，P2。
- 修复 / 验收：原因弹窗打开或导出中直接返回，已通过。
