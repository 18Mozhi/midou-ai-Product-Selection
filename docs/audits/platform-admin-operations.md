# `/platform-admin/operations` 逐页 UI、功能与链路审计

## 页面审计记录

1. 页面名称和路由：备份恢复，`/platform-admin/operations`；平台后台 / 系统运维 / 备份恢复。
2. 服务角色：具备 `platform:operate` 的平台运营管理员、平台超级管理员。匿名真实 GET 为 401；本地测试账号临时降为平台安全管理员后，路由守卫和真实 GET 均为 403，随后已恢复超级管理员。
3. 业务目标：在惠州当前 S0 单机边界内核对最近备份、同机独立加密副本、RPO/RTO 和 90 天内隔离恢复演练。本页只读，不执行备份、恢复、清理或下载，也不代表整机、磁盘、机房或异地灾备。
4. 当前截图：修复前桌面 [before-desktop-1440.png](../../output/playwright/platform-admin-operations/before-desktop-1440.png)、修复前 390px [before-mobile-390.png](../../output/playwright/platform-admin-operations/before-mobile-390.png)、刷新悬挂并丢失快照 [before-refresh-hanging-mobile.png](../../output/playwright/platform-admin-operations/before-refresh-hanging-mobile.png)；修复后桌面 [after-desktop-1440.png](../../output/playwright/platform-admin-operations/after-desktop-1440.png)、超时保留 [after-refresh-inflight-preserved-mobile.png](../../output/playwright/platform-admin-operations/after-refresh-inflight-preserved-mobile.png)、停库保留 [after-mysql-unavailable-preserved-mobile.png](../../output/playwright/platform-admin-operations/after-mysql-unavailable-preserved-mobile.png)、恢复后 390px [after-recovered-mobile.png](../../output/playwright/platform-admin-operations/after-recovered-mobile.png)。
5. 页面所有可操作入口：刷新事实、失败后重新核验、会话失效后重新登录、面包屑、十个系统运维二级入口、平台主导航、主题、桌面列设置、列显示复选框、首列冻结、密度选择、桌面技术详情、390px 十个资产详情抽屉、抽屉关闭、移动端更多和返回用户工作台。本页没有搜索、筛选、排序、分页、写表单、上传、下载、导入、导出、删除、暂停、取消或恢复执行按钮。
6. 每个按钮和控件：见“前端功能测试结果”，逐项列出，不使用“其他按钮正常”。
7. 调用接口：`GET /api/v1/platform/operations/backup-recovery`；覆盖 200、401、403、429 合同、重复点击、真实锁等待超时、MySQL 停止、恢复、稳定错误码和脱敏。
8. 涉及数据表：`backup_recovery_runs`、`backup_recovery_assets`、`platform_audit_events`；权限链还涉及 session、role、capability 和 authorization decision 表。数据库结构没有修改。
9. 权限和数据隔离：平台全局只读聚合，不接受组织、工作区或租户参数，因此跨租户 ID 注入入口不存在；响应不返回组织/工作区明细、文件路径、文件名、哈希、主机、账号、Cookie、Token、密钥或凭证。
10. 正常状态：隔离 MySQL 5.7、Redis、Node API、Node Worker、Python Crawler 与 Vite 实际运行；页面显示 10 组本地合成资产、RPO 15 分钟、RTO 240 分钟、恢复副本和隔离演练核验。合成数据仅证明本地链路，不冒充生产恢复。
11. 空数据状态：无 runs 时服务返回 `empty`，页面显示尚无备份恢复记录；通过服务与 E2E 合同验证，未伪造真实空生产库。
12. 加载状态：首次无快照显示“正在读取备份事实”；已有快照刷新时事实保持可见，按钮显示“正在刷新…”，并具 `disabled` 与 `aria-busy`。
13. 接口失败状态：修复前真实停库产生非稳定 500 且清空旧事实；修复后连接类故障为 503 `backup_recovery_dependency_unavailable`，返回脱敏 action hint 并保留最后成功事实。
14. 超时状态：对 `backup_recovery_runs` 持有真实写锁；API 14 秒取消，浏览器 15 秒兜底，页面显示“刷新已超时”并保留 verified 快照。超时 request_id `f7a145b4-3a8d-408c-ae25-2f3366460837` 在锁释放后成功审计数仍为 0。
15. 无权限状态：匿名 401；缺 `platform:operate` 为 403，响应无 data。401/403 不保留旧平台事实；401 提供重新登录。
16. 表单校验状态：本页无表单和查询参数；RPO/RTO、区域、最大演练年龄等由后端既有配置校验。不存在的输入项不能标记通过。
17. 重复提交状态：修复前锁等待中两次刷新产生两个在途请求，审计总数由 2 增至 4；修复后单个 AbortController 阻止第二次点击和额外 DOM click。
18. 刷新和返回状态：成功刷新更新 observed_at/request_id；失败保留快照，依赖恢复后重新核验回 verified。面包屑到系统状态、浏览器前进/返回、reload 和多标签真实请求均不依赖 Mock 或 localStorage 事实。
19. 不同分辨率：1440×1000 与 390×844 实际打开并截图；桌面 `scrollWidth=1425 <= 1440`，390px `scrollWidth=375 <= 390`。390px 下 10 条资产均逐个打开详情抽屉并关闭。
20. UI 和交互问题：本批修复刷新闪空、重复触发、无界等待、失败缺少旧事实与会话失效缺登录动作；保留原有高密度业务布局。共享移动底部导航会覆盖靠近视口底部内容，作为范围外壳层基线记录，未越权修改。
21. 功能问题：修复前锁等待造成请求与审计放大，依赖错误语义不稳定；修复后单飞、有界取消、稳定 503、事务回滚和恢复重试闭环完成。
22. 性能问题：单次读取最多 20 条 runs 并按最近备份聚合 assets，现有界取消；未验证生产长期历史、50/100 并发、连接池饱和或正式 p95/p99，容量标记未验证。
23. 安全问题：授权成功读取才在同一事务写成功审计；取消和依赖失败不伪造成功。响应 `private, no-store` 且错误脱敏；未使用生产账号、真实通知、支付、第三方 Cookie 或不可逆恢复。
24. 企业级缺失：真实宝塔全量备份/PITR/隔离恢复生命周期、生产加密材料、正式容量、外部告警和长期审计归档仍阻塞。备用服务器、异地灾备和主机故障保护是当前明确不建设边界，不冒充已具备。
25. 具体优化建议：见“逐页面优化升级方案”；必须保留目标值、最近备份、恢复副本、演练核验、10 组资产、blockers、关联 ID、权限、审计和宝塔单机边界。

## 接口与联合流程

`GET /api/v1/platform/operations/backup-recovery` 正常为 200 稳定 envelope，无请求参数；匿名 401、无能力 403、通用限流 429、依赖与读取超时 503。平台接口不接受租户 ID；跨租户参数测试为不适用，而不是通过。响应不得含 SQL、驱动、连接、主机、账号、路径、文件名、哈希、组织明细或凭证。成功读取在一个 MySQL 事务内读取 runs/assets 并写 audit；取消或失败回滚，`private, no-store`。

联合链路：本地管理员登录 → 平台权限 → Web GET → API 鉴权/授权 → MySQL 读取最近备份和资产 → service 计算 RPO/RTO、恢复与演练状态 → 同事务成功审计 → 页面表格/移动卡片展示 → 锁等待超时保留 → MySQL 故障保留 → 依赖恢复重新核验。Node Worker 与 Python Crawler 实际启动且 Crawler 持续领取空队列 204；M07-04 备份/恢复由宝塔有限任务执行，不经过 Worker/Crawler。真实 Amazon、1688、供应链登录、验证码、代理、解析、清洗和入库不属于本页，不能据此标记通过。

## 问题记录

### BACKUP-P1-001 重复刷新、无界等待并丢失可信快照（已修复）

- 所属页面或模块：M07-04 Web/API/repository；问题类型：核心运维可靠性；严重等级：P1。
- 问题描述：可信 verified 页面在数据库锁等待时可重复刷新，整页退回 loading；同一操作者无法继续查看事故前事实，并放大请求与审计。
- 复现步骤：登录 → 打开本页 → 对 `backup_recovery_runs` 持有测试写锁 → 快速点击两次刷新。
- 预期结果：单飞、有界取消、旧快照保留、失败不写成功审计。
- 实际结果：修复前两个在途请求、页面闪空，锁释放后审计 2 增至 4；修复后额外点击无效，14/15 秒停止，旧 verified 可见，超时 request_id 审计数为 0。
- 截图或日志证据：`before-refresh-hanging-mobile.png`、`after-refresh-inflight-preserved-mobile.png`、API 请求日志与事务计数。
- 涉及文件：`BackupRecoveryCenter.vue`、backup recovery route/service/repository、M07-04 tests；涉及接口：上述 GET；涉及数据：runs/assets/audit。
- 影响范围：事故认知、连接池、锁等待、审计真实性；修复建议：本批 AbortSignal、single-flight、sequence、事务回滚；验收标准：额外 click 不增请求、15 秒内提示、迟到审计为 0、恢复可重试，已满足。

## 逐页面优化升级方案

- 页面定位、使用者、核心任务：平台运维角色在最短路径判断最近备份、同机恢复材料与隔离演练是否可信；不是恢复执行台。
- 当前问题与优化目标：刷新故障不能让可信事实消失或无限等待；已以单飞、有界读、快照保留和权限清除完成。共享移动导航另行处理。
- 应保留/删除或合并：保留所有业务事实、四项演练核验、10 组资产、blockers、时间和关联 ID；不删除能力，不新增网页恢复、下载密文或暴露路径。刷新和失败重试共用一套请求控制。
- 信息架构与新布局：保持“边界说明和刷新 → 总状态 → RPO/RTO → 最近备份与演练 → 资产 → blockers → 技术关联”；桌面表格、390px 摘要卡片与详情抽屉。
- 主要/次要操作：主要为刷新/重新核验；登录恢复为权限动作；列、密度、冻结、详情和导航为次要。忙态必须禁用且保留快照。
