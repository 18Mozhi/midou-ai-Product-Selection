# `/platform-admin/releases` 页面审计记录

## 页面定位与证据

- 页面：发布管理；路由：`/platform-admin/releases`；组件：`ReleaseRolloutCenter.vue`。
- 使用者：具备 `platform:operate` 的平台运维角色；平台超级管理员本地测试账号已验证。
- 业务目标：只读核验当前运行构建、迁移、发布观察门、停止阈值与回滚事实，不从浏览器发起发布或写探针。
- 数据链：页面 → `GET /api/v1/platform/operations/releases` → `ReleaseRolloutService` → `deployment_releases`、`deployment_release_gates` → `platform_audit_events`。
- 桌面截图：`output/playwright/platform-admin-releases/after-desktop-1440.png`。
- 390px 截图：`output/playwright/platform-admin-releases/after-mobile-390.png`。
- 本次证据来自本地隔离 MySQL 5.7、Redis、API、Worker、Python Crawler 与真实浏览器；未连接生产、未执行真实发布、支付、通知或外部采集。

## UI 与交互审计

- 信息架构：结论 → 三方版本身份 → 5/25/100 观察门 → 指标 → 固定阈值，符合“先决定能否继续发布，再查证据”的运维任务。
- 布局和层级：桌面高密度表格适合横向比较，移动摘要卡片避免压缩六列；技术标识默认折叠，业务状态中文化。
- 颜色和反馈：成功结论、危险状态和刷新告警区分明确；告警使用 `aria-live`，在途按钮使用 `aria-busy` 与禁用状态。
- 可读性和可访问性：按钮、链接、组合框具备可访问名称；移动详情入口为真实按钮。未执行完整 WCAG 审计，不能扩展为全站无障碍通过。
- 操作路径：正常核验只需进入页面；故障后原位重新核验，不要求重新导航。权限失效时直接进入登录恢复路径。

## 问题记录

### REL-P1-001 刷新可并发且失败清空事实

- 模块/类型/等级：发布管理 / 功能与可靠性 / P1。
- 复现：成功加载页面后连续点击刷新，并让后续 GET 返回 429、503 或网络失败。
- 预期：只有一个在途请求；旧事实可继续用于判读；提示失败并允许重试。
- 原实际：每次点击都发起请求，进入加载态并失去上次成功快照。
- 修复实际：按钮在途禁用，代码级序列保护；失败横幅保留快照并展示 request_id。
- 文件/API/数据：`ReleaseRolloutCenter.vue`；GET 发布事实；不写业务数据。
- 影响：平台运维在依赖抖动时可能失去刚核验的发布证据，重复请求还会放大数据库压力。
- 验收：E2E 断言调用数保持 2（初次 + 一次刷新），并验证失败后结论和 5/25/100 事实仍可见。

### REL-P1-002 读取无服务端上限且超时后可能晚写成功审计

- 模块/类型/等级：发布管理 / 接口、性能与审计一致性 / P1。
- 复现：阻塞发布事实查询，使浏览器等待超时或连接中断。
- 预期：服务端有界失败，取消查询链并且不形成本次读取成功审计；错误响应脱敏。
- 原实际：路由没有读取上限，两个查询和成功审计不在同一事务，客户端放弃后服务端仍可能继续完成。
- 修复实际：14 秒服务端上限、连接关闭取消、单连接事务、失败回滚；依赖和超时错误码稳定且脱敏。
- 文件/API/数据：release route/service/MySQL repository；GET；读取 `deployment_releases`、`deployment_release_gates`，成功时写 `platform_audit_events`。
- 影响：慢查询占用资源，并造成用户看到失败而审计记录成功的不一致。
- 验收：定向 Node 测试覆盖 503 脱敏、超时 Abort、成功提交和取消回滚；API/Web 构建与页面 E2E 通过。

### REL-P3-003 favicon 404

- 模块/类型/等级：共享外壳 / 控制台噪声 / P3。
- 证据：隔离浏览器控制台出现 `/favicon.ico` 404。
- 影响：不阻断发布页业务，但降低控制台信噪比。
- 建议/验收：在后续共享外壳批次提供有效 favicon 或显式响应；重新加载任意页面后不再出现 404。
- 本批次状态：范围外基线，未修改、未宣称通过。

## 本页优化方案与验收标准

页面定位、角色和核心任务保持不变：平台运维快速确认“当前构建是否具备可信发布事实”。保留三方 SHA、迁移、发布状态、5/25/100、五项指标、停止阈值、技术详情、列设置、冻结和密度；不删除、合并或改写这些业务能力。主要操作仍是“刷新发布事实”，次要操作是列/密度偏好和证据展开，不新增业务写入口。

本次新布局只增加紧邻页头的刷新故障横幅，不重排正常态信息架构。横幅显示失败类别、恢复建议、request_id 和重新核验；加载、空、阻断、陈旧、自动停止、回滚、错误、超时、无权限各自保持明确状态。响应式行为继续使用桌面表格、390px 摘要卡片与详情抽屉。权限差异由路由和 API 双层控制；数据状态只在成功 GET 后替换快照，失败不伪造新状态，401/403 清空快照。

验收标准：单飞刷新；客户端 15 秒、服务端 14 秒有界；失败保留成功快照；权限失败不泄露快照；取消或错误回滚审计；200/401/403/429/503 合同稳定且脱敏；1440px 与 390px 无关键内容遮挡；POST 写探针、数据库结构、发布阈值和宝塔单 Node 拓扑不变。
