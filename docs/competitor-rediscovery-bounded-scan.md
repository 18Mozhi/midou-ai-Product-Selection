# 自动竞品再发现的有界循环扫描

全局资格查询在隔离容量条件下超过20秒，按已有分类事件调整索引顺序的原型同样超过20秒，未发布该原型。真实1000阈值且积压1001时原查询23ms即返回空，因此并非所有空读都慢。当前变更针对容量释放后对所有机会一次性求主品、标题和详细相关性资格的开销，不调大容量、不重放任务。

## 调度与事实边界

每个Worker沿活动机会ID有序扫描最多20条，只限现有trend_topic且未archived/deleted记录，组织和工作区都必须active。在该批ID内执行原完整资格查询与原排序，仍只调度一个商品，保留原主品事实、精确标题、最近发现间隔、活动任务排除、至少5个独立详细相关竞品门及选中后的锁内去重。分页不是截断前20条后永远重读：没有合格结果也在事务提交后前进；扫到末尾，下次从头开始。

批次同时读取既有全局活动采集积压。达到AUTOMATIC_SOURCE_QUEUE_BACKLOG_LIMIT或计数异常时不执行昂贵资格读取、不推进游标；后续资格SQL仍再次核对同一阈值，防止仅依赖早先读数。进行中/并发/批次仍可能使总数短暂超过阈值，该设置不是原子硬预留。阈值默认1000不变。

游标和60秒扫描时钟仅在外层事务成功提交后更新，失败回滚不消耗批次；游标只在当前Worker内存中，重启从头扫描，没有数据库或持久化格式变化。原详情刷新和缺失主品/找货修复的入口、交替及优先级保持。资格仍使用既有COMPETITOR_REFRESH_INTERVAL_SECONDS间隔作为最早再发现时间，分页、容量与负载可能使实际调度更晚，不承诺一分钟遍历全部机会或日百品已经恢复。
