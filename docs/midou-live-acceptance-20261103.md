# 米兜智能选品：线上十一项逐条核验与修复

## 定位与原因

以已发布 `331b6ba999f093365af8c59ddd65e0fc10864da2` 为线上基线，沿 AGENTS → feature-map → 实际 Vue/仓库读取链核验。已有 Chrome 标签保留旧版 SCOUTOPS DOM；主动刷新后名称、原始 JPG Logo 和新布局出现，不能把旧标签未刷新误判为部署失败。

生产同一“米兜 / 默认工作区”只读仓库测量发现：候选页 14,367ms，其中计数 14,360ms；全部商品 2,600ms；找货 2,773ms。不是 HTTP 全链路或持续吞吐指标。原并行化未消除候选/采集中筛选中的重复身份关联。EXPLAIN 还确认活动版本派生表物化完整 payload（含不展示的大字段），找货商品名连接因转换被连接列而逐条扫描机会表。

修复仅改变查询计划：候选与采集中对原 pending 范围物化一次原主品身份，保留完整原质量门与外层筛选；分页继续复用该身份。物化活动版本只携带原证明/展示实际引用的列和 JSON 字段，不截断 ASIN/URL、改换记录、删除历史或更改优先顺序。找货先在原组织/工作区物化同一 UTF8MB4 Unicode 比较键，保留原大小写/排序规则、LEFT JOIN、生命周期条件和缺失回退，不直接把任意输入转成 ASCII。

## 使用、发布与未改边界

- 首页五步仅为证据导航，“查看进度”不伪造未开始/完成/运行状态。组织右栏只重用现有资料和既有受保护路由，不新增授权。
- 当前灰色操作色来自账号已保存的“石墨”主题，是用户偏好而非样式加载失败；需要参考图蓝色可在个人中心 → 外观偏好选择商务蓝，预览后自行保存。
- 无新增环境变量、依赖、数据库结构/索引、外部 API 字段或 Python 输入；`.env.example`、OpenAPI 无对应契约变化。不改 Worker/Python、来源恢复、重试或推荐/完成门。
- 本次 backend + frontend 需通过官方 `python scripts/deploy-baota.py --skip-build` 在隔离干净 main 发布，并由宝塔加载 Node；前端刷新生效。不要直接部署包含其他未发布采集改动的原工作分支。
- 真实第三方采集可用性、日吞吐和 95% 视觉签收与读取优化分开验收，不以静态/健康/fixture 通过替代。

## 验证记录

同一生产数据、第一屏 20 条的新旧只读实现对照（各一次，不是持续负载 SLA）：候选 14,438 → 3,455ms；采集中 15,186 → 2,082ms；全部 2,667 → 2,390ms；找货 2,739 → 835ms。候选总数 324、采集中 1090、全部 1414、找货 945；返回事实和排序逐项对照相同（仅排除随时钟变化的 lifecycle_dwell_seconds）。已完成与推荐均为空，约 17–34ms，不据空结果声称复杂业务已验收。

真实采集另有独立阻塞：本轮只读时 Amazon 商品来源 disabled、最近 source_changed；1688 enabled 但 circuit open，连续五次 network_error。Worker 状态文件心跳新鲜且 running，不能据排队任务推断 Worker 已停止。本工作区有 460 个 queued 和 33 个 blocked_captcha。未擅自启用来源、清除熔断、重放任务或绕过验证码；来源恢复需按原流程单独验证。数据库 Date 使用既有池解释，本记录不把历史 UTC 序列化时间直接当北京时间窗口过滤。

- 最小查询结构、参数绑定、原门保留和批量读取定向 20 项通过。
- 完整单测轮次未全绿：dot reporter 3731 个通过事件、5 个失败事件（含四个文件级加载失败）。一个是采集中旧 SQL 文本形状断言，已改为检查同一身份证明与原 NOT 门，24 项 SQL 回归通过；四个退役表面文件在功能地图生成期间加载失败，地图稳定后重跑 53/53 通过。保留原失败日志，不宣称重新跑过全量且全部通过。
- 实际隔离发布副本的 22 工作区构建通过，定向 SQL 20/20、文档/静态/格式/体积检查通过；浏览器最终在隔离副本服务上运行 32/32 通过。原分支与发布副本存在三份前序供应商对比重构源码差异，因此不把原分支的浏览器结果直接当作发布包验收，未夹带该重构。
- 桌面 1672×940、手机 390×844 参考工作区回归 22 项通过，含新增流程和治理栏断言。无横向溢出。
- 通知筛选归到同一条工作栏并增加原记录入口提示；个人资料身份卡保留可访问的账号标题，避免仅为消除重复页头而隐藏账号身份。更广的最终双端回归记录追加在交付账本，不改截图真实性阈值。
- 完整检查、同数据新旧读取、正式发布后复核的最终结果保存在原四角色交付目录的追加核验记录中；原失败/超时轮次不删除、不当作通过。
