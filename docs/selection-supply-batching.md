# 货源标题分批匹配与续租

1688采集已经能取得一页60条，但原自动评估只把过滤后的前10个报价交给分类器。若合格报价位于第11个之后，扩大后的候选池仍无法参与匹配。本项让当前单页容量进入原匹配路径。

## 行为与边界

仍先按货源ID取最新记录，排除无效时间、缺失标题/证据、非CNY、无效金额、新人价与手机壳备用路径。最多检查60个合格候选，每批最多10个、顺序调用，最多6批；先经过原词法/p75路径，只有需要时才调用分类器。

每批结果独立校验原文、属性和本批来源引用，不能拿其他批次的引用混入。合并的上下文仅包含实际提交过的候选；找到通过现有代码检查的报价立即停止，未调用的后续候选不冒充已分类。模型即便返回compatible，材质、数字规格、当前证据、币种和报价资格检查仍可拒绝，之后继续后续批次。金额始终来自原始报价，不生成相似度、采购批准或利润。

后续批次前，通过单次有条件UPDATE续租：必须仍为leased、机会/组织/工作区匹配、归当前Worker且尚未过期。未更新一行即停止后续模型调用；不复活失效租约，也不清除新证据触发的重排标记。模型期间不持SQL事务。最终写价仍保留原机会锁、租约及当前证据复核。

分类请求失败或输出无效时，沿用原分类错误及证据评估路径，不把失败解释为匹配；新证据/刷新继续按原队列唤醒。每批模型输入上限仍为10，无新模型参数。整体最多60来自已验证的单页候选上限，未扩为无界历史扫描。

## 合同与配置

没有新增HTTP/事件字段、表、迁移、依赖、生产服务或Python输入。既有 `opportunity.supply_title_classified` 事件保留实际候选原文和所选分类；OpenAPI只同步事件描述。现有成本API与前端消费原金额和证据字段，未修改它们。

继续使用 `AI_TIMEOUT_MS` 和 `AUTOMATIC_SELECTION_EVALUATION_LEASE_SECONDS`，默认30秒请求超时和120秒租约；单次模型等待仍取现有超时与半个租约的较小值。续租使用同一租约秒数，无新配置项；环境示例仅补充说明。批量10/总量60为代码固定边界。
