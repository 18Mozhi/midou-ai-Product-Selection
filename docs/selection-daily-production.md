# 每日选品流程产出

## 已确认口径

2026-10-17 用户明确：每天至少 100 个完成情报、主品、5–10 个竞品、评分、1688 货源整条流程的商品，包含低分、不推荐。目标不再使用合格推荐数。评分权重、阈值和合格推荐规则保持不变。

## 首次完成记录

评分 Worker 在当前评分写入后、自动评估 Worker 在评分输入未变化且评估完成后，复用父事务和已取得的机会行锁核验事实。检查同组织/工作区的情报关联事件及原记录、真实 Amazon 主品、最新完整数值评分和采购价。采购价必须关联该机会的 1688 找货任务与原始归一化证据，商品链接、CNY 价格一致，有商品和供应商名称，排除新人价；利润评分须引用当前采购证据。竞品复用既有推荐门的真实详情证明，排除主品并按 ASIN 去重，记录 5–10 个实际竞品及其快照/证据引用。

达到上述流程条件后，在既有 opportunity_events 记录 opportunity.selection_pipeline_completed，resource_type=selection_pipeline，resource_id 仍为机会 ID，payload contract=selection-pipeline-v1。记录包含主品 ASIN、情报证据、竞品、评分运行和采购来源；没有最低评分、必须推荐或低风险条件。缺少数值评分、费用/证据不完整的记录仍不算完成，不能用缺失值当零分。

同一机会/ASIN 在父事务内先核对已有事件，不重复写入或改写首次时间；异常随评分/评估事务回滚并沿用原重试。不同机会出现同一 ASIN 时，日报以整个工作区最早完成时间去重，因此刷新、重试和次日再次评分不会重复冲日目标。按北京时间日历日半开区间计数，机会发现时间不限制流程完成时间。已完成后归档或作出不推荐决定不抹去历史完成事实。

本版本开始记录首次核验完成，没有伪造或回填旧商品的历史完成时间。旧证据已失效或流程不完整不会生成记录。记录不等于已实现不间断运行或每日百品。

## 接口与使用

GET /api/v1/me/home-dashboard 的 automatic_selection.daily_production 增加可选 completed_count：该北京日期首次核验完成的工作区独立 ASIN 数。date、timezone、discovered_count、qualified_count、target_minimum=100、measured_at 保留。原发现数与合格数仍是当天新建主品的当前快照，不再充当流程目标；它们与完成记录不是同一统计口径。

首页显示完成整条流程、当天新增主品和新增合格推荐，进度只取 completed_count。旧服务没有新字段或未读取时显示未读取并隐藏进度，不回退到新增/推荐数，不补零。海外浏览器仍显示北京时间；零、超过 100、整体未知和仅缺完成字段均有测试。沿用既有每 5 秒及聚焦读取，离页停止。

## 发布和验证

复用既有事件表和索引，无新表、迁移、依赖、环境变量、Python 输入或新增接口地址。详细竞品与风险 SQL 提取为 API/Worker 共用实现，与本次修改前的运行 SQL 逐字比较一致，推荐规则未改变。

本地构建 Contracts/Database/API/Worker/Backend/Web，用 python scripts/deploy-baota.py 发布同一运行包，并由宝塔重启唯一 Node 项目 ai选品：/www/server/panel/pyenv/bin/python /www/server/panel/script/restart_project.py nodejs ai选品。API 与 Worker 需要加载新代码，Python 不因本项重启；目标固定 100，无新增调节项。回滚保留历史事件，旧代码忽略新字段；不得删除已记录完成事实。

19 项计数/记录定向检查及另 66 项评分、采集、权限和 HTTP 回归通过。首页与实际 HTTP 浏览器业务在桌面和 390px 手机共 42 项通过；永久日统计基线按新口径更新。生产 MySQL 5.7.44 对证据、竞品和计数三段 SELECT 做只读 EXPLAIN；实际计数 SQL 以只读派生合成事件验证跨日重复、同 ASIN 多记录和跨工作区隔离，预期 1、实得 1。没有创建临时表或执行生产写入，这些检查不证明真实商品已完成流程或达到 100。22 个工作区完整构建、静态分析、文档/运行说明及真实性检查通过；格式检查发现一处浏览器文件格式问题，修正后单文件复验通过；其余检查无失败。未部署。记录写入异常会传播给父事务，没有自行提交或吞掉失败；未知完成测量不会借用其他计数。
