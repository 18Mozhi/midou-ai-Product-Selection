# 每日选品产出快照

## 依据与计数

用户要求每日至少 100 个有效商品。工作台原有累计机会数和待采纳数不能证明每天新增多少独立商品，因此补充当前工作区的每日产出，不把原累计数当成百品进度。

按用户时区 Asia/Shanghai 的北京时间日历日，使用已有 UTC 创建时间半开区间 [当天00:00, 次日00:00)。主品身份复用选品库既有 Amazon 主品解析 SQL，COUNT DISTINCT 主品 ASIN，不按机会 ID、采集次数、市场数或供应商链接凑数。当天新增的非归档/未删除机会中，有可验证主品身份才进入新增数；如果当前历史机会仍可解析相同主品 ASIN，即使旧机会已归档，也不算当天新增。

当前通过质量门数是上述新增 ASIN 中至少有一条记录通过既有全部质量门的数量，沿用评分、市场、竞争详情、利润、风险规则，不改变阈值、费用或匹配规则。重复 ASIN 只算一次；无 ASIN 或缺资料不算合格。目标 100 来自本次用户原话，超过目标仍显示真实数量，不截断成 100。

这是一份当前快照，不是历史首次达标账本；质量变化可能降低当前合格数。若历史身份的原始证据已失效或不再可解析，当前查询无法还原已丢失的身份，不宣称永久防重或历史验收。没有新增持久化账本、回写历史身份或数据库结构。真实每日百品仍需来源连续运行和逐品证据验收。

## 接口与界面

GET /api/v1/me/home-dashboard 的 automatic_selection 增加可选 daily_production：date、timezone、discovered_count、qualified_count、target_minimum、measured_at。新版本读取真实聚合，旧响应缺少该字段或备用仓库未支持时显示未读取，不补零。DTO、OpenAPI、服务备用值和 Vue 消费已同步；组织/工作区仍来自会话。后端时钟可注入以测试跨日，生产不依赖数据库或浏览器默认时区。统计展示时间固定北京时间，即使用户浏览器在海外。

工作台顶部显示新增主品、当前通过质量门及目标进度，进度只使用合格数；日期、范围和统计时间明确可见。原兼容状态 running 的界面文案改为“采集调度已配置”，不再仅凭调度配置宣称不间断运行。删除按累计数点亮的四步旧流程条及其 CSS；折叠区只显示调度时间、待决策记录、已采纳数量，并说明不能证明 Worker 实时运行。没有新的写接口、权限、环境变量、依赖、Python 输入或插件载荷。沿用首页可见时每 5 秒和聚焦重新读取的既有机制，离开页面即停止。

## 验证与发布

最小验证覆盖北京时间跨日/跨年、主品与质量 SQL 复用、参数绑定、服务兼容及未知值。真实 MySQL 5.7 只读事务验证 6 组实际计数 SQL（重复、历史、缺身份、未过门、混合质量）；生产完整查询 EXPLAIN 并执行，选取单一工作区当天结果为 0/0，单次约 10 毫秒。这不是全平台日报、负载基准或日目标验收，未执行生产写入。

本地构建 Contracts/API/Backend/Web 后用项目固定 python scripts/deploy-baota.py 发布同一运行包，由宝塔重启唯一 Node 项目 ai选品 以加载 API：/www/server/panel/pyenv/bin/python /www/server/panel/script/restart_project.py nodejs ai选品。无需 Python 重启、新配置或目标调节；当前目标固定为用户要求至少 100，不通过环境变量暗改。当前未部署。
