# 商品详情布局重制

2026-10-19 按原始 UI 重制要求，沿用已实际读取的 Ecom168 与商品列表参考，重排详情中的数据和操作顺序。重制前真实 1858px 页面：商品头部高 325.48px、系统建议高 333.47px，评分与采集进度从 y=974.75 开始，首屏无法直接核对分析数据。

## 页面与流程

沿用此前已经精简的六个直接入口、返回路径与旧 tab 规范化，不恢复编号侧目录、市场重复页、AI 辅助、业务血缘或经营复盘。评分仍由后端产生，表格只显示原始权重、输入分、加权分、证据数和缺失项，不在浏览器重新计算。配套精简边界继续见 selection-member-simplification.md。

- 商品头部按图片、身份、四项事实、数据来源/运行信息、评分状态分区。桌面主品事实紧随身份，来源说明和运行信息同排；手机上的事实、来源与评分各自横跨整行，不再把全部资料挤在图片右侧。
- 商品与评分页先展示评分表、竞品和供应候选；宽度至少 1280px 时并排，较窄页面按阅读顺序单列。未知值、真实零值、购买下限、广告未知、证据引用和权限状态继续使用原字段。
- 决策说明置于分析之后，采用标题/质量进度、实际阻断/处理状态、可展开依据三层布局。五项质量门、采纳条件、提前观察/驳回、必填原因、键盘和原决策锚点保持原逻辑。
- 手工补证工具仍为折叠内容，移至分析和决策之后，原事件和权限不变；不把手工点击变成自动运行的前提。
- 主品详情尚缺失时，既有 amazon_competitor_snapshot_missing 内部错误的用户指引改为“等待当前主品的 Amazon 详情快照。”。该错误实际由评估器查询当前主品 ASIN 的详情快照后产生，原“竞品快照”措辞容易误导补证方向。

组件脚本分别与变更前逐字比较，四个 script 均未变化；只重排模板、替换对应旧样式和调整上述真实指引。没有模型、评分、成本、采集来源、租约、数据库、API 字段或依赖变更。API 指引生产者、前端阻断显示和 OpenAPI 的 next_action 说明同步；Python/插件没有相关变更。

## 验证与运行

浏览器回归检查两种宽度的面板顺序、宽屏并排/窄屏单列、决策区域收拢、原采纳门、提前人工处理、必填原因、权限及真实缺失状态。新增当前 Windows 桌面/手机视觉基线，保留历史基线。新增布局断言不会允许通过扩大截图容差隐藏错误。

当前 162 项桌面/手机浏览器流程、102 项相关 Node 测试及 22 个工作区构建通过。四张新基线只代表 Windows 验证，Linux 视觉基线没有生成；模拟浏览器数据不代表生产采集事实。

沿用固定宝塔发布命令，无新增环境变量或用户配置。静态包更新后刷新页面生效；API 指引随部署器重启既有 Node 项目 ai选品 后生效。无需额外服务或 Python 配置变更。

该页面重制和局部回归不代表全站最终签收，也不代表每天 100 个商品已完成整条分析链。实际发布、首屏坐标和业务状态仍须以当前线上回执核验。
