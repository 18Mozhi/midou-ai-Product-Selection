# 格式门禁单测隔离与预检诊断

2026-09-12。当前 UI 实施的验证基础设施收尾，不改变产品运行行为或验收标准。

## 已确认的问题

`tests/unit/code-style-gate.test.mjs` 原来直接在真实工作区的 `tests` 和 `apps/api/src`
创建故意错误的样例，再调用 `verify-code-style.mjs --write`。真实验证器会枚举全库
生产文件及工作区改动，而不只枚举这个样例，因此单测的格式修复有机会写入用户或
其他测试正在观察的源文件。临时样例清理并不能防止这种范围外格式化。

这是由实际调用参数、工作目录和验证器的文件枚举范围确认的隔离缺陷；尚不因此
断言此前生产只读预检的失败一定由它造成。

## 修改方式与保留的门禁

- 错误样例在 OS 临时目录下新建独立 Git 仓库，使用固定虚构测试身份生成初始
  提交。Git 模板与钩子停用、签名关闭；清除子进程继承的 Git 仓库指向和
  `CODE_STYLE_BASE_REF`，确保不会误指真实索引、分支或基准。真实仓库不提交。
- 仍调用实际 `scripts/verify-code-style.mjs`，不复制或伪造验证器。通过可删除的
  目录链接复用现有 `node_modules`，不安装依赖，沿用实际 `.prettierrc.json`。
- 保留未格式化、普通超长行、Repository SQL 超长行与正确样例四种运行结果。
  正确样例明确断言检查了 1 个生产文件、1 个 Repository，并验证临时仓库干净。
- 真实工作区另保留完整 `--check` 单测；仅破坏性 `--write` 移到临时库，不缩小
  全库格式检查范围，也不改变 `npm run format:check` 的行为。
- finally 先确认并解除本次依赖链接，再核对临时路径的真实位置、父目录和前缀，
  最后删除本次临时仓库。依赖目录不会随样例删除。诊断输出记录创建/删除的精确路径。
- `production-acceptance-contract.test.mjs` 仅补充失败时的 `errorCode` 和 `signal`，
  仍保留 10 秒超时、退出码及 225 路径/258 操作/60 受保护路由/6 角色等原断言。
