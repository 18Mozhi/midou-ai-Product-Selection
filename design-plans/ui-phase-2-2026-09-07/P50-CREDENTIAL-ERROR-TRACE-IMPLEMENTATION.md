# P50 · 凭证读取错误与请求追踪

日期：2026-09-25

## 发现与修正

SC50-02 实际路由回归发现：后台刷新失败会保留上一份完整快照并显示恢复文案，但失败请求编号没有绑定到提示；失败分支还会覆写 `requestId`。这使失败追踪不可见，并混淆旧快照与本次失败读取的请求归属。

现将本次读失败编号独立保存：首次读取错误由 `UiStatePanel` 展示；已有数据刷新失败时，旧数据继续原子保留，失败提示显示当前失败编号；成功读取的快照编号不被失败请求替换。超时没有服务端编号时仍不伪造编号。创建、轮换、档案引用错误继续在当前弹窗显示既有 `action_hint` 和 `request_id`，没有改变写入后敏感内容清除行为。

## 回归与边界

`tests/e2e/m03-02-credential-assets.spec.ts` 覆盖资产、档案、来源选项三项读取的单项失败和保留快照路径，组合 503 与 401/403；另验证创建、轮换和档案引用冲突反馈在本弹窗中可见且非秘密字段保留。撤销错误和网页登录分阶段失败由已有用例覆盖。定向新用例桌面与 390px 手机各 2/2 通过；完整页面双端回归与生产构建记录于本批进度。

所有 API 均为浏览器本地路由拦截，不访问真实凭证、后端、MySQL、角色授权或生产环境；无 API、业务、权限、数据、配置或依赖合同变化。
