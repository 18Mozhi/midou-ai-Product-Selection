# P47 列表读取与健康检查顺序实施

起点main / 004c3e0e，工作树干净。承接用户“继续其他交互”，修复PR-G03中的读取顺序与检查交错；没有新视觉设计或扩大已批准范围。

## 运行改动

生产只修改ProviderAdapterCenter.vue脚本：每次load记录loadGeneration和probeRevision；成功与失败回写前同时检查它仍是最新读取、没有跨越检查边界且当前不在检查。只有最新load可清除refreshing，每个请求仍清理自己的原12秒定时器。

probe通过既有全局防重判断后递增probeRevision，完成（成功或失败）时再次递增。这样，检查前发起的读取，以及检查中发起后在检查前/后到达的读取，都不能回退刚获得的检查结果、覆盖其页面消息/追踪或用旧空列表关闭详情。请求仍正常结束，不主动取消、重放或追加GET/POST，也不声称取消了服务端动作。

检查完成后新发起的正常读取照常生效；没有永久锁住记录或按版本号推断服务端业务真相。检查进行中发起的刷新结果不采用，若需要最新列表，检查结束后再次刷新。既有最新读取错误/快照策略、超时、所有接口、请求body、权限、健康/恢复算法不变；模板和CSS逐字保持，上轮详情内反馈和焦点逻辑不变。

## 定向与实际浏览器证据

[48张修复前后图](../../output/playwright/p47-read-order/index.html)。baseline是004c3e0e的不可变组件；current为未注入模板/CSS的当前生产组件。390/760/1440各两版，共6组；每组4种读写顺序，152项显式检查、166份原始加载源指纹（不是页面数）。

四种实际操作：先刷新再检查，旧GET成功迟到；先刷新再检查，旧GET错误迟到；检查中关闭详情发起刷新，再打开详情，旧空列表先于probe到达；同样步骤但旧空列表后于probe到达。原版分别复现rss-v1回退、页面消息被旧错误覆盖、旧空列表使详情消失且probe结果无法补回原行；当前保留两行、新检查事实与反馈。每种场景随后发起全新读取，确认v4样例仍能正常更新，手机关闭返回原入口。

数据取现有两条M03-03测试记录。v3/v4适配器版本、旧空列表与旧错误是显式受控样例，用来辨认响应顺序，不是实际版本发布或线上来源数据。共96次GET、24次无body健康POST全部本地供给/模拟，无外发、数据库写入或真实健康/授权验收。

13项定向合同包括：完整模板/样式不变；精确历史hash与拒绝未知漂移；双GET成功/失败及先后完成，旧finally不能清除新busy；GET/probe交错的旧版反例与修复；失败probe仍作废旧读；之后的新读可用；原最新读取错误与12秒定时器合同；全部当前源/图片/尺寸/清单及实际页面结果绑定。双GET同时调用来自真实脚本的受控单元回放，不冒充界面上禁用刷新按钮能重复点击。

历史P46/P47图片、脚本和结果保持。历史测试只对当前精确组件hash关联004c3e0e，再按原链关联更早证据；新测试直接读取当前原始源，不用历史归一化替代当前验证。
