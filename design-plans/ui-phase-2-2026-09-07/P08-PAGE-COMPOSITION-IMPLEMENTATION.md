# P08 组织与工作区选择 · 生产 Vue 实施记录

## 实施范围

将已审核的 C 方向直接接入 `/select-context` 的真实 `TenancyChooser.vue`：以蓝色范围说明区和白底工作区承载组织目录、当前组织上下文、工作区与团队计数；手机端按层级单列。当前账号仍为非交互文字，不添加账号菜单或弹窗。归档工作区显式标为不可进入；搜索只过滤服务端已返回的组织名称与 slug。

## 合同与状态

- 保留 GET `/org/memberships`，选择组织后并行 GET `/org/{id}/workspaces` 与 `/teams`。
- 组织选择不更新会话。只有 `status=active` 的工作区可 POST `/auth/context`，请求仍只包含该工作区所属 `organization_id` 与 `workspace_id`。
- 保留无组织时 POST `/me/personal-workspace`（无 body）及原有默认 `/home` / 安全 `return_to` 分支；本轮没有用真实账号触发创建。
- 保留错误、403、401、无组织、无工作区和完成状态语义；请求序号阻止已被后续组织选择或返回目录取代的响应改写页面状态。
- 未修改 API/OpenAPI、数据库、配置、依赖、权限规则或数据格式；无需迁移。部署按固定宝塔流程更新静态前端，并重启受管 Node 项目以满足部署器发布合同。
