## 动作归属：本轮新增的精确边界

| 来源 | 实际入口与结果 | 设计/实施注意点 |
| --- | --- | --- |
| P19页首/空态“添加竞品” | manager打开三步创建；前两步本地、第三步POST | 不把下一步当服务端写入；失败保留确认步 |
| P19“查看/当前竞品规则” | 即使只读也导航P20；当前对象带competitor query | 不是P19本地规则弹窗；导航不授予管理权限 |
| P20普通“新建规则” | manager打开规则窗，重置目标/指标/方向/阈值 | 与创建竞品的保留草稿规则不同 |
| P20首次挂载create=1 | manager也会打开竞品创建窗；模板没有rulesPage排除 | 不能把创建窗的全部源候选直接排除出P20 |
| P20首次挂载create=1且competitor为字符串 | 两个show标记同时为true；Escape先关规则，再关创建 | 这是特殊深链状态，不是批准的双弹窗设计；实际层叠/焦点另验 |
| 只读者同一深链 | 两个show标记均为false | 是前端源分支对照，不证明真实服务端权限 |
| 对象行“查看详情” | 无busy禁用条件；点击先改selected，再等GET | 读请求与采集结果归属必须独立，不靠禁用主按钮证明安全 |
| 暂停/恢复与删除入口 | 桌面/移动同handler，入口disabled=busy | 不能仅从可直接调用函数，宣称DOM必然可双击重入 |

UiStatePanel在loading时不渲染动作footer，其余状态按父primary/secondary处理；MonitoringReadinessStrip只有父slot动作，没有额外写入能力。搜索query、来源链接、任务链接与原生更多/帮助仍按既有合同核对，不新造批量/规则编辑或停用接口。

1. **补完整动作清单**：P19/P20共用源按路由、query、权限和事件归并；保留双query异常，不能简单删除“非正常页面”的候选。三role定义与业务变体分开，十绑定不重复算按钮。

3. **实现已明确的结果归属**：按原对象、范围和在途上下文限定读写回调，不改API、数据库、幂等/权限或后台任务事实。异常query的产品优先级尚未确认，不自行实施。
4. **完成图稿逐控件证据**：三步创建、规则、删除的默认/hover/focus/pressed/disabled/busy与错误保留，字段与取消/返回另外标识；现有108PNG不能抵扣全部控件六态。具体图获审后再迁入Vue。
