## 1. 本轮目标与真实起点

目标：重新设计全站页面结构、视觉语言、按钮与弹窗，交付可逐页审阅的完整图包，并在设计确认后落实到真实 Vue、测试及宝塔生产环境。保留既有功能、权限和数据合同，不保留旧 UI 的默认豁免。

1.6核对时的历史起点（已由PLAN 2.3更新为24份规格、缺49份）：

- 路由目录为 73 条，包含跳转、内部开发页和 fallback，不等于 73 个正常生产业务页。
- 已提交的盘点工具发现 1377 个控件/事件候选、100 个弹窗定义或调用候选；这些数字尚非去重后的业务动作或弹窗变体分母。
- PROGRESS 已记录 W00 静态盘点、五类代表页的局部 Vue 基线、W01审核工具和 A/B 方向图；已有19份页面规格，任务方向12图、其他代表方向及按钮板76图。仍缺54份规格，运行时分母、最终逐页设计、完整实现及全站验收尚未完成。
- 核对基线为 main / 181ab16，已有未跟踪机会候选草稿，本轮不修改、暂存或认定其完成。任务缓存修复e1f7a92及证据刷新4e5e8f5已提交，不重复安排为待实现；54个目录外候选、任务71项、评分25项、身份38项、账号/首页51项、趋势60项有已提交局部语义记录，但不能直接相加充当全站去重分母。P14新增8项合同测试与旧8项桌面/移动各16项通过记录来自PROGRESS，不是本轮重测或全站设计通过；产品源码变化后按PLAN 2.2刷新相关证据。
- 本次只规划，没有重新连接生产环境，线上是否仍与历史部署一致不能从本地 HEAD 推断。

执行人负责设计与编码，验收职责负责证据复核，用户负责风格选择及最终签收。同一实施者可以承担验收职责，但应明确属于自检，不声称独立第三方审核。默认不创建代理任务。

审核分三次，不要求用户一次看完全部材料：

3. 总体验收：W09 对照真实生产版本完成全站与连续业务链审阅，记录用户签收。

审核意见至少关联目标 ID、图/源码版本、通过或修改、原因、时间与复核证据。已有审核台可记录并导出批注，但完整图对照和正式通过流程仍属 W01 待完善，不把当前工具误称最终审核系统。

## 6. 验证责任与失败处理

六角色沿用 config/route-catalog.json：member、selection_manager、organization_admin、platform_operations_admin、platform_security_admin、platform_super_admin。按实际 capability 验允许和拒绝两条路径；不让超级管理员代验其他角色权限。

验证层级必须分开：

- 设计/静态：图、规格、字段溯源、控件状态与布局审阅。
- Vue + 隔离合同数据：状态、响应式、请求内容、焦点和交互；不得称真实数据库验证。
- 真实后端 + 隔离数据：事务、幂等、权限、数据范围、错误与恢复链。
- 生产：同版本路由、真实允许链路、必要隔离写入及残留清理；危险全局操作按 PLAN 限制。

每页默认 1440×1000、390×844，补 768/1024、适用断点邻界、200% 缩放和长文本；共享组件另覆盖三主题和两种密度。加载、空、错误、无权限、过期、受阻、恢复等状态按适用性逐项记录，不能全写不适用。

先最小验证，失败即修复复测；通过后验证全部受影响消费者。W09 执行现有 verify:functional 聚合门，并补其未包含的 frontend-budget、runtime-docs、e2e-realism 等 PLAN 所列相关门。已读到的聚合脚本包含代码风格、静态分析、构建、Node/Python 测试、桌面/移动 E2E、文档、计划、发布矩阵和安全门；实施时若脚本变化须重读。按序执行，避免临时夹具污染格式检查。

阻塞发布的问题包括：权限越界、字段或业务合同变化、数据错误、主要操作不可达、重复写入、关键状态缺失、敏感信息泄漏、版本不一致。纯视觉差异也必须记录并修正至用户认可；例外只能由用户明确接受，不能由实施者自动降级。
