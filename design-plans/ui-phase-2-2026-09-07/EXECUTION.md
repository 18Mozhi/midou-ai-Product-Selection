## 1. 本轮目标与真实起点

目标：重新设计全站页面结构、视觉语言、按钮与弹窗，交付可逐页审阅的完整图包，并在设计确认后落实到真实 Vue、测试及宝塔生产环境。保留既有功能、权限和数据合同，不保留旧 UI 的默认豁免。

本次核对到的起点：

- 路由目录为 73 条，包含跳转、内部开发页和 fallback，不等于 73 个正常生产业务页。
- 已提交的盘点工具发现 1377 个控件/事件候选、100 个弹窗定义或调用候选；这些数字尚非去重后的业务动作或弹窗变体分母。
- PROGRESS 已记录 W00 静态盘点和 W01 审核工具；运行时分母、逐页设计、完整实现及全站验收尚未完成。
- 工作树已有任务页测试与设计草稿。本轮不修改、提交或清理它们，也不将草稿文件存在视为相应设计通过。
- 本次只规划，没有重新连接生产环境，线上是否仍与历史部署一致不能从本地 HEAD 推断。

执行人负责设计与编码，验收职责负责证据复核，用户负责风格选择及最终签收。同一实施者可以承担验收职责，但应明确属于自检，不声称独立第三方审核。默认不创建代理任务。

## 4. 每页任务卡及状态规则

每页沿用固定 Pxx，不因改标题或调整构图换 ID。每张任务卡必须包含 PLAN 第 4 节的十项规格，并增加以下执行字段：

| 字段 | 记录要求 |
| --- | --- |
| 归属 | pageId、workPackage、route、surface、共享消费者 |
| 输入与依据 | 角色、范围、真实字段/API、基线 SHA、现有测试 |
| 设计决策 | 主任务、旧问题、新构图、保留功能、删除/合并的视觉入口及理由 |
| 工作范围 | 文件/组件、actionIds、dialogIds、状态与响应式变化 |
| 验收 | caseIds、预期请求和结果、图路径、环境、敏感材料处理 |
| 状态与责任 | 实施者、自检/独立复核说明、用户意见版本、阻塞及解除条件 |

动作记录必须表达“触发 → 前置条件 → 输入 → 实际 handler/API → 成功/失败 → 原页同步”；既有 API 内容只引用或按源码记录，不能在计划中发明请求字段。

状态顺序：待盘点 → 规格完成 → 设计待审核 → 设计通过 → 实现完成 → 本地验收通过 → 生产验证通过 → 用户验收通过。进入下一状态必须有对应证据。若用户要求修改，保留原意见和旧图版本，返工该项；关联组件改变时，同时将受影响消费者标记待复核。

生成器管理 baseline/actions/dialogs/coverage/review-data；人工规格、审核意见与验证记录独立保存，不直接覆写生成物中的状态。后续若扩展聚合器，必须测试重生成保留人工结论、版本失效和缺图失败关闭。

## 5. 全套图与用户审核方式

最低交付量：73 条路由 × 桌面/移动 = 146 个最终设计图槽位；另有 146 个真实 Vue 实现证据槽位。业务弹窗全部变体、按钮状态板、异常状态和过程图另计，不能以凑足 146 张结束。跳转、fallback 与内部页按各自语义留图及 URL/响应证据，不冒充普通业务页。

每个页面审核卡集中展示：旧版参考 → 新设计 → Vue 实现 → 本页变化 → 按钮/弹窗 → 未完成或未验证项。按页、工作包、角色、失败项筛选。设计稿可以使用合成或隔离数据，但必须标注；AI 概念图若采用也不算接口、权限或真实运行证据。

审核分三次，不要求用户一次看完全部材料：

1. 方向审核：W01 比较新构图，选定全站视觉方向；未回复不是通过。
2. 分包审核：W02–W08 每包给出全页、按钮和弹窗图，并逐条处理意见；不能只展示首页。
3. 总体验收：W09 对照真实生产版本完成全站与连续业务链审阅，记录用户签收。

审核意见至少关联目标 ID、图/源码版本、通过或修改、原因、时间与复核证据。已有审核台可记录并导出批注，但完整图对照和正式通过流程仍属 W01 待完善，不把当前工具误称最终审核系统。

## 6. 验证责任与失败处理

六角色沿用 config/route-catalog.json：member、selection_manager、organization_admin、platform_operations_admin、platform_security_admin、platform_super_admin。按实际 capability 验允许和拒绝两条路径；不让超级管理员代验其他角色权限。

验证层级必须分开：

- 设计/静态：图、规格、字段溯源、控件状态与布局审阅。
- Vue + 隔离合同数据：状态、响应式、请求内容、焦点和交互；不得称真实数据库验证。
- 真实后端 + 隔离数据：事务、幂等、权限、数据范围、错误与恢复链。
- 生产：同版本路由、真实允许链路、必要隔离写入及残留清理；危险全局操作按 PLAN 限制。

每页默认 1440×1000、390×844，补 768/1024、适用断点邻界、200% 缩放和长文本；共享组件另覆盖三主题和两种密度。加载、空、错误、无权限、过期、受阻、恢复等状态按适用性逐项记录，不能全写不适用。

先最小验证，失败即修复复测；通过后验证全部受影响消费者。W09 执行现有 verify:functional 聚合门，并补其未包含的 frontend-budget、runtime-docs、e2e-realism 等 PLAN 所列相关门。已读到的聚合脚本包含代码风格、静态分析、构建、Node/Python 测试、桌面/移动 E2E、文档、计划、发布矩阵和安全门；实施时若脚本变化须重读。按序执行，避免临时夹具污染格式检查。

阻塞发布的问题包括：权限越界、字段或业务合同变化、数据错误、主要操作不可达、重复写入、关键状态缺失、敏感信息泄漏、版本不一致。纯视觉差异也必须记录并修正至用户认可；例外只能由用户明确接受，不能由实施者自动降级。

## 7. 发布、回退与交接

发布前核对本次授权范围、干净工作树、发布区间所有权、通过的测试及恢复材料，再调用既有 `python scripts/deploy-baota.py`。新布局默认不需要数据库迁移；出现迁移需求先拆出说明影响并确认，不能借此前一次迁移授权无限扩展。

生产沿用 `/www/wwwroot/ai选品` 和宝塔既有对象。前端静态文件发布不需要自行创建或重启开发服务；Node/Python 是否重启按实际运行包及配置变更判断并由宝塔执行，Nginx 仅在配置变化且语法检查通过后 reload。不能借 UI 项目重建服务架构。

上线后核对公开构建身份、健康、六角色路由、核心链与逐项证据。失败即停止晋级，保留诊断材料，按已验证的恢复方案恢复已知稳定运行包；不能宣称数据库会随前端自动回退。备份保留到生产核验通过，敏感生产图和恢复材料留在中国境内受限目录。

最终 ACCEPTANCE 应列出：页面/动作/弹窗/状态分母及通过数、未执行原因、用户意见闭环、生产 SHA、测试命令结果、重启和恢复记录、精确清理结果、保留图包位置与提交 hash。用户未签收时只能称技术交付，不称第二阶段全部完成。
