# P48 · 配置终态返回与目录重读实际 Vue r1

## 本批范围

以真实 ProviderSourceCenter `load()`、上一批保存/烟测状态、ProviderSourceConfigurationDialog 和 ApiClientError 为准。本批覆盖保存成功、部分保存和版本冲突在关闭任务窗后的目录重读、失败保留与显式恢复。审核宿主精确变换父/子真实 SFC，并让写入与目录读取只命中本地受控响应；**生产 SFC、API、数据库、权限、环境、依赖及线上数据均未改，未部署。**

pbakaus/clarify 用于把两个结果拆开说明：配置是否已经写入，以及来源目录是否已经同步。目录重读失败不能覆盖成功写入事实，也不能把上一次目录内容冒充最新配置。

## 三种返回结果

- 保存成功：确认窗关闭后先显示“设置已保存，正在更新来源目录”；读取成功显示“设置已保存，来源目录已更新”；读取失败显示“设置已保存，但来源目录尚未更新”。
- 部分保存：烟测未通过但停用配置已写入；返回目录后分别显示“停用配置已保存，正在更新 / 已更新 / 尚未更新”，不丢失第一段 PUT 的事实。
- 版本冲突：没有新写入；关闭窗后读取服务端当前版本，成功显示“已读取最新配置”，失败明确“当前页面不会把旧内容当作最新配置”。

## 失败保留与恢复

- `load()` 在审核宿主中返回明确的成功/失败结果；原有保留目录行为不变，但调用方不再用后续成功文案覆盖失败。
- 目录读取失败时继续显示上一次成功加载的来源，并提供唯一主动作“重新读取来源目录”。
- 重读按钮触发新的安全 GET；读取期间改为浅蓝“正在同步”，成功后变成绿色结果区。
- 技术编号进入原生折叠区，不占据主要结论。
- 配置任务窗关闭后焦点进入持续存在的同步标题；失败时进入重读按钮；重读成功后回到同步结果标题。
- 开始新的编辑任务时清除上一次返回反馈，避免旧结果继续干扰当前来源。
