# P53 · 读取、回收与焦点归属实施

日期：2026-09-12

起点：`main/eeb1a77b`

页面：`/platform-admin/collection/browser-runtime`

生产组件：`apps/web/src/components/CollectionRuntimeCenter.vue`

## 已实施

- 运行列表读取固定查询、状态和页码快照；新读取中止旧读取并递增代次，迟到成功、失败和 `finally` 均不能覆盖当前页面。
- 同路由 `q/status/page` 的 back/forward 会恢复已提交查询、状态、页码和输入框；服务端页码纠正仍用既有 `replace` 合并到当前页面 URL。
- KeepAlive 离页中止等待中的 GET，返回浏览器运行页后只恢复被中断的读取；已提交的回收 POST 不取消、不重放，也不在隐藏页面后台发起核对 GET。
- 回收成功和随后事实读取失败分成两个稳定礼貌播报区域。成功只说明服务器返回的过期租约数量，不宣称操作系统进程已停止或采集已经恢复。
- 没有取得 HTTP 响应的回收归为“结果未知”，提示先核对正式运维记录并锁定再次回收；有明确 HTTP 失败响应时继续采用服务端 `action_hint`。
- 回收确认打开后，P53 根节点进入原生 `inert`；共享确认窗保持取消按钮初焦点、双向 Tab 闭环、Escape 关闭和触发按钮返焦。回收等待中确认窗锁定取消与重复提交。
- 回收按钮增加就近范围说明：当前快照数量只是观测值，实际操作对象仍是执行时服务端的全局过期租约集合。

## 保持不变

- GET、POST 路径、查询字段、状态集合、分页大小和空对象 POST body 均不变。
- 回收仍只输入“确认回收”，没有影响勾选、原因、档案选择或客户端计算的回收列表。
- 不修改 API、权限、Origin/幂等校验、服务端事务、MySQL、Python、浏览器档案、环境变量、依赖或部署配置。
- 手机运行详情继续复用 `ResponsiveDataView`；本批没有修改共享详情组件或新增运行、下载、凭证编辑入口。
