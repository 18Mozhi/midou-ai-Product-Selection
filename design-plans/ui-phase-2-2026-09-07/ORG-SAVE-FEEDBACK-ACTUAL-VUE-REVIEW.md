## 提案

- 仅审核宿主分开显示“资料已保存”与“页面正在更新 / 已更新 / 暂未更新”。
- 保存、读取编号分别位于原生 details 中；失败时保留既有错误区及读取编号。
- 普通读取失败说明下方只读资料来自上次读取；权限拒绝仍撤下资料和表单，指向既有
  重新加载入口，不通过文案恢复权限或泄露已撤下的组织名称。
- 按每次 load 的实际返回判断，不使用可能残留的 lastReadFailureStatus。
- 资料写入反馈随组织/路由切换及停用清除；失去归属的写入不启动新页面读取，过期读取
  不发表回执。其他 submit 分支保留原文案和行为；本批不顺手修复其他写入链。

原字段约束、PATCH 地址/方法/参数、expected_version、幂等头、原因、权限及服务端事务
不变。原成功后清空表单并在成功读取时重新填充的规则保持；写入已接受但重读失败时，
保留原有禁用表单安全门，直到操作者显式刷新并成功读回，不自动重复提交。

## 实际 Vue 实施

- 页面现在按 pending / ready / failed 展示保存与重读回执；写入请求编号和读取请求编号
  分别收在可键盘展开的原生 `details` 中。
- 写入已接受而重读失败时继续保留原有只读旧快照提示和禁用表单安全门；上方刷新只发
  GET，成功后恢复资料、更新读取编号并解除表单禁用，不会再次提交 PATCH。
- 组织/路由变化、KeepAlive 停用与卸载会清除回执并使迟到写回执失去归属；过期上下文
  不触发新页面的自动读取。其他组织后台写入分支未改变。
- `tests/e2e/m06-01-organization-admin.spec.ts` 的保存等待、成功回执、失败回执和手动
  只读恢复场景在 desktop Chromium 与390px mobile 各通过；定向单测覆盖 SFC 编译、追踪
