# P05 邮箱验证 · 自动验证与结果规格

2026-09-09局部语义核对：[逐项清单](../action-reviews/P05.json)与[身份审核入口](../IDENTITY-SEMANTIC-REVIEW.md)对应源控件/字段/内联结构及既有C图。后续实际实现只替换 P05 验证结果页面的呈现，不改共享认证行为、API、权限或持久化合同。

状态：C 方向视觉已由用户统一批准；P05 已接入生产 Vue 路由并完成实现验证。页面为独立蓝色验证边界与白色结果工作区，桌面/手机自适应；具体提交、部署与在线证据见[P05实施记录](../P05-PAGE-COMPOSITION-IMPLEMENTATION.md)。真实邮件投递、有效/过期单次令牌和正式 M07-03 仍不由本地夹具或只读生产页面检查证明。

2026-09-09新增：[IDENTITY-C-r1具体图稿](../design/identity-direction-c/README.md)。该首轮视觉记录保留为历史来源；当前生产交付状态以实施记录及本规格中的合同边界为准。

## 1. 用户与导航

公开邮件链接入口。注册成功也会局部显示verify，但URL可能仍/register；无token时只是查收说明，不能作为验证已完成。

## 2. 任务与字段来源

挂载时若mode=verify且token存在，自动POST /auth/email-verification/confirm `{token}`。实际后端返回200 data.status；旧E2E的204是前端兼容夹具，不能作为接口规范。

## 3. 桌面构图方向

以正在验证、完成、失败、缺链接材料四类结果为主视觉，下一步靠近结果。不保留与结果无关的大面积身份宣传栏；只有真实成功才使用成功标记。

## 4. 移动构图方向

先标题和结果，再恢复说明与返回登录，短内容不撑成多屏；长错误和关联标识换行。不会展示token原文供截图。

## 5. 动作及条件

ID-EMAIL-CONFIRM为自动动作，不在控件候选中；ID-SHOW-LOGIN有结果区及页脚两个入口。共享注册/安全导航仍需真实目标；没有独立重新发送验证邮件按钮/API，不在新稿伪造。

## 6. 弹窗与校验

无表单或弹窗。token缺失零确认请求；有效性由服务端判断。当前失败后仍可能显示“正在验证邮箱”，新稿必须处理明确失败标题，但本批没有修复。重复/过期不得显示完成。

## 7. 状态与权限矩阵

无token查收、有token加载、成功、错误/限流/受阻；query expired展示与真实API错误映射分开。LocalIdentity不把所有401映射为requestState=expired，不能将query截图充作真实过期验证。

## 8. 状态连续性

params在组件创建时读取；按路径重挂载，query-only变化未重新解析。刷新有效链接会再走自动确认，需要服务端单次使用语义。切回登录仅改mode，不清URL token；敏感URL在交付索引中脱敏，不新增持久化。

## 9. 响应式与效果

1440/390、768/1024、200%缩放；标题/说明稳定，不用旋转图形代替状态。16px正文、44px操作，焦点与live区域待实际读屏验证；主题/密度和减少动效偏好沿共享规范。

## 10. 验收与证据

本地 E2E 使用隔离请求拦截与合成 token，检查缺 token 零 POST、一次精确 `{token}` 请求、成功需显式返回、服务端失败标题及关联编号，且 token 不出现在页面；单元、类型、构建及生产静态资源核验见实施记录。不得把合成令牌或 `state=expired` 页面参数描述成真实令牌失效/邮箱投递证据。

## 11. 本次实现补充

- 注册请求受理仅显示“检查验证邮件 / 验证邮件已提交”，不会因共享 `requestState=success` 误报邮箱已验证。
- 无 token 时不调用确认 API；有 token 时只在初次挂载沿用既有自动确认动作，token 不回显。
- 实际服务端错误、限流和受阻状态有可访问的告警区；仅服务端成功才显示验证完成，验证成功不自动登录。
- 不新增重发入口、字段、API、配置、依赖或持久化；query-only 生命周期仍按原有路由挂载行为。
