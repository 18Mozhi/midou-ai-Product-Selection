# P47 检查反馈归属与详情焦点实施

起点main / e7c31b8b，工作树干净。用户批准的是已展示手机详情分区，并要求继续完善交互。本批落实生产组件中的反馈归属与检查中焦点；不把整体页面、其他宽度/状态或真实探针扩大为已批准。

本批用户进一步答复：“反馈组合通过，继续其他交互”。只通过展示的390px检查拒绝反馈（浅蓝提示、追踪摘要、展开编号），不是全部反馈状态、整窗、整页或真实健康验收。

## 改动与边界

ProviderAdapterCenter.vue增加probeFeedback，保存本次完成检查的providerId/message/requestId。每次新检查清除旧反馈，原全局probing锁保持；详情常驻status节点按当前row.id显示本来源结果，另一来源检查中明确解释禁用原因。追踪编号使用独立快照，不随后续列表读取改写。仍保留原页面消息、原GET数据替换、无body的POST、错误文案、重试/超时/鉴权及恢复门。

捕获发生在probe完成的同一同步finally内、清除probing之前；对应try/catch已设置本次消息与追踪，期间没有await，其他GET不能插入此同步区间。后续GET可以按原逻辑改写页面消息，但不能覆盖已保存的本来源检查反馈。不能将这一点等同旧GET覆盖新probe数据的竞态已修复。

浏览器额外复现原问题：点击后按钮禁用，焦点掉到body，Escape不再到达详情overlay。仅移动详情将MouseEvent传给probe，并在禁用前把焦点放到同一详情的常驻status节点（tabindex=-1、preventScroll）；不改变桌面调用、不新增Tab停靠、不在异步结果到达时移动焦点。全局防重先于焦点转移执行。状态区、追踪摘要有可见焦点样式；真实读屏器播报和全部无障碍验收仍待。

本批生产仅此组件有运行改动。已批准详情C模板和待审页面C模板不直接导入生产；review回放使用当前完整script/反馈节点，加原C详情模板与局部新反馈审核CSS。蓝色提示/追踪样式只在审核标记与P47详情组合内生效，已获上述有限区域批准。
