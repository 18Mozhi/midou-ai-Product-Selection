## 确认的问题与下一步

### P36-HISTORY-01：同实例查询变化未反向恢复

1. 首次进入 `/org-admin/tokens`，搜索“月度经营”，URL 由现有 watch 写入该查询。
2. 用真实 router.push 导航到同一路径、`org_token_query=只读系统 2`。
3. 地址已变，搜索框仍为“月度经营”，列表仍为旧筛选的一条结果；DOM 对比证实没有重挂载。
4. back 回到原查询，forward 再回到新查询；组件身份仍不变。

原因来自当前源码：五个 query 值仅在 setup 初始化时读入；watch 只有 refs → router.replace，没有 route.query → refs 的反向恢复。既有 E2E 只验证 reload，所以不能支持历史导航已通过的结论。

### P36-HISTORY-02：缓存返回保留旧筛选，与当前地址不一致

同一实例离页后由不带查询的令牌链接返回，URL 没有 `org_token_query`，筛选框仍显示“月度经营”；DOM 是原节点。缓存宿主未触发额外读取。本证据只针对本地 KeepAlive 宿主；生产 Shell 的缓存键、范围切换和路由鉴权尚未完整挂载验证，不把它推断为跨组织数据泄漏。

后续修复应保持现有 query 键、默认值、200 字 URL 初读规则、合法选项、6 条分页、无关参数保留和重置语义，补同实例反向恢复及批量更新防止页码被误重置，并验证迟到 replace 回执不覆盖新路由。是否缓存旧数据/是否自动重新读取不在本次决定范围，不新增 API 或刷新策略。修复后应重新采集问题场景，将问题证据替换为真实恢复证据；不能只把测试改成期望旧错误。
