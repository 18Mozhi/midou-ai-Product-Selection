# P49 · 1688 启用检查实际 Vue 首批布局 r1

## 本批范围

以真实 App、ProviderRuntimeSurface、Alibaba1688AcceptanceCenter 以及 M03-07 验收合同为准，对 P49 默认读取面进行隔离评审实现。覆盖原始 2/3 门禁、原始三项全待验收、三门通过但来源仍停用、三门通过且来源已启用四种状态。审核宿主仅在 Vite 内精确替换实际 SFC 的模板和旧局部样式并注入 P49 专属 CSS；**生产 SFC、GET/POST 合同、验收门、覆盖计算、权限、数据库、环境、依赖和线上数据均未改，未部署。**

pbakaus/layout 用于确定同一条阅读路径：“当前结论 → 三项门禁证据 → 当前下一步 → 受控验收运行 → 诊断覆盖与最近运行”。三项门禁是并列证据，不再使用容易误读为先后步骤的 1/2/3 圆点；搜索、详情与翻页仍位于独立诊断区，不加入启用门禁。

## 布局与信息层级

- 蓝色结论栏只回答当前总体结论、来源启停状态、通过门禁数量与责任人，并持续说明“门禁与来源启用互相独立；系统不会自动启用或停用来源”。
- 白色主体采用连续分区而非同质卡片墙。未通过原因与两个真实下一步入口紧邻门禁证据，不需要在页面底部重新寻找动作。
- 受控运行表单独立于最近运行结果；组织、工作区、关键词和提交按钮仍按原字段、原绑定、原禁用合同工作，关键词上限仍为 200。
- 覆盖矩阵明确标注为诊断证据，不计入三项启用门禁；解析器版本与观测时间就近显示，三行事实保持接口顺序。
- 技术详情仍默认折叠，provider_id、overall 和 request_id 没有被升级成主层信息。

## 响应与交互核对

- 1440/1024px 为左侧蓝色结论栏与右侧连续证据主体；1024px 收紧内部多列，但不删字段。
- 760/390px 复用同一 DOM 顺序并转为单列，结论先于证据，两个下一步按钮与四个表单控件均占满可用宽度。
- 刷新、组织、工作区、关键词、提交与主要下一步入口均通过代表性 44px 热区检查；文本输入使用 16px 字号，蓝色键盘焦点可见。
- 四档宽度均通过页面零水平溢出；标题、门禁、动作、表单、覆盖和最近运行的 DOM 阅读顺序一致。
- 布局技能建议的可选 `impeccable` 首次外部扫描器未完成初始化，已在上一批终止；本批没有把它记为通过，继续使用 Vue 编译、PostCSS 隔离、四视口、溢出、44px、键盘焦点和 DOM 顺序替代验证。
