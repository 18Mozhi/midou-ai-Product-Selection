# P27 保存中关闭守卫与深链焦点回返

## 范围与合同

- 创建或编辑请求进行中时，编辑窗的“取消”与原生 Escape 不关闭当前窗，避免用户丢失本次正在结算的交互上下文。
- 服务端成功仍走原成功分支关闭提交中的窗；失败仍留在原窗并显示既有 `actionHint`/`request_id`。
- 保存期间字段编辑策略仍按规格待决，本批没有禁用或锁定字段。
- 深链直接打开执行详情或编辑窗、没有可返回的触发器时，关闭后将焦点交还 P27 页面标题；由按钮打开时仍优先返回原触发器。
- 共享 `useModalDialog` 以显式选项让 P27 创建/编辑/详情三个原生模态的 Tab 与 Shift+Tab 在首末可见焦点间循环；其他页面默认不启用。
- 原生 required 校验保留；清空规则名提交时不发送请求，浏览器聚焦首个无效字段。

## 实现

- `AutomationRuleCenter.vue` 的 `closeEditor()` 在 `busy` 时安全返回；原生 `cancel` 事件仍由 `useModalDialog` 阻止默认关闭，再调用该守卫。
- `useModalDialog` 新增 opt-in `trapFocus`，监听只在模态打开时注册，并在关闭/卸载时清理。只有 P27 调用方显式启用，避免与其他页面现有自定义焦点陷阱重复。
- 创建和执行详情两个模态共享页面标题作为无触发器的焦点回退点，标题使用 `tabindex="-1"` 仅支持程序化聚焦。
- 未改路由守卫、请求/body、权限、并发/幂等、Worker、数据库或写入生命周期策略。

## 验证

- `tests/e2e/m05-05-automation-rules.spec.ts` 新增两个真实 Vue 浏览器场景：创建/编辑在 POST/PATCH 等待时分别按取消和 Escape 均保持打开，成功响应后才关闭；详情/编辑深链 Escape 后均聚焦页面标题。
- 原桌面 Chromium 与 390px mobile-390 M05-05 基线22项通过（均使用本地拦截响应）。
- 新增 P27 键盘专项桌面/手机各1项：验证三个对话框焦点边界、关闭回焦和原生必填阻止；完整双端套件重跑24/24通过。共享模态生命周期单测锁定 opt-in 和监听清理。
- 本地浏览器回归不证明真实规则持久化、RBAC、Worker、副作用审计或正式 M07-03 验收。
