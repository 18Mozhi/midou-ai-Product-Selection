## 实际验证路径

1. 从真实平台概览，经导航菜单进入组织管理，桌面表格/手机记录预览打开详情。
2. 打开保存或停用原因窗；写入场景点击原确认按钮，并等待真实浏览器请求进入拦截器；原因场景不提交。
3. 浏览器后退到组织列表，再后退到平台概览，真实壳层缓存停用账号组件。
4. 五种时序：成功回执留在概览时返回、失败回执留在概览时返回、先返回同一组织再收到成功、先返回同一组织再收到失败、未提交原因窗离页后返回。
5. 两次前进返回原详情。用 DOM 节点身份相等证明账号组件没有重新挂载；此时写入“返回后的新草稿”。旧成功/错误不覆盖它、不新增反馈、不触发概览重读。前进到详情 URL 打开详情是正常路由行为，不误判为旧回执重开。
6. 原因窗离页自动消失，返回后不复现，无写请求；最后真实 Escape 返回列表，点击品牌链接可回概览，背景可操作。

写请求仍为原组织 UUID 的 PATCH（name / timezone / data_retention_days / reason）或 POST status（archived / reason），保留 Idempotency-Key。已发送请求并未被取消。夹具概览保持原始事实，专门验证旧回执不能自动重读或接管新视图，不能据此推断服务器事实已经同步。
