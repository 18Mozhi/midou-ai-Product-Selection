# 第二阶段逐页实施与验收矩阵

日期：2026-09-07；基线与执行门见 [PLAN.md](PLAN.md)。本表是待执行规格，不是完成报告。P01–P73 对应当前路由目录顺序；后续路由变动保留 ID 并追加，不重排历史证据。

## 阅读与执行规则

- 组件名均指 `apps/web/src/components/<名称>.vue` 的真实入口；多个路由共享入口时，按现有 routePath/mode 追踪到子组件，不把共享入口当作只有一页。App.vue、NavigationShell.vue、AccountShell.vue 的装配与权限逻辑一并回归。
- 每行给出该页的布局方向和最低定向验收；完整字段、按钮、菜单及弹窗清单由 W00 沿真实 handler/API 盘点，进入实现前按 PLAN 第4节扩展为独立 page-spec。下表不声称穷举了每个现存按钮，也不授权增加当前没有的业务动作。
- “重排”“分区”“步骤化”只调整已有事实的呈现。当前代码没有的状态、指标、操作不能为了符合草图自行补业务规则；形成缺口记录并修改稿件。保留现有筛选范围、分页总数口径、URL状态、权限和失败保留行为。
- 所有页面均执行桌面/移动图、六态按钮、适用异常态、键盘操作、焦点、长文本、无页面级横向溢出、三主题令牌检查。表中移动方案不能简单等比缩小桌面。
- 每个包的测试文件是扩展入口，不表示现有用例已覆盖新设计。实施时把 actionId/dialogId 映射到实际 test title/caseId；遗漏的状态新增必要永久测试。测试文件均在 `tests/e2e/` 下，省略统一的 `.spec.ts` 后缀。
- 每页执行人：该包实施者；事实与测试复核人：该包验收者；最终视觉签收人：用户。当前全部状态均为“待盘点”。共享组件复核不能替代用户逐页签收。
