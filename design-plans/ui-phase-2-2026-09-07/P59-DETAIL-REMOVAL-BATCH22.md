## 原因与产品修改

沿 P59 → ResponsiveDataView 实际调用链复现：先刷新、再打开仍在显示的旧记录，响应返回空集合时父组件的 v-if 空态替换了整个数据视图。详情与背景已清理，但原组件内的返回目标全部卸载，焦点落到 BODY。不是改变删除规则，也没有发起删除操作。

按 fixing-accessibility 的焦点归属规则，ResponsiveDataView 新增可选内部属性 `focusFallback?: () => HTMLElement | null`。卸载前只有焦点仍在自己的浮层内才安排交接；下一次 Vue 更新后检查目标仍连接、可见、非禁用、非 inert，且不抢后来弹窗的焦点。原关闭路径仍优先原按钮、手机列表、数据视图，调用方目标仅为最后后备。原 KeepAlive 清理、行身份、字段、Tab 顺序和关闭事件保留。

P59 五个已有结果 section 各自绑定 ref、tabindex=-1 和原标题，向对应数据视图提供后备目标。整个集合变空时回到所属结果区；只有选中记录消失而其他记录仍在时，沿用原手机列表后备。凭证和令牌互不串焦、不清空另一集合。生产样式只给结果区补现有 --so-focus 轮廓；公共组件其他19个导入方未启用新属性，不改变其卸载行为。

本批 C 审核 CSS 同时补结果区/手机列表蓝色焦点，并让深蓝悬停记录的说明和详情入口显示白字，仅在审核宿主生效。r3 目检发现主标题在截图中过暗；补充主标题色值检查后确认它最终正确变白，实际是继承颜色的过渡未结束，故只扩大稳定等待到标题、说明和入口三者，没有追加不必要的产品样式改动。
