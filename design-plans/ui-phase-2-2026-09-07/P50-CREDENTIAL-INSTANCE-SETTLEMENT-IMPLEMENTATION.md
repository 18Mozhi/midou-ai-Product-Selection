# P50 · KeepAlive 实例淘汰后的写入结算

日期：2026-09-24

## 问题与范围

`CredentialAssetCenter` 位于真实 `NavigationShell` 的 KeepAlive 路由树中。缓存淘汰会销毁原页面组件实例；先前的离页写入归属只保存在该实例上，因此延迟返回后的结果没有页面可展示。此次只补齐已提交写入跨实例的前端结算，不更改业务规则、请求契约、权限、持久化、凭证加密或部署配置。

## 实现

- 新增 `apps/web/src/credential-write-coordinator.ts`，用模块级 Vue 状态保留当前操作标签和非敏感结算信息，不保存请求/响应正文、Cookie、凭证值或档案数据。
- `CredentialAssetCenter.vue` 在写入期间通过协调状态锁定修改入口。原实例仍负责处理响应；若它已卸载，完成状态留给替换实例显示，替换实例读取原有三项资源后消费状态。
- 已提交请求不因页面销毁而取消，也不自动重放。登录资产成功后仍只继续一次原有档案请求；资产未知仍不创建档案。API 与数据结构未变化。

## 验证证据

`tests/e2e/m03-02-credential-assets.spec.ts` 新增真实 App/Router/NavigationShell/KeepAlive 路由缓存压力回归：从实际凭证路由发起拦截的登录两段写，切换超过缓存上限的不同路由以淘汰原实例，再返回凭证页并验证等待锁定、资产与档案 POST 各恰好一次、恢复提示及三项事实读取。桌面 Chromium 与 390px 手机各 1/1 通过。

此测试使用浏览器本地路由拦截和合成响应，不访问真实 API、扩展、凭证、加密材料、MySQL 或生产环境；因此只证明前端生命周期和现有请求次数，不等于真实服务端、角色权限或生产验收。
