## 源码范围与可见入口

`/work` 经父壳层传 `mode=today`、无taskId；当前组织/工作区按 `reset_on_scope` 缓存。TaskWorkspace、TaskListPanel、TaskBatchActions共有48个局部源候选，归为36组：29个页面动作组、5个事件转发/定义组、2个排除组。它们不是全站独立按钮分母。

| 边界 | 当前实际行为 | 新设计不能误称 |
| --- | --- | --- |
| 今日工作 | 列表带mine=true，为本人任务，不限今天截止、不排除终态 | 今日到期任务或自动推荐的首项 |
| 状态计数 | 本人、当前工作区全部状态；不受当前搜索/分页影响 | 当前筛选结果数量 |
| 搜索和排序 | 应用搜索trim；切换四种排序也立即应用当前搜索草稿；均清选择和页码 | 只有点应用才会使用草稿 |
| 选择 | 仅task:update；单行、本页、清除分开；无跨页全选 | 选择全部搜索结果 |
| 查看 | RouterLink到/tasks/id，from保留完整/work URL | 本页直接打开任务详情弹窗 |
| 导出/详情编辑 | mode=all的导出分支及P24详情事件在P13正常入口不可达 | 静态import里的按钮都属于今日工作 |

## 每类表单与弹窗

三处原生dialog对应7种业务变体；3个内部form和搜索form只是结构容器，不重复计弹窗。6个v-model之外，排序、复选框、批量原因/日期/负责人由事件控制，清单全部列出。

| 变体 | 字段与提交 | 关闭/失败边界 |
| --- | --- | --- |
| 新建 | 标题200、说明5000、四优先级、可选本地期限；POST /tasks，无负责人字段，空期限null | 取消保留草稿、只清create/title/description query；源错误在窗外，字段未锁定 |
| 删除 | 必填原因500，trim；DELETE当前id及expected_version | 取消清目标及原因；执行中Escape可清目标，await后仍读目标的竞态待真实Vue验收 |
| 批量暂停 | 仅in_progress可执行；必填原因 | 其他状态跳过，不取消底层采集 |
| 批量继续 | 仅paused可执行；不发送原因 | 无可执行项时确认禁用 |
| 批量延期 | 排除completed/cancelled；原因及必填期限→ISO | 不添加默认延期规则 |
| 批量调整负责人 | 排除completed/cancelled；额外task:assign，原因及真实成员目录 | 不虚构成员；目录失败的确认保护仍需真实Vue/服务验收 |
| 批量取消 | 排除completed/cancelled；必填原因 | 每个任务独立请求/版本，不新增批量API或联动取消采集 |

原生新建、删除与批量dialog现均在busy时阻止Escape关闭：TaskWorkspace的创建/删除取消回调检查共享写入状态，TaskBatchActions已有对应保护；创建/删除的实际Vue等待态由本批双端回归覆盖。原型的窗内错误、字段锁定及焦点细节仍须按具体状态验证。174个逐动作视觉槽尚未绑定具体selector，不能以66图或通用控件板声称全按钮六态完成。

## 本轮确认的提交风险

直接从当前TaskWorkspace提取confirmBatch函数，使用TypeScript转译、隔离VM和惰性API替身执行，未发送HTTP或SQL：

1. 初始action=pause、原因“初始原因”，两个任务版本分别2、3。首项请求等待时改action=cancel和原因；释放等待后第二项确实以cancel及新原因提交。当前函数遍历原eligible数组，但每次请求重新读取action/字段，并不是完整操作快照。
2. 首次调用等待中busy=true，再直接调用confirmBatch，替身记录第二次请求。按钮disabled并不等于函数有重复提交防护。这不是实际浏览器双击、服务端重复变更或幂等失败的证明。

执行阶段需验证：先固定本批任务、版本、动作与字段；提交中关闭/重开不得改变已经确认的操作；所有请求结果归属原批次；真实重复提交与部分失败仍按原幂等/版本合同验收。此处记录验收要求，未改变API、业务资格或生产逻辑。已有GET的active/路由/read key/AbortController保护继续保留，不能把写入风险泛化为读取无隔离。
