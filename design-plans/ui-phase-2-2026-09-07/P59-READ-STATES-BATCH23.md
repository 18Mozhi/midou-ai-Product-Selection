## 产品修复与审核设计

实际Vue先复现：首次加载中仍提示“切换时间窗，或由运维在宝塔检查 API 与 MySQL 后重试”，且状态区没有aria-busy。按fixing-accessibility，只在SecurityOperationsCenter的非ready区增加与真实loading绑定的aria-busy、标题关联及消息role=status；加载中改为“正在读取安全运营数据，请稍候。”。失败时原接口action_hint/兜底说明、标题、重试按钮可用条件全部保留，业务script逐字不改。

C审核宿主把状态标题从h3提升为h2以配合现有h1；白色区域左对齐、深蓝标题、浅灰技术详情和手机全宽重读按钮。生产布局CSS不改，审核CSS仍不接入生产。只读页面没有新发布/授权/删除入口；已加载后403如何处理也没有借本批改成新的安全策略。

## 状态与真实接口边界

覆盖首次loading、401 expired、403 forbidden、429 rate_limited、503 blocked、400 error，以及ready刷新中和ready刷新503失败八场景。错误响应为本地样例，按实际api-client读取error.code/action_hint/request_id；没有调用业务后端。

首次失败不展示结果或摘要，不能声称保留不存在的快照；已有结果刷新中仍保留原结果并标busy，刷新503失败保留并明确说明上次成功数据。权限/登录失效原本无区域内重读按钮，页面顶部刷新仍存在，本批照实验证，不新增“申请权限”或跳转登录契约。恢复以本地响应切换成功验证，不等于真实重新登录或权限恢复。

客户端实际对429/503 GET执行0/150/400ms三次尝试。初版验证器误按一次请求计数，在429处明确失败；已修正测试计数，不删除生产重试。单个宽度/动效组22次HTTP读取，四组共88次；不把自动重试误报成重复点击。15秒超时、500ms手动去抖、两类20条分页、请求归属和审计规则均未改。
