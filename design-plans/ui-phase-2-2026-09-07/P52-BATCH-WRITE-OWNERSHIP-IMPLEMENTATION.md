# P52 · 批量重放写入归属实施

日期：2026-09-12

起点：`main/be034fea`

页面：`/platform-admin/collection/overview`

生产组件：`apps/web/src/components/CollectionOperationsConsole.vue`

## 已实施

- 打开确认预览时固定批次编号、所选开放死信、原因和影响范围；确认后的响应式草稿变化不能改变任一 POST 的目标、正文或幂等键。
- 批次继续使用串行单任务重放；每条独立事务，某条成功、明确失败或结果未知都不会回滚或跳过其余已固定条目。
- 执行期间锁定范围、分页、刷新、死信选择和原因，避免当前页面产生与在途批次不一致的新读写意图；只读导航仍可离页。
- 网络不可达及 408、425、429、502、503、504 归为“结果未知”，与服务端明确拒绝分开计数；成功只表述为“创建新任务”，不表述为采集执行成功。
- 结果未知的批次不会自动重发，并在当前页面锁定新的批量预览；用户需先进入对应任务核查。
- KeepAlive 离页不取消已提交的 POST，也不在后台发起总览核对；批次结束后保存结算，返回时先恢复当前 URL 范围，再执行一次只读核对。
- 部分成功、明确失败、结果未知和后续读取失败分别呈现；读取失败保留原事实快照，不覆盖批次结算。

## 保持不变

- POST 路径仍为 `/platform/collection/tasks/{task_id}/replay`，正文仍只有 `reason`。
- 幂等键仍为 `dead-batch:{batchId}:{taskId}`；每条任务独立，批次上限仍为 20 条当前页开放死信。
- 原因仍为去除首尾空白后至少 2 字、原始长度最多 500；确认仍要求影响勾选和“确认重放”。
- 不改变 `collection:replay` 权限、Origin、服务端幂等、事务、审计或任务状态机。
- 不修改 API、后端、数据库、环境变量、依赖、CSS、路由或部署配置。
