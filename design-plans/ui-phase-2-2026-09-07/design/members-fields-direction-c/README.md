## 字段与边界

| 字段 | 本次展示与验证 | 保持的真实规则 |
| --- | --- | --- |
| 邀请邮箱 | 空、格式错误、合法/无效混合、重复/大小写、254/255字符、修正、在途编辑 | 换行/逗号/分号拆分、trim小写去重；无效项单独报错，不因警告阻止合法项 |
| 邀请角色 | 五个现有选项、焦点、在途编辑 | 无新增空选项或角色；选中不等于发出邀请 |
| 邀请原因 | 空/纯空白、500字符、脚本赋值501反例、修正、在途编辑 | 必填、trim后1–500；原生maxlength阻止用户继续输入，脚本赋值另列反例 |
| 姓名/邮箱搜索 | 默认/空/姓名命中/无结果、焦点、在途编辑 | 仅当前已加载成员，不扩张到ID、角色等字段 |
| 状态、角色、团队、排序 | 每个实际选项与焦点、在途编辑 | 来自现有固定集合或原成员团队，不请求目录或服务端分页 |
| 单行角色 | 五角色、焦点、在途编辑 | 先选择，另按分配角色并填原因；替换而非追加 |
| 共享原因 | 默认/空/不足2字/修正/501字、焦点 | 当前共享前端trim至少2字、无maxlength；不新增500上限 |

包括3个邀请v-model、6个value/emit输入和1个共享原因；父组件6个P29组织资料字段排除。使用原生select，不虚构readonly/disabled/空必填角色或选项弹出层覆盖。8组合为邀请无效与重复、部分失败、在途、创建待投递及禁用/恢复/分配角色/撤销邀请四原因内容。同一个共享原因调用不是四种全局弹窗；13容器变体增加8图引用至21，不更改源动作数/30未映射代表按钮槽。

## 本次设计与旧提案差异

frontend-design与fixing-accessibility用于新子稿的明显输入边框、蓝焦点、16px关联说明/错误/计数、即时清错，以及合法批项不受错误标记阻断。筛选说明放在label外避免重复朗读，行角色说明放在操作行下方避免挤窄选择框。ui-skills CLI缺失，未安装依赖，使用已安装技能和项目Playwright验证方式。

原94图和444按钮图、其HTML/CSS/JS均不改。旧原因稿有未批准500字符保护；本子稿对共享原因单独采用现有Vue的最小长度规则，截获旧原型提交并记录独立的准确方法/URL/body意图，再关闭窗口。**不是实际Vue/API调用，不证明服务端接受501字。** 邀请原因仍保留500上限。取消与焦点沿原稿；完整原因重开、KeepAlive、迟到回执与真实服务结果仍待。

源邀请函数开始时固定邮箱、角色、原因，等待时编辑草稿不改变已开始批次。测试提取真实函数验证此事，但不修改最终表单覆盖或403尾部丢失行为。用户关于中断后保留失败/未处理邮箱的决策未回复，未实施该政策。
