## 业务与提案边界

成员候选只要求当前组织membership.status为active，锁定账号不被擅自过滤。没有选择时按钮仍可点并提示；归档团队仍保留成员动作。移除只调整团队成员关系，不删除账号、不清空负责人字段。页面不提供后续改负责人、改流程或团队归档等不存在的API入口。

分配原因确认蓝色，移除原因确认红色；下方明确目标团队、目标成员和影响。确认先关闭原因窗，再进入成员动作等待；POST仍只有action/membership_id/reason，不添加expected_version。取消/关闭零提交且返回对应按钮；父刷新读取summary/teams/members，不冒充刷新成功。

原稿中的创建字段锁定、原因最多500字、未知结果保护和按旧目标显示迟到反馈仍是提案差异。本批不批准这些规则、不修改真实Vue，也不修复已知OG-G02：真实成员写入期间切团队后，反馈可能误引用新目标或访问未选成员。父请求原目标与子反馈归属不能混为一谈。创建/共享原因全部字段、后续草稿处理、完整生命周期、角色主题缩放和生产验收仍待。
