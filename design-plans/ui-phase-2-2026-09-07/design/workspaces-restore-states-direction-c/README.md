# P32 恢复工作区 · 后续状态 r1

用户通过手机恢复组合后继续其余状态。本批复用原 C 渲染器、数据及样式，新增10组/20张图：空原因、单字、两个字可提交、键盘循环、取消返回、关闭返回、Escape返回、等待、失败、失败后重开。仅新子稿在恢复等待时增加可读的状态提示及role=status，避免只剩灰色按钮却没有解释；不更改控制器和原图。所有新图仍待具体审核，不改既有局部批准和整页批准状态。

## 状态说明

- 清空或去除首尾空白后不足两个字：确认按钮灰色禁用；两个字可用蓝色确认。最低长度来自现有共享原因窗，不新增规则。
- Tab / Shift+Tab 在窗内循环；取消、关闭和 Escape 不提交，焦点回到恢复入口。
- 确认后原因窗关闭，页面处于等待，恢复入口禁用。本批不画成原因窗内显示保存进度，以免背离当前调用方式。
- 失败不伪造恢复后的状态，不自动重试。重新打开原因窗时回到默认“恢复工作区”，不宣称保留已提交原因。

本批仅核对短原因与既有离线意图。原提案的500字上限与真实共享前端没有maxlength的差异仍存在；服务端500上限也不等于用户批准前端截断。既有原型的其他保护、异步结果归属和字段锁定不在本批落实到真实 Vue。错误文字是明确的合成反馈，不是生产 API 原文。

`node scripts/verify-ui-phase2-workspaces-restore-states.mjs --smoke` 检查手机；`--capture` 执行双端并生成正式图片；无参数重跑双端并核对源与图指纹。复用现有 Playwright，不安装依赖、不启动服务器。真实鼠标/键盘操作原型；仅隔离响应完成使用原型已有 complete 钩子。

检查精确 POST 意图的目标 ID、restore、expected_version 与 trim 原因，等待禁用不能重复触发，失败不改夹具数据；HTTP请求、cookie和storage均为零。浏览器与上下文由 finally 关闭。图片是永久审核交付物，不是应删除的临时测试图片。
