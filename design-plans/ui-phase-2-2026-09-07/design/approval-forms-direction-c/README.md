## 交互与可访问性

frontend-design用于保持C蓝白语言和字段层级；fixing-accessibility用于关联标签、帮助与错误、首错焦点、键盘闭环及非颜色提示。输入框聚焦保留独立轮廓；错误使用文字、边框和aria-invalid，aria-describedby关联帮助和错误，表单有polite汇总。未尝试提交前不把空白字段全部标红。

长度取真实Vue中的maxlength，字符数按浏览器UTF-16计数，不冒称字素/视觉字数；原数字min/max与隐式整数step保持。原生invalid仍阻止提交，只抑制浏览器浮动气泡，改用就近中文错误并聚焦首错；不使用novalidate、不改变required或范围。五字段同时为空验证汇总数量与首错焦点，帮助/错误位于label外避免名称重复。SLA、成员、已发布模板、资源归属说明不构造额外业务规则；资源存在性/类型/归属仍须后端校验。

新表单控制器只修本包的一个旧原型缺陷：validText覆盖发布原因oninput后，纠正空格原因会失去内部同步。回归先复现DOM已正确而请求reason为空，再保存并调用原同步处理器；复验发布body的reason.trim与expected_revision一致。旧包和生产Vue没有改，不能声称线上曾发生或现已修复。

## 来源与不可合并的差异

- 当前Vue的审批人与超时接收人、发起资源编号放在details；新稿直接可见并保留就近错误，是待审布局，不是源DOM相同。
- 原Vue未统一锁定busy字段；本包沿前批控制器演示锁定/失败保留，不证明跨窗pending归属或后端成功。未验证软键盘/IME、全部浏览器/角色/主题、读取竞态和真实服务。
- 原Vue只有详情显式实现遮罩关闭。本包其他窗的遮罩关闭沿旧提案；原Vue发布“返回”清目标而保留内存原因，Escape清二者，本包旧控制器统一清二者。源重开发布总清原因，图中的重开结果与此一致；不能将本包空闲检查说成所有源关闭路径已等价。此差异仍需具体审核。
- 空格阻止来源是旧原型validText；原Vue模板/请求的required不拦仅空格，服务端再校验。本包不把浏览器原生required与trim混为一谈，不自动修改生产校验规则。
- 模板仍是单节点；发起类型跟随已发布模板；发布仍只reason.trim/expected_revision；决定仍用原reason/expected_version，证据缺失只提醒，超时不自动审批。
- 旧独立夹具模板v1/详情锁v3、节点与历史升级、同成员不同展示名等差异保持，不拼造一致数据库快照。旧94布局图与前批64按钮图均原样保留。
