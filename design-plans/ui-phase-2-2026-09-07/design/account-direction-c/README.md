## 为什么与旧版不同

| 层面 | 本研究的选择 |
| --- | --- |
| 页面组织 | 不保留旧账页大编号、横向模块索引、巨幅标题与商品数据模板；采用上下文区+账号目录，不是统一模板换色 |
| 主行动 | 新建放到当前账号范围区；查询/刷新在结果区；不使用虚构批量动作 |
| 信息顺序 | 邮箱、注册日期、组织名称、平台角色、状态直接对应账号事实 |
| 详情 | 身份列与组织/平台角色/会话分区，安全动作独立；没有相互混淆的组织/平台权限编辑 |
| 移动 | 上下文压成摘要，表格改字段记录；提议直接开详情，常驻关闭入口；组织授权提议独立弹窗 |
| 字体与视觉 | 冷灰背景、蓝色上下文、圆角分区、微软雅黑UI中文、Bahnschrift身份/数字，无外部字体与装饰动效 |

旧参考为`design-plans/ui-redesign-2026-09-05/screens/desktop/43-platform-admin__users.png`，它是历史HTML概念图，不是当前线上或Vue截图；其商品列表、批量分配等错误语义不作为功能依据。当前业务事实来自[本页规格](../../page-specs/P43.md)及[动作合同](../../platform-user-design-contract.md)。

## 可复验交付

在仓库根目录执行：

```text
node scripts/verify-ui-phase2-account-direction.mjs --capture
node scripts/verify-ui-phase2-account-direction.mjs --check
```

--capture实际启动隔离Chromium、执行交互并覆盖本目录18张永久研究图和evidence.json，退出时关闭context/browser；不会改正式截图基线、全局清单或用户审核记录。--check只读核对源与图哈希。已有Playwright依赖直接复用，脚本拒绝其他参数，不创建HTTP服务或生产连接。

当前检查含双视口场景、整页无横溢、可见目标44px、搜索/重置与全局数保持、详情身份、嵌套模态/返回焦点、必填邮箱、密码长度、组织字段条件显示、演示提交不创建记录。控制台错误和外部请求要求为0；这些是本地HTML检查，不是Vue、真实后端或全站无障碍证明。

## 审核与剩余边界

状态始终为pending-user-review，不由脚本改成通过。请评估上下文区是否占空间、目录密度、身份与权限的分区、移动直接进入详情和独立授权窗；可以要求修改或全部推翻。页面没有完整全局导航、全部11原因变体图、完整控件六态、加载/权限失败全状态、三主题/两密度与生产图。正式P43双视口设计槽位仍未填充，不因为研究图足够多就计入正式通过。

源文件、README、图和evidence均为本次永久审核交付，不是临时截图。没有新增长驻服务、生产运行配置或重启需求。
