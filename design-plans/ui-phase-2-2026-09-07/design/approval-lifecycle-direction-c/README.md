## 本批交付

五类提交：批准、驳回、保存模板草稿、发起审批、发布模板。每类都有等待、原窗失败、原窗模拟成功、关闭后等待、重开等待，另有原审批A成功/失败返回时后来审批B保持打开的两种场景；27场景×1440/390=54PNG。A/B沿原分页布局合成样例，明确不是真实审批数据。

frontend-design技能用于页级结果提示、窗内等待/错误层级和清晰区分审稿工具；手机等待文案缩为“等待结果…”避免按钮换行。已有字段帮助与导航尺寸修复复用，旧布局/按钮/表单/导航/诊断包不改。本包不导入旧controls.js的全局pending实现，避免旧结果写入当前同名DOM。

## 交互规则与源边界

- 真实底稿事件先生成原合同的请求预览，随后记录不可变请求副本、原dialog及渲染代次。不是客户端新增API字段，不发送HTTP，也不模拟数据库成功记录。
- 与源码单一busy边界一致，一次写入待返回时其他提交也不可重复发送；原提交窗锁定自己的输入，新开的窗口允许编辑草稿但暂不能提交。新窗就近提示具体前次操作仍在等待，当前草稿不会自动发送；等待结束移除提示。关闭保留在途操作，不取消或重放。
- 原窗口仍是同一代次时：模拟失败保留输入供核对重试，模拟成功只关闭该窗口。模板发布只关闭上层，保留下层模板窗；不会变更模板、审批状态或动作历史。
- 原窗口已关闭、重开或换成B时：结果只进入页级原操作提示，不关闭当前窗、不清新草稿、不移动焦点、不把旧错误写进B。完成后释放全局提交等待。重复旧结果按操作token忽略，不能干扰后续重试。
- 原生关闭按钮、Escape、遮罩，及三类表单取消/返回均验证。非详情遮罩与发布关闭原因清理仍沿旧提案，**不宣称和当前Vue全部一致**；字段空格校验和直接展示替代差异也保留。
- 当前源Vue的同实例GET乱序、关闭后旧GET回流、旧写成功关闭后来窗口、页级requestId覆盖问题仍未迁入修复。本批仅验证离线写预览的归属模型；读取、组织/工作区失活、真实错误解析/HTTP、服务端权限/并发与MySQL均未验收。
