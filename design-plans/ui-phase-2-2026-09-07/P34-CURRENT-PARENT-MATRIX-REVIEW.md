## 发现与修订

上一批6个关联测试停在旧图包共享源哈希断言，涉及 NavigationShell.vue 或 signal-ledger.css。
本轮没有改旧哈希或假装旧图包仍对应当前源码，另用当前源码、既有 C 导航与 P34 C 子页
重跑原父级完整读取矩阵。旧图包、此前r4整体图和用户批准范围均保留。

实际捕获发现：原 C 页头规则依赖 `.org-approval-c-workbench` 存在；首次加载/失败撤下子页
时，顶部变回旧橙色/渐变。这是父子样式依赖缺口，不是权限或接口问题。

修订仅在父 Vue 内存预览增加 `data-approval-c-view` 展示标记。新样式仅匹配审批页且子页
缺席的父级及页头：平面背景、蓝色刷新、灰色禁用、隐藏已有导航标题的重复标题。
子页存在时原r4样式继续生效。没有改生产文件，原完整父 script、请求、状态机、事件、
重试次数、错误文案和已批准白色提示区保持；没有新增业务动作或弹窗。

另一个失败来自旧验证脚本将所有 `dialog[open]` 当作业务窗；现有 C 壳在桌面有非模态
导航容器。新验证只排除精确的 `.role-navigation-frame`，另断言桌面仅一个带既有标签的
导航容器、手机零个展开导航、两端零个意外原生模态窗。不是放过任意业务弹窗。
