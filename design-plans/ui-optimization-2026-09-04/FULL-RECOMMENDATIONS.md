# ScoutOps UI 全站优化建议

## 1. 结论

当前界面已经具备完整主题、权限壳层、44px 触控基线和桌面/移动适配，不需要推翻业务结构。主要问题是视觉层级在不同模块间漂移：部分成员页用大标题和大卡片，部分后台页进入高密度表格，技术标识、状态、主行动和说明文字经常处于相近权重。建议保留现有“深海蓝 / 极光紫 / 云雾白”主题合同，以“证据罗盘”统一壳层、证据表达、按钮层级、数据视图和弹窗。

## 2. 全局设计系统

### 2.1 视觉语言

- 画布使用深海墨蓝，导航与内容区只用轻微明度差分层，不再依靠强边框切割。
- 主行动统一钴蓝；实时与可追溯信息使用青色；成功、待办、危险只使用绿、琥珀、珊瑚三种语义色。
- 取消装饰性渐变和大面积光晕。图表允许多色，但页面行动色仍保持唯一。
- 卡片默认边框透明度降低，浮层用“细环 + 软阴影”，后台优先用细边框而不是重阴影。
- 中文正文与表单保持 16px；元数据 13px；页面标题桌面 36–38px、移动 30px，不再以 48px 以上标题挤压数据首屏。

### 2.2 间距与密度

- 4px 基线：图标间距 8px、控件内部 12/16px、卡片 16/20px、模块 24/32px。
- 控件圆角 8px、卡片 12px、弹窗 18px；嵌套圆角遵循“外层 = 内层 + 内边距”的视觉关系。
- 成员端使用标准密度，组织与平台后台使用紧凑密度，但所有可点击区域仍不低于 44×44px。
- 桌面内容最大宽度 1180–1240px；宽屏增加留白，不无限拉长表格列。

### 2.3 产品签名：证据轨

所有业务数据页在标题区下方提供同构证据轨：

1. 当前组织 / 工作区或平台范围；
2. 主要来源或观测对象；
3. 最近更新时间与过期状态；
4. 可信度或核验结论；
5. 有异常时给出唯一下一步。

这条证据轨只重排已有真实信息，不新增字段，也不把缺失数据伪装成可信度。

## 3. 壳层与导航

- 顶栏只保留品牌、当前范围、搜索、当前角色主操作、通知与个人菜单；按钮顺序保持跨角色稳定。
- 成员、组织、平台三套侧栏继续独立。组织/平台菜单按任务组折叠，每次只展开当前组，避免 10 个以上入口同时争夺注意力。
- 当前页面同时通过侧栏高亮、面包屑和标题表达；深层路由的上级面包屑必须可点击。
- 平台后台首页先展示业务影响和待处理，不先展示主机参数；技术标识、请求编号、内部版本统一进入“技术详情”。
- 移动端保留五入口底栏；当前深层页面高亮“更多”，当前角色主操作在标题区进入拇指可达范围。

## 4. 页面布局

### 4.1 仪表盘

- 用一条“今天首先处理什么”行动带代替等权指标卡墙。
- 四个以内的核心指标放在行动带前后，数字使用等宽数字，变化值紧邻主值。
- 图表无数据时不展示空坐标系，改为解释缺失原因和可执行动作。
- 首页、治理概览、平台概览、采集总览和运行页面复用同一骨架，但成员端突出决策，后台突出异常与影响。

### 4.2 列表、表格与筛选

- 固定“搜索 → 关键筛选 → 更多筛选 → 批量操作 → 结果”顺序。
- 常用筛选最多直接展示 3 个，其余进入抽屉；已生效条件用可移除标签并提供“一键清空”。
- 表格首列承担对象识别，末列只保留一个直接动作，其他动作进入菜单。
- 长标题、ID、来源地址和错误信息不得无出口截断；提供展开、复制或详情。
- 390px 下表格转卡片，只显示对象、状态、主值和一个主动作，详情由抽屉承载。

### 4.3 详情与决策页

- 首屏按“结论 → 证据充分度 → 缺口 → 主行动”排列。
- 市场、竞争、成本、风险、AI 辅助和血缘信息改为页签或分区，不在首屏同时展开。
- 决策按钮固定为一个主操作；“驳回/暂停/删除”保持危险色并进入影响确认。
- 任务、机会和组织详情保留上一页筛选上下文，返回时不丢失位置。

### 4.4 表单、规则与向导

- 字段按用户做决定的顺序分组，不按后端字段顺序罗列。
- 必填、格式、影响范围和权限在输入前说明；错误就近展示并保留已填内容。
- 规则、来源配置、费用规则和配额调整保存前展示当前版本与新版本差异。
- 多步骤向导显示“当前步骤 / 总步骤”，允许返回前一步；最终一步才展示高影响确认。

## 5. 每一个按钮

源码逐项位置见 `button-inventory.md`，共 634 个实例。统一规则：

- 主按钮：每页最多一个，使用行动蓝；文字用“动词 + 对象”，例如“创建选品”“记录决策”。
- 次按钮：描边样式，用于查看、导出、预览和保存筛选。
- 文字按钮：只用于低权重跳转，不承担提交或危险操作。
- 危险按钮：珊瑚描边或实色，只用于删除、停用、暂停、回滚和撤销高影响动作。
- 图标按钮：必须有可读名称；通知、个人菜单、关闭和更多操作的热区统一 44px。
- 批量按钮：未选择对象时禁用，并在按钮旁显示已选数量和影响范围。
- 所有按钮必须覆盖默认、悬停、聚焦、按下、禁用、处理中六态；处理中保持原宽度，避免布局跳动。

按钮六态的统一图见 `boards/buttons-system.png`。

## 6. 每一个弹窗

源码逐项位置见 `dialog-inventory.md`，共 56 个实例，归并为 10 个可复用类型：高影响确认、审计理由、创建向导、移动筛选抽屉、记录详情、规则预览、任务创建、来源配置、敏感输入、消息编辑。

统一规则：

- 标题直接说明动作，不使用“提示”“操作”等空泛词。
- 标题下先写不可逆影响和作用范围，再展示输入字段。
- 取消始终在主按钮左侧；关闭按钮和 Esc 行为一致；高影响弹窗默认失败关闭。
- 提交失败停留在当前弹窗，保留输入并在字段或顶部给出恢复动作。
- 请求 ID、内部 ID、版本哈希和追踪信息折叠到“技术详情”。
- 移动端弹窗改为底部抽屉，主按钮贴近底部安全区，内容区可滚动但标题和操作区固定。

对应设计图为 `boards/dialog-*.png`。

## 7. 页面状态

- 加载：显示结构骨架和正在读取的对象，不用全屏旋转图标。
- 空状态：区分“从未创建”“筛选无结果”“没有权限”“来源暂不可用”。
- 错误：用业务语言说明影响、恢复动作和关联编号，不只显示错误码。
- 过期：明确已显示数据的观测时间，不把旧数据显示为实时。
- 断网与恢复：断网时保留已显示事实；恢复后自动校对并显示新的更新时间。
- 无权限：保留当前位置和对象名称，提供返回安全页面的入口。
- 404：优先返回最近有效页，其次回到当前角色首页。

完整状态图见 `boards/states-system.png`。

## 8. 动效与反馈

- 按钮按下 120–160ms，弹窗/抽屉 200–240ms，提示与菜单 150–180ms。
- 只动画 transform 与 opacity；不使用 `transition: all`，不动画宽高。
- 高频表格、搜索和快捷操作不加进入动画；首次加载的行动卡可使用 30ms 级联。
- 实时更新不重排整页，只高亮变化行 1.5 秒并保留文字/图标状态。
- 遵循 `prefers-reduced-motion`，关闭位移动效后仍保留颜色、文字和图标反馈。

## 9. 分角色重点

- 普通成员：减少技术语言，首屏优先“今天做什么”和“为什么可信”。
- 选品负责人：强化批量分配、保存筛选、键盘导航和返回上下文。
- 组织管理员：所有变更都显示当前组织、影响成员、能力名称和审计理由。
- 平台运维：先看业务影响、异常、负责人和恢复动作；主机与请求细节按需展开。
- 移动用户：一手操作、固定底栏、卡片化表格、可中断向导、恢复后保留进度。

## 10. 实施顺序与验收

### P0：全站骨架

统一壳层、标题区、证据轨、按钮层级、间距与圆角。验收 73 个路由在 1440/1024/768/390px 无横向溢出，主操作可见，角色与范围不混淆。

### P1：核心业务流

优先改首页、趋势、机会列表/详情、供应链、任务与审批。验收从输入信号到查看证据再到记录决策不需要跨页记忆。

### P2：组织与平台后台

统一紧凑表格、异常优先驾驶舱、技术详情折叠和高影响确认。验收所有后台动作明确作用范围、负责人和审计原因。

### P3：状态与细节

完成 8 类状态、10 类弹窗、按钮六态、移动抽屉和 reduced motion。验收键盘、触控、200% 缩放和慢网络下仍能完成主流程。

## 11. 本次未改变的内容

- 不改变路由、权限、API、字段、数据库、业务规则和真实数据判断。
- 不新增依赖，不替换 Vue 技术栈，不引入外部生产服务。
- 不把旧概念图中的演示数据、付费套餐或未启用能力重新带入产品。
- 本包是审核稿；只有你确认方向和页面后，才应进入生产 UI 实施。
