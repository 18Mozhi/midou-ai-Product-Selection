# ScoutOps UI 全套优化审核包

本包是设计提案，不改生产页面、接口、权限、字段、路由或数据合同。它以当前 `docs/feature-map.json`、`apps/web/src/route-catalog.generated.json`、真实 Vue 组件、现有 E2E 截图和 `images-html` 参考包为依据。

## 实施状态

- P0 共享壳层已开始落地：受保护路由统一使用真实路由一级标题、页面说明和范围/任务域/角色上下文轨；桌面角色切换移至侧栏工具区，内容宽度、标题尺度、顶栏密度与按钮按下反馈按本稿收敛。
- 页面级来源、新鲜度和可信度仍必须由各业务模块提供真实事实，P0 不生成占位数据。
- P1 核心业务流、P2 组织与平台后台、P3 弹窗与页面状态仍按本文顺序继续实施，不能把本次共享层描述为 73 页全部完成。

## 审核入口

1. 打开 `index.html` 查看 73 个页面的桌面/移动优化稿与逐页建议。
2. 查看 `page-matrix.md` 核对真实路由是否完整。
3. 查看 `button-inventory.md` 核对每个源码按钮及建议层级。
4. 查看 `dialog-inventory.md` 核对每个弹窗实例与归一类型。
5. 在 `boards/` 审核设计系统、按钮六态、页面状态和 10 类弹窗。

建议用本地静态服务器打开，避免浏览器限制 ES Modules：

```powershell
cd design-plans/ui-optimization-2026-09-04
python -m http.server 4188
```

然后访问 `http://127.0.0.1:4188/`。审核完成后关闭该命令窗口即可。

## 设计决策

- 主方向：**证据罗盘**。页面始终回答“当前范围、主要来源、新鲜度、可信度、下一步”。
- 视觉：深海墨蓝画布、单一钴蓝行动色、青色实时信号、绿/琥珀/珊瑚状态色。
- 密度：成员端标准密度；组织/平台后台紧凑密度；正文与表单保持 16px，元数据不低于 13px。
- 层级：每页一个主按钮；技术标识默认折叠；异常与业务影响先于纯指标。
- 组件：按钮热区至少 44px；卡片 12px 圆角；弹窗 18px；间距使用 4px 基线。
- 动效：按钮 120–160ms、弹窗 220ms；只动 transform/opacity；遵循 reduced motion。

## 全站优先级

1. 先统一壳层、页面标题区、证据轨和按钮层级，覆盖面最大。
2. 再统一表格/卡片响应式、筛选抽屉、详情页主从结构。
3. 再归一 10 类弹窗和 8 类页面状态，减少同义不同形。
4. 最后逐页做业务密度与空/错/加载状态微调。

## 生成与复核

运行 `node build.mjs` 会从真实路由表重新生成页面矩阵、控件清单和全部 PNG。生成脚本只写当前设计包目录。
